# 系统概览

> 高并发直播电商秒杀系统。基于 **JDK 25 (ZGC) + Spring Boot 4.1 + 虚拟线程** 构建，
> 覆盖秒杀抢购、弹幕互动、实时排行榜三大核心场景。

**说明**：
- **Gateway** 是唯一响应式服务（WebFlux），不做业务逻辑
- 其他业务服务均使用 **Spring MVC + 虚拟线程**（`spring.threads.virtual.enabled=true`）
- WebSocket 使用 `@ServerEndpoint` + 注入 VT Executor
- 秒杀服务有 **两个部署变体**：`livemall-seckill`（集群，端口 8090）和 `livemall-seckill-single`（单实例，端口 8082）
- 模块间通过 **Dubbo**（同步 RPC）或 **Kafka**（异步消息）通信

## 四、Gateway 路由

所有外部请求统一经 Gateway 转发：

```yaml
spring:
  cloud:
    gateway:
      server:
        webflux:
          routes:
            - id: user-service
              uri: lb://livemall-user
              predicates: [Path=/auth/**,/user/**]

            - id: seckill-service
              uri: lb://livemall-seckill
              predicates: [Path=/seckill/**]

            - id: leaderboard-service
              uri: lb://livemall-leaderboard
              predicates: [Path=/leaderboard/**]

            - id: live-service
              uri: lb://livemall-websocket
              predicates: [Path=/live/**]

            - id: websocket-service
              uri: lb:ws://livemall-websocket
              predicates: [Path=/ws/**]
```

**白名单**（免 JWT）：
- 完全公开：`/auth/login`, `/auth/register`, `/auth/refresh`, `/ws/**`, `/actuator/health`
- GET 公开：`/live/rooms`, `/live/room/**`, `/leaderboard/**`

## 五、数据流：核心链路

### 5.1 秒杀抢购

```
用户 → Gateway(JWT验签) → SeckillController.placeOrder()
  ├─ ① Caffeine 查活动缓存
  ├─ ② Redis Lua 原子扣减库存（Hash Tag = {activityId}，强制走 MASTER）
  │    ├─ 成功 → Kafka 发送 seckill-order 消息
  │    └─ 失败 → 返回"库存不足"/"重复抢购"
  └─ (异步) SeckillOrderConsumer ↓
       ├─ Semaphore 背压（上限 30 = HikariCP 池大小）
       ├─ Thread.startVirtualThread()
       ├─ @Transactional INSERT order（VERSION 乐观锁防并发）
       ├─ DuplicateKeyException 幂等兜底（uk_activity_user 唯一索引）
       ├─ Redis Pub/Sub 或 gRPC 推送秒杀结果到 WebSocket
       └─ 手动 ACK
```

### 5.2 弹幕发送

```
用户(WS) → LiveWebSocket.onMessage("BARRAGE")
  └─ broadcastToRoom() → 广播给同房间所有 WS 连接
```

### 5.3 送礼 + 排行榜

```
用户(WS) → LiveWebSocket.onMessage("GIFT")
  ├─ broadcastToRoom() → 广播送礼特效
  └─ Thread.startVirtualThread() → Dubbo LeaderboardService.addScore()
       └─ Redis ZINCRBY leaderboard:{roomId}
```

### 5.4 超时取消订单

```
TimeoutCancelScheduler（@Scheduled 15s）
  └─ 分页查询超时订单（timeout-scan-batch: 500）
       └─ cancelOrder()
            ├─ DB UPDATE（@Version CAS）
            └─ Redis Lua 回补库存（EXISTS 幂等校验）
```

## 六、数据一致性防线

| # | 防线 | 技术 | 说明 |
|---|------|------|------|
| 1 | 扣减原子性 | Redis Lua | 查重-扣减-标记，Hash Tag `{activityId}` 同槽 |
| 2 | 超时回补 | Kafka 延迟 + @Scheduled | 前端假过期防末秒竞态；定时扫描仅兜底 |
| 3 | DB 最终兜底 | `uk_activity_user` 唯一索引 | `DuplicateKeyException` → 幂等 ACK |
| 4 | Redis 容灾 | `read-from: MASTER` | 强制走主，禁读写分离，杜绝异步复制超卖 |
| 5 | 退款幂等 | Lua EXISTS + 原子回补 | 前置校验防重复回补 |

## 七、关键技术决策

| 决策 | 选型 | 理由 |
|------|------|------|
| GC | 分代 ZGC | 秒杀对 P99 敏感，G1 Mixed GC STW 可达 856ms（同压测验证）；ZGC 并发转移 STW < 3ms |
| 线程模型 | 虚拟线程 | Spring Boot 4.1 原生支持 VT，降低同步编程心智负担 |
| 响应式 | 仅 Gateway | Gateway 是唯一高吞吐转发节点，WebFlux EventLoop 优于 VT |
| 锁 | ReentrantLock | JDK 25 JEP 491 修复了 synchronized VT pinning，RL 保留为最佳实践 |
| 用户上下文 | ScopedValue | 替代 ThreadLocal，零拷贝 + 不可变，JDK 25 正式 API |
| RPC | Dubbo | 面向接口 + 负载均衡 + 面试高频 |
| 消息 | Kafka | 高吞吐（顺序写 + 零拷贝），KRaft 免 ZK |
| 幂等 | DB 唯一索引 | `DuplicateKeyException` 轻量可靠 |
| 背压 | Semaphore | 上限对齐 HikariCP 池，阻塞 poll 迫使 Broker 降速 |
