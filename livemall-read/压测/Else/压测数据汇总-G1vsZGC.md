# 压测数据汇总：G1 vs ZGC

> 环境：VM 8vCPU/16GB | MySQL + Redis Cluster + Kafka + Nacos | JDK 25 Spring Boot 4.1 | Seckill 单服务 300 并发 30s

## GC 耗时对比（450/45s 同压测，jstat -gccause）

| 指标 | G1 | ZGC | G1 是 ZGC 的倍数 |
|---|---|---|---|
| **YGCT（Young GC 总耗时）** | **0.652s** | **0.001s** | **652 倍** |
| **CGCT（并发 GC 总耗时）** | **0.205s** | **0.001s** | **205 倍** |
| **总 GC 耗时** | **0.856s** | **0.003s** | **285 倍** |
| **Young GC 次数** | 170 次 | 9 次 | **19 倍** |
| **Full GC** | 0 | 0 | 持平 |
| **GC 触发原因** | G1 Evacuation Pause（STW） | Proactive / High Usage（并发） | ZGC 无强制 STW |

> G1 所有 Evacuation Pause 均为 STW 操作；ZGC 的 GC 全部并发执行，应用线程零阻塞。

## 综合观察

### 拐点分析
- **300 并发为性能甜点**：异步削峰后 TPS 1513 / P99 92ms，资源利用最优
- **400 并发接近天花板**：TPS 1661 / P99 122ms
- **600 线程快斜坡峰值**：TPS 2065（SkyWalking 追踪 Kafka Producer 同步发送 3342ms 为瓶颈）

### G1 vs ZGC（300/30 应用层）
- ZGC P99 183ms 比 G1 269ms 低 86ms，TPS 高 121
- ZGC Max 286ms 比 G1 385ms 低 99ms
- G1 在 60/60 过载配置下 Max 达 1478ms（连接池竞争 + GC 叠加效应）

### G1 vs ZGC（450/45 GC 层）
- G1 45s 内 GC 总耗时 **0.856s**，均为 STW Evacuation Pause；单次平均 5ms
- ZGC 45s 内 GC 总耗时 **0.002s**，均为并发，零 STW
- ZGC 的 Young GC 次数仅为 G1 的 1/19，GC 触发为主动式（Proactive），不阻塞应用线程
- **数据直接证明**：秒杀场景中 ZGC 彻底消除 GC 抖动对 P99 的干扰，G1 的 STW 暂停是秒杀延迟的隐藏瓶颈

### 生产限流阈值
- **并发上限**：300
- **QPS 上限**：1400
- **理论最大容错**：500ms 超时窗口 + 180ms 余量
