### P0-1：SignVerifyGlobalFilter 阻塞 Redis 调用在 WebFlux 中

**位置**：`docs/2-模块详细设计/2.6-网关与可观测性.md` line 158-162
`docs/3-功能实现细节/3.6-网关与公共/3.6.3-接口签名验签.md` line 46-48

**代码**：
```java
redisTemplate.opsForValue().setIfAbsent("nonce:" + nonce, "1", 60, TimeUnit.SECONDS)
```

**问题**：
- Gateway 是 WebFlux（Reactor EventLoop），`redisTemplate` 是阻塞式 Redis 客户端
- Nonce 的 `SETNX` 操作阻塞 EventLoop 线程，将响应式网关退化为同步模型
- 10w QPS 下 EventLoop 线程被阻塞 → 请求排队 → 网关吞掉降级

**修复方案**（二选一）：

| 方案 | 做法 | 代价 |
|------|------|------|
| A | 用 `spring-boot-starter-data-redis-reactive` + `ReactiveRedisTemplate` 做非阻塞 Nonce | 多一个依赖，Nonce 逻辑改为响应式 |
| B | Nonce 检查移到下游业务服务的 `HandlerInterceptor` 中做（MVC + VT 允许阻塞 Redis） | Nonce 检查穿透到各服务，非 Gateway 统一拦截 |

**推荐方案 A**——Gateway 已依赖 Redis，加 reactive 适配器即可，改动最小。

**位置**：`docs/2-模块详细设计/2.7-数据库设计.md` §1.2

表 DDL 建了 7 个字段、2 个索引，但整个项目没有任何代码路径读/写它。无效设计。

**修复方案**（二选一）：

**推荐方案 A**——设备会话用 Redis TTL 7 天自动过期 + SCAN 清理足矣。Redis 挂了用户重新登录即可，不需要 MySQL 做持久化。

### P1-3：WebSocket 模块无优雅关闭

**问题**：关播（3.2.2）启动的异步 VT（`Thread.startVirtualThread(() -> sleep 5s → close)`）在容器 shutdown 时会被 kill，10w 个 session 残留泄漏。

**位置**：`docs/3-功能实现细节/3.2-直播与WebSocket/3.2.2-关播.md`
`docs/3-功能实现细节/3.2-直播与WebSocket/3.2.4-离开直播间.md`

**修复方案**：
```yaml
# application.yml
spring:
  lifecycle:
    timeout-per-shutdown-phase: 30s
```

```java
@PreDestroy
public void gracefulShutdown() {
    // 广播 KICK → 等待 5s → closeAll
    WsSessionManager.closeAll();
}
```
