# 10 — 故障场景与降级

> **目标：** 面试官最爱问"XXX 挂了怎么办"。要展示的不是"挂了就挂了"，而是**降级链路**。

---

## 1. 场景：Redis 挂了

### 问题
秒杀进行到一半，Redis 节点宕机。用户还能抢购吗？

### 降级链路

```
第一层 — Sentinel 降级：
  限流阈值从 100 QPS 降到 10 QPS
  → 大幅减少打到下游的请求量

第二层 — Caffeine 本地缓存：
  活动状态 + 库存标记还在本地缓存里
  → 还能挡大部分请求（有库存 → 放行，无库存 → 售罄）

第三层 — 库存降级到 MySQL：
  Redis Lua 不可用 → 绕过 Redis，直接查 MySQL 库存
  SELECT stock FROM t_seckill_activity WHERE id = ? FOR UPDATE
  → 数据库行锁扣减库存
  → 能力降级到 ~1000 QPS（MySQL 单行锁竞争）

第四层 — 熔断：
  如果 DB 也扛不住 → 直接返回 "活动太火爆，请稍后再试"
  → 保护 DB 不被冲垮
```

### 面试话术

> "Redis 挂了有分层降级：Sentinel 收紧限流 → Caffeine 本地缓存顶一阵 → 降级到 MySQL 行锁扣库存 → 如果 DB 也撑不住就熔断。目标是保护核心链路不崩溃，宁可不卖也不能把数据库打挂。"

## 2. 场景：Kafka 挂了

### 问题
Kafka Broker 宕机，消息发不出去。秒杀还能用吗？

### 降级方案

```
方案 A（默认）— 同步下单降级：
  Kafka 不可用 → 跳过 Kafka
  Redis Lua 扣减后 → 直接同步 INSERT DB 订单
  → 下单延迟增加 10-50ms，但功能可用

方案 B（保护）— 暂存 Redis：
  消息先存到 Redis List（临时队列）
  Kafka 恢复后，定时任务批量重发
  → 用户无感知，但消息可能积压

本项目选择方案 A：
  因为秒杀链路本就要求快速返回结果，
  同步 INSERT 比 Kafka 异步慢 10-50ms，可控。
```

## 3. 场景：MySQL 挂了

### 问题
数据库宕机，数据写不进去。

### 降级方案

```
读操作不受影响：
  - 活动信息走 Redis 缓存（缓存预热时已加载）
  - 排行榜走 Redis ZSet
  - 用户信息有 Redis 缓存

写操作降级：
  - 订单暂存 Redis 草稿（TTL 1h）
  - Redis 恢复后批量写入 MySQL
  - 用户看到"订单处理中"，稍后刷新确认
  - 如果 Redis 也超时 → 写入失败，返回"系统繁忙"

主从切换：
  如果只是主库挂，切换到从库读
  (本项目单机 MySQL，面试时提一下主从方案即可)
```

## 4. 场景：Sentinel 挂了（限流失效）

### 问题
Sentinel 进程崩溃，限流规则不生效。瞬间流量全打到下游。

### 降级方案

```
最差情况 — 不限流：
  - Sentinel 挂了 → 不再限流
  - Caffeine 本地缓存还能过滤无库存请求
  - Redis Lua 原子扣库存 → 确保不超卖
  - 只是流量全打进来，下游压力增大，但正确性不受影响

更好的方案 — 兜底限流：
  - Nginx 层限流（limit_req_zone）
  - 或 Guava RateLimiter 兜底（应用内限流）
  - Sentinel 恢复后自动切回
```

## 5. 场景：秒杀开始时流量打崩

### 问题
10w 人同时点秒杀按钮，系统瞬间卡死。

### 防护

```
① 网关层 — Sentinel 热点限流
  每用户每活动 100 QPS，恶意/异常高频请求直接 429

② 本地缓存 — Caffeine 1s 刷新
  "无库存"标记存在时 → 直接返回售罄，不查 Redis
  过滤 90% 请求

③ Redis Lua — 分片 + 原子扣减
  4 分片 × 8w QPS = 32w 上限
  单次操作 O(1)，<1ms

④ Kafka — 异步削峰
  扣库存成功即返回，订单创建异步
  前端显示"抢购成功，订单处理中"

⑤ DB 唯一索引 — 兜底
  uk_activity_user 确保一人一单
```

## 6. 场景：Snowflake 时钟回拨

### 问题
服务器 NTP 时间同步导致时钟回拨了 5 秒。

### 处理

```java
public long nextId() {
    lock.lock();
    try {
        long timestamp = System.currentTimeMillis();
        if (timestamp < lastTimestamp) {
            long diff = lastTimestamp - timestamp;
            if (diff <= 100) {  // ≤100ms
                // 先释放锁，避免 VT pinning + 持锁阻塞
                lock.unlock();
                try { Thread.sleep(diff); } finally { lock.lock(); }
                timestamp = Math.max(lastTimestamp + 1, System.currentTimeMillis());
            } else {  // >100ms
                throw new RuntimeException("时钟回拨超过 100ms，拒绝生成 ID");
            }
        }
        // 正常生成...
    } finally {
        lock.unlock();
    }
}
```

**关键设计：**
- 等待时不持锁（先 unlock → sleep → 重新 lock）→ 其他线程可以正常生成
- ≤100ms 自旋等待 → 100ms 是经验值，足够覆盖 NTP 微小调整
- >100ms 抛异常 → 防止长时间回拨导致 ID 冲突

## 7. 场景：Kafka 消息堆积

### 问题
秒杀期间大量下单消息发到 Kafka，Consumer 消费不过来。

### 应对

```
① 扩容消费者
  Kafka 支持增加消费者组中的消费者数量
  前提：分区数 ≥ 消费者数

② VT 消费
  每个消息委托给一个 VT 处理
  虚拟线程数不受平台线程池限制
  内存够就能同时消费更多

③ 监控告警
  Consumer Lag 超过阈值 → 告警 → 扩容

④ 用户体验
  用户看到"订单处理中"，刷新后从 DB 查到结果
  异步处理的延迟用户能接受
```

## 8. 场景：WebSocket 连接断了不重连

### 排查

```
① 心跳日志 → 有没有 PING/PONG
② 服务端是否 60s 超时断开了连接
③ 客户端指数退避是否限制了重试次数（10 次）
④ Redis ws:route:{userId} 的 TTL 是否被心跳续期
⑤ 是否是跨节点路由失败（查 ws:route:{userId}）
```

## 9. 场景：秒杀成功但没看到订单

### 排查链路

```
用户请求 → Gateway 日志（有没有到达）
  → SeckillController 日志（入参 activityId + userId）
    → Redis Lua 返回值（200/-1/-2）
      → Kafka Producer（消息发出没有？看 ack）
        → Kafka Consumer（消费日志有没有异常）
          → MySQL INSERT（唯一索引冲突？数据落库没有？）
            → WebSocket 推送（ws:route 路由对了吗？）
```

**常见原因：**
- Kafka 消费侧异常（消息被消费但 DB 写入失败）
- DB 唯一索引冲突（一人一单 → 重复下单静默失败）
- WebSocket 推送时用户已断开（离线消息 5min 后过期）

## 10. 面试 "挂了怎么办" 回答公式

面试官问"XXX 挂了怎么办"，按这个公式回答：

```
第一步：判断影响范围
  → "读不受影响，写暂时降级" 还是 "全挂"

第二步：分层降级
  → 限流收紧 → 缓存顶住 → 降级 DB → 熔断兜底

第三步：用户体验
  → 用户看到什么？"处理中"还是"系统繁忙"？

第四步：恢复策略
  → 自动恢复（检测到可用后切回）还是手动（运维介入）？

第五步：预防措施（加分项）
  → 监控告警 / 主从切换 / 多活部署
```

## 速查表：所有降级场景

| 故障 | 读影响 | 写影响 | 降级方案 | 用户感知 |
|------|--------|--------|---------|---------|
| Redis 挂 | 缓存 miss → 查 DB | 库存走 DB 行锁 | 限流+缓存+DB+熔断 | 变慢，可能售罄 |
| Kafka 挂 | 无影响 | 同步下单 | Redis Lua → 直接 INSERT | 下单变慢 10-50ms |
| MySQL 挂 | Redis 缓存可读 | 写暂存 Redis | 读缓存 + 写草稿 | 查数据正常，下单稍后 |
| Sentinel 挂 | 无影响 | 不限流 | Nginx/Caffeine 兜底 | 无感知 |
| Nacos 挂 | 无影响（本地缓存） | 新服务无法注册 | 已有链路不断 | 无感知 |
| Snowflake 回拨 | 异常 | 异常 | ≤100ms 等待，>100ms 抛异常 | 短暂不可用 |
