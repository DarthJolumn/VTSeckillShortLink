## 30 秒电梯演讲

> 我做了一个**高并发直播电商秒杀系统 LiveMall**。5 个微服务 + Gateway，Java 21 虚拟线程 + Dubbo RPC + Kafka + Redis + MySQL。核心链路是秒杀抢购：Gateway 限流验签 → Redis Lua 原子扣库存（4 分片）→ Kafka 异步下单 → WebSocket 推送结果。目标是 10w QPS，难点在库存热点分片、弹幕实时推送、秒杀与直播的联动。

## 7 个必问技术点 + 一句话回答

| # | 问题 | 一句话回答 |
|---|------|-----------|
| 1 | 为什么 Dubbo 不选 Feign | 面试纵深——Dubbo 有 SPI、5 种负载均衡、多种容错策略能连问 5 轮，Feign 只是 HTTP 客户端问两句就没了 |
| 2 | 为什么双 Token | Session 每次查 Redis（10w IO/s），双 Token 99% 请求仅 JWT 验签（0 IO），差 900 倍 |
| 3 | 为什么虚拟线程 | 创建成本低 2 个数量级，M:N 调度，对现有代码零侵入；ScopedValue 替代 ThreadLocal 避免内存泄漏 |
| 4 | Lua 为什么原子 | Redis 单线程执行 Lua，整个脚本执行期间不会被其他命令插入，不需要事务 |
| 5 | 库存分片为什么 4 片 | 单 key DECR 上限 8w QPS，4 片 = 32w QPS 余量；过度分片导致库存碎片化 |
| 6 | Kafka 零拷贝是什么 | 数据从磁盘到网卡不经过用户态：传统 4 次拷贝，sendfile 只 2 次（磁盘→内核→网卡） |
| 7 | ZSet 底层是什么 | 跳表（skiplist）+ 哈希表，增删改查 O(log N)；跳表通过概率升级（P=0.25）维持平衡 |

## 秒杀全链路（面试必画）

```
1. Gateway: Sentinel 限流 + JWT 鉴权 + 签名验签
2. SeckillController: 校验活动状态（Caffeine 1s 缓存）
3. Redis Lua: userId % 4 → DECR stock:shard:N → ≥0 成功
4. Kafka: 发下单消息（异步削峰）
5. Consumer: VT 消费 → INSERT DB → 状态机 PENDING
6. WebSocket: Dubbo WsPushService.push → 推结果给用户
7. 超时取消: @Scheduled 15s 扫描 + 乐观锁 CAS + 回补库存
```

## 错误码速查

| Code | 含义 |
|------|------|
| 200 | 成功 |
| 1001 | 库存不足 |
| 1002 | 重复下单 |
| 1003 | 活动未开始 |
| 1004 | 活动已结束 |
| 1005 | Token 过期 |
| 1006 | 用户已封禁 |
| 1007 | 签名无效 |
| 1008 | 次数超限（限流） |

| 1013 | 登录已过期 |

## 降级链路（面试官最爱问）

```
Redis 挂了: Sentinel 降级限流 100→10 QPS → Caffeine 挡一波 → 直接查 MySQL
Kafka 挂了: 切同步下单（Lua 扣减后直接 INSERT DB）
MySQL 挂了: 读走 Redis 缓存，写暂存 Redis 草稿
Sentinel 挂了: 降级为不做限流，Nginx 层兜底
```
