# 01 — 业务全景

> **目标：** 能清晰介绍这个项目做什么、谁用、有什么功能。面试官的第一个问题一定是"你做了什么项目？"

---

## 1. 一句话定位

**高并发直播电商秒杀系统**——模拟抖音/淘宝直播间的秒杀抢购场景。

不是做一个"商城"，是做一个"直播间里的秒杀"。

## 2. 核心业务流程

```
主播开播 → 观众进入直播间 → 发弹幕互动 / 送礼
                              ↓
                    主播上架秒杀商品
                              ↓
              观众疯狂点击抢购（10w QPS）
                              ↓
              库存扣减 → 订单创建 → 结果推送
                              ↓
              排行榜实时更新（送礼越多排名越高）
```

## 3. 三种角色

| 角色 | 能做什么 | 入口 |
|------|---------|------|
| **观众 (audience)** | 看直播、发弹幕、送礼、抢秒杀、看排行 | `/` |
| **主播 (anchor)** | 观众全部权限 + 开播/关播、上架秒杀、看数据 | `/anchor` |
| **管理员 (admin)** | 主播全部权限 + 管理活动、封禁用户 | `/admin` |

## 4. 五大业务模块

### 4.1 用户与认证

```
注册（用户名+密码 BCrypt 加密）→ 登录（双 Token）
  → Access Token（JWT，15min）→ 每次请求验签（无 IO）
  → Refresh Token（Redis，7 天）→ 过期后换新 Access
  → 登出 → 删 Redis Refresh Token
  → 设备管理 → 看在线设备 + 踢人
```

### 4.2 直播与 WebSocket

```
主播开播 → 创建直播间 → WS 端点 /ws/live/{roomId}
观众进入 → WS 连接 → 加入房间 → 在线人数 +1
观众发弹幕 → DFA 敏感词过滤 → 广播全房间
观众送礼物 → 广播特效 → 排行榜加分
心跳检测 → 30s PING/PONG → 60s 无响应断开
断线重连 → 指数退避 1s→2s→4s...→30s
```

### 4.3 秒杀（核心）

```
管理员创建活动（商品/价格/库存/时间）
活动上架 → 预热 Caffeine 缓存
到点开抢 → 10w 人同时点按钮
  → Gateway Sentinel 每用户限流 100 QPS
  → Caffeine 本地缓存 1s 判断有无库存（无库存直接拒绝）
  → Redis Lua userId%4 分片 DECR 扣库存
  → 扣成功 → Kafka 异步下单
  → Consumer VT 消费 → INSERT DB 订单
  → WebSocket 推送给用户"抢到了！"
15 分钟未支付 → 定时任务取消 → 回补库存
```

### 4.4 排行榜

```
送礼/点赞/评论/分享 → ZIncrBy 加分
实时 Top 100 → ZRevRange 取前 100
个人排名 → ZRevRank
每 5 分钟 → 快照存 MySQL（历史可查）
```

### 4.5 网关与公共

```
所有请求 → Gateway(:8080)
  → CorsConfig 跨域处理
  → SignVerifyGlobalFilter 签名验签（防篡改+防重放）
  → JwtAuthGlobalFilter JWT 鉴权（提取 userId → 下游 Header）
  → Sentinel 限流（热点参数限流）
  → 路由转发到对应服务
```

## 5. 面试时要讲的故事线

不要平铺功能清单，要讲故事：

> "我做这个项目是因为想展示高并发场景下的技术深度。选直播电商是因为它天然具备多种技术挑战：**秒杀的瞬时高并发**（库存扣减）、**WebSocket 的长连接管理**（弹幕推送）、**实时排行榜**（ZSet）、**认证的安全与性能平衡**（双 Token）。每个模块都有独立的技术纵深，面试官无论往哪个方向追问都能接住。"

## 6. 与真实项目的差异（面试时诚实回答）

| 方面 | 本项目 | 生产环境 |
|------|--------|---------|
| 视频流 | ❌ 没有（只做了弹幕/送礼等互动） | 需要 OBS 推流 + CDN 分发 |
| 支付 | ❌ mock 支付按钮 | 对接支付宝/微信支付 |
| 部署 | Docker Compose 单机 | K8s 多节点 |
| 监控 | Zipkin 链路追踪 | Prometheus + Grafana 面板 |
| CI/CD | ❌ 没有 | Jenkins/GitHub Actions |

> "项目重点不是业务广度是技术深度，视频流和支付不是我要展示的。"

## 7. 关键数字（面试要脱口而出）

- 目标 QPS：**10w**
- 服务数：**5 个微服务 + 1 个网关**
- Java 版本：**21（Virtual Threads）**
- Access Token TTL：**15 分钟**
- Refresh Token TTL：**7 天**
- 库存分片：**4 片**
- 心跳间隔：**30s PING，60s 超时**
- 超时取消：**15 分钟**
