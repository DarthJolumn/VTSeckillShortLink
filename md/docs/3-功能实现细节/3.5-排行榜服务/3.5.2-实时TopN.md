> 运行在 VT 上。HTTP GET 请求走 VT。Caffeine 本地缓存读（无 IO）+ 未命中时 Redis ZREVRANGE（IO，VT park）。不加 `@Transactional`。

## 输入输出

**请求** `GET /leaderboard/top?activityId=1&top=100`（需 JWT）

**响应**

```json
{"code": 200, "data": [{"rank": 1, "userId": 1001, "score": 999.5}, ...]}
```

## 核心流程

```
GET /leaderboard/top?activityId=1&top=100
  → 查 Caffeine 本地缓存（TTL 1s）
     ├── 命中 → 直接返回
  → ZREVRANGE "leaderboard:{activityId}" 0 top-1 WITHSCORES
  → 构造 RankEntry 列表，rank 从 1 开始
  → 写入本地缓存
  → 返回
```

```java
public List<RankEntry> getTopN(Long activityId, int n) {
    String key = "leaderboard:" + activityId;
    Set<ZSetOperations.TypedTuple<String>> set = redisTemplate
            .opsForZSet().reverseRangeWithScores(key, 0, n - 1);
    if (set == null) return List.of();

    List<RankEntry> result = new ArrayList<>(n);
    int rank = 1;
    for (ZSetOperations.TypedTuple<String> tuple : set) {
        result.add(new RankEntry(rank++, Long.valueOf(tuple.getValue()), tuple.getScore()));
    }
    return result;
}
```

## 边界处理

| 场景 | 行为 |
|------|------|
| 活动不存在 | 空列表 |
| top < 1 | 空列表 |
| top > ZSet 大小 | 返回全部 |
| 缓存过期 | 下次请求从 Redis 重新加载 |

🤔 **面试扩展**：ZREVRANGE 时间复杂度 O(log N + N)，N 为 ZSet 大小，百万用户约 O(log 100w) ≈ 20 步 + 取 top100 约 120 次操作，< 1ms。Caffeine 1s 缓存防打爆 Redis。
