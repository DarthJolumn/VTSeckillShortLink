## 输入输出

**请求** `GET /leaderboard/rank/{userId}?activityId=1`（需 JWT）

**响应**

```json
{"code": 200, "data": {"userId": 1001, "score": 999.5, "rank": 1}}
```

## 核心流程

```
GET /leaderboard/rank/{userId}?activityId=1
  → ZSCORE "leaderboard:{activityId}" userId → score
  → ZREVRANK "leaderboard:{activityId}" userId → rank (0-based)
  → score == null → 未上榜 (rank=-1, score=0)
  → rank + 1 → 转 1-based
  → 返回
```

```java
public RankEntry getRank(Long activityId, Long userId) {
    String key = "leaderboard:" + activityId;
    Double score = redisTemplate.opsForZSet().score(key, userId.toString());
    Long rank = redisTemplate.opsForZSet().reverseRank(key, userId.toString());
    if (score == null) return new RankEntry(userId, 0.0, -1);
    return new RankEntry(userId, score, rank.intValue() + 1);
}
```

## 边界处理

| 场景 | 行为 |
|------|------|
| 用户未上榜 | rank=-1, score=0 |
| 活动不存在 | rank=-1 |
| 用户 ID 为 0 | 无特殊处理，按正常查 |

🤔 **面试扩展**：ZREVRANK 底层通过跳表查找，O(log N)。ZSCORE 通过哈希表查找，O(1)。两个操作的性能差异——ZSET 是跳表 + 哈希表的组合数据结构。
