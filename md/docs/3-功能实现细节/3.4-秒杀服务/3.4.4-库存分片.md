## Redis Lua 脚本

```lua
-- KEYS[1] = orderedKey (ordered:{activityId}:{userId})
-- KEYS[2] = stockShardKey (stock:shard:{activityId}:{shard})
-- ARGV[1] = shardCount

local ordered = redis.call("GET", KEYS[1])
if ordered then
    return {code = -1, msg = "重复下单"}
end

local stock = redis.call("DECR", KEYS[2])
if stock >= 0 then
    redis.call("SETEX", KEYS[1], 86400, "1")
    return {code = 200, msg = "扣减成功"}
end
return {code = -2, msg = "库存不足"}
```

**分片路由**

```java
private String getShardKey(Long activityId, Long userId, int shardCount) {
    int shard = (int)(userId % shardCount);
    return "stock:shard:" + activityId + ":" + shard;
}
```

**分片数计算**

```
shardCount = 预计峰值 QPS / (10w × 0.7)
10w QPS → 10w / 7w ≈ 2 片
50w QPS → 50w / 7w ≈ 8 片
本项目基线 4 片
```

## 关键代码

```java
public StockResult deduct(Long activityId, Long userId) {
    int shardCount = getShardCount(activityId); // 从活动配置读取
    String orderedKey = "ordered:" + activityId + ":" + userId;
    String stockKey = "stock:shard:" + activityId + ":" + (int)(userId % shardCount);

    List<Long> result = redisTemplate.execute(seckillLuaScript,
            List.of(orderedKey, stockKey),
            String.valueOf(shardCount));
    // result -> [code, msg]
    return new StockResult(result.get(0).intValue(), "");
}
```

## 边界处理

| 场景 | 行为 |
|------|------|
| 单个分片库存耗尽 | 其他分片仍有库存，但该用户路由到已空分片 → 库存不足 |
| 库存碎片化 | 规模大时需碎片回收（高阶优化）|
| DECR 到负数 | Lua 中判断 stock < 0 返回库存不足，不超卖 |

🤔 **面试扩展**：为什么不用 MULTI/EXEC 而用 Lua？Lua 天然原子、支持条件分支（if-else），MULTI/EXEC 在 DECR 后无法根据结果决定是否回滚。分片代价：库存碎片化——一片卖完但总分片还有库存。4 片是 trade-off 结果。
