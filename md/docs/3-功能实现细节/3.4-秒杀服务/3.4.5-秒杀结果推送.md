| 属性 | 值 |

| 涉及类 | `SeckillOrderConsumer`、`WsPushService`（Dubbo）|

> 🔴 VT 警告：`@KafkaListener` 消费者默认跑在 Kafka 的 `ConcurrentMessageListenerContainer` 线程池（平台线程）上。如需将消费逻辑跑在 VT 上，需配置 Kafka 容器的 `Runtime.getRuntime().availableProcessors()` 个线程并行消费；或消费方法内部手动 `Thread.startVirtualThread(() -> process(record))`。本项目接受平台线程消费 Kafka（消费者数是分区数，可控），但消费内的 DB 写入和 Dubbo 调用是 IO 密集，平台线程会被阻塞。**优化方向**：消费器内部提交到 VT。

详见面试扩展。

## 核心流程

```
SeckillOrderConsumer 消费 Kafka 消息
  → INSERT t_seckill_order 成功
  → 构造 WsMessage type=SEC_KILL_RESULT
  → Dubbo 调用 WsPushService.push(userId, message)
  → WebSocket 服务查 ws:route:{userId} → 推送
```

## 消息格式

```json
{"type": "SEC_KILL_RESULT", "data": {"orderNo": "123456", "success": true, "msg": "抢购成功"}}
```

## 关键代码

```java
// SeckillOrderConsumer.java
@KafkaListener(topics = "seckill-order", concurrency = "4")
public void consume(ConsumerRecord<String, SeckillOrderMsg> record) {
    // P1-5 fixed: 委托给 VT 执行，避免阻塞 Kafka 容器平台线程
    Thread.startVirtualThread(() -> {
        SeckillOrderMsg msg = record.value();
        try {
            // INSERT 订单
            SeckillOrder order = new SeckillOrder();
            order.setOrderNo(msg.getOrderNo());
            order.setActivityId(msg.getActivityId());
            order.setUserId(msg.getUserId());
            order.setStatus(0); // PENDING
            seckillOrderRepository.save(order);

            // 推送结果
            WsMessage push = new WsMessage("SEC_KILL_RESULT",
                    Map.of("orderNo", msg.getOrderNo(), "success", true, "msg", "抢购成功"));
            wsPushService.push(msg.getUserId(), JsonUtil.toJson(push));
        } catch (Exception e) {
            // 数据库异常 → 发送失败推送
            WsMessage push = new WsMessage("SEC_KILL_RESULT",
                    Map.of("orderNo", msg.getOrderNo(), "success", false, "msg", "下单失败"));
            wsPushService.push(msg.getUserId(), JsonUtil.toJson(push));
        }
    });
}
```

## 边界处理

| 场景 | 行为 |
|------|------|
| Kafka 消费失败 | 重试 3 次后进死信队列，人工处理 |
| WebSocket 推送时用户断连 | 走离线消息机制（Redis offline list 5min TTL）|
| 用户未连接 WebSocket | 推送失败可接受，用户刷新页面查订单列表 |

🤔 **面试扩展**：为什么结果推送用 WS 而不是轮询？秒杀结果通常在几百 ms 内返回，WS 推送实时性远好于轮询。Kafka 消费 + Dubbo 推送路径约 100~500ms，用户几乎无感知等待。
