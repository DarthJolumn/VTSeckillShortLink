## 输入输出

**请求** `PUT /seckill/order/{orderNo}/refund`（需 JWT）

| 场景 | code | message |
|------|------|---------|
| 成功 | 200 | "退款成功" |
| 订单未支付 | 400 | "未支付的订单无法退款" |
| 已退款 | 200 | 幂等 |

## 核心流程

```
PUT /seckill/order/{orderNo}/refund
  → JWT → userId
  → SELECT * FROM t_seckill_order WHERE order_no = ? AND user_id = ?
     ├── status = 0 → 400 未支付不能退款
     ├── status = 3 → 幂等返回成功
  → 乐观锁 UPDATE t_seckill_order SET status=3, version=version+1
      WHERE order_no = ? AND status = 1 AND version = ?
  → Redis Lua 回补库存
  → 返回成功
```

## 边界处理

| 场景 | 行为 |
|------|------|
| 退款尚未支付的订单 | 400 拒绝 |
| 重复退款 | 幂等 |
| 回补库存失败 | 日志记录，人工对账 |

🤔 **面试扩展**：秒杀场景通常不退款（价格极低），但设计上保留扩展。支付系统在架构范围外，面试时说明：支付宝/微信的接入属于基础设施，本项目聚焦秒杀核心链路。
