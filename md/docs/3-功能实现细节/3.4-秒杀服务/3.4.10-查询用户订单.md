# 查询用户订单 (3.4.10)

| 属性 | 值 |
|------|-----|
| 功能编号 | 3.4.10 (原#28) |
| 所属模块 | 3.4 秒杀服务 |
| 涉及类 | `SeckillOrderController`、`SeckillOrderService`、`SeckillOrderRepository` |
| 关联功能 | 3.4.6 创建订单（查询对象）|
| 关联文档 | `2.8-接口文档.md` §二、秒杀服务、`1.4-项目约束清单.md` |

> 运行在 VT 上。纯 SELECT 查询，不加 `@Transactional(readOnly=true)`——JPA 查询本身原子，readOnly 只在 flush mode 有影响。

## 输入输出

**订单列表** `GET /seckill/order/list?page=1&size=10`（需 JWT）

| 场景 | code | data |
|------|------|------|
| 成功 | 200 | `PageResult<OrderVO>` |
| 未登录 | 401 | null |

**订单详情** `GET /seckill/order/{orderNo}`（需 JWT）

| 场景 | code | data |
|------|------|------|
| 成功 | 200 | `OrderVO` |
| 不存在 | 404 | null |

## 核心流程

```sql
-- 订单列表
SELECT * FROM t_seckill_order
WHERE user_id = ?
ORDER BY created_at DESC
LIMIT ? OFFSET ?;

-- 订单详情
SELECT * FROM t_seckill_order
WHERE order_no = ? AND user_id = ?;
```

## 边界处理

| 场景 | 行为 |
|------|------|
| 无订单 | 空列表 |
| 查看别人的订单 | 只查 userId = 当前用户，404 |
| 订单号不存在 | 404 |

🤔 **面试扩展**：订单查询为何不分库分表？秒杀订单量级预估：一次秒杀活动 10w 订单，一年 100 次约 1000w 行，单库单表索引优化即可。达到亿级才需要分表（按 user_id 或 order_no hash）。
