## 输入输出

**请求** `POST /auth/logout`（需 JWT Header）

| 字段 | 位置 | 类型 | 必填 | 说明 |
|------|------|------|------|------|
| refreshToken | Body | String | ✅ | 要注销的 token |

**响应**

| 场景 | code | message |
|------|------|---------|
| 成功 | 200 | "退出成功" |
| token 已失效 | 200 | "退出成功"（幂等） |

## 核心流程

```
POST /auth/logout { refreshToken }
  → [Gateway] JWT → userId
  → Redis GETDEL refresh:{refreshToken}
     ├── null → 幂等返回成功
  → 解析 value = "userId:role:deviceId" → 取 deviceId
  → Redis SREM device_sessions:{userId} {deviceId}
  → 返回成功
```

## 关键代码

> VT 下所有 IO 不阻塞平台线程。幂等设计——退出不检查 token 是否存在。

```java
public void logout(String refreshToken, Long userId) {
    // GETDEL 原子获取+删除，防并发下两次读到相同值
    String value = redisTemplate.opsForValue().getAndDelete("refresh:" + refreshToken);
    if (value == null) return; // 幂等：已过期或已退出
    // value = "userId:role:deviceId" → 取 deviceId
    String deviceId = value.split(":", 3)[2];
    redisTemplate.opsForSet().remove("device_sessions:" + userId, deviceId);
}
```

## 边界处理

| 场景 | 行为 |
|------|------|
| token 已过期 | GETDEL 返回 null → 幂等成功 |
| 重复退出 | 同上 |
| value 格式异常 | 500（tokens 数据不一致，登出保底）|
| 退出后 accessToken 仍可用 | 可接受，15min 后过期 |

🤔 **面试扩展**：用 GETDEL 而非 GET+DEL，防并发 GET+DEL 两次读到相同值导致 Redis 两次删除失败（第二个 DEL 删了刚写入的新值）。accessToken 退出后不黑名单，因为 15min 窗口较短，黑名单带来每次请求的 IO 开销。
