## 输入输出

**请求** `POST /auth/register`

| 字段 | 类型 | 必填 | 校验 | 示例 |
|------|------|------|------|------|
| username | String | ✅ | 4~50 字符，去空格，不可重复 | `"zhangsan"` |
| password | String | ✅ | ≥8 字符 | `"Test1234"` |
| phone | String | ❌ | 11 位手机号 | `"13800138000"` |

**响应**

| 场景 | code | message |
|------|------|---------|
| 成功 | 200 | "注册成功" |
| 用户名已存在 | 1012 (§2.1) | "用户名已被注册" |
| 参数校验失败 | 400 | 具体错误字段 |

## 核心流程

```
POST /auth/register
  → X-Idempotency-Key 幂等检查（Redis SETNX，5min TTL）
  → @Valid 参数校验
  → username.trim() 去空格
  → preRegister(password) → BCrypt.hashpw 加密（VT 事务外，不占 DB 连接）
  → register(request, hashedPwd)  [@Transactional]
      → existsByUsername 唯一性检查 → 已存在 → 1012
      → userRepository.save(username, hashedPwd, phone)
          → 并发冲突：DataIntegrityViolationException → 1012（唯一索引兜底）
  → 返回 Result.ok()
```

## 关键代码

> BCrypt 加密（纯 CPU 密集 ~10ms）在 `preRegister` 中完成——不持 @Transactional，避免 VT 下占用 DB 连接。DB 写入收紧在 `register` 方法中，加 @Transactional 保证 existsByUsername + save 的原子性。

```java
@PostMapping("/register")
public Result<Void> register(@Valid @RequestBody RegisterRequest request) {
    String hashedPwd = userService.preRegister(request.getPassword());
    userService.register(request, hashedPwd);
    return Result.ok("注册成功");
}

// ── 加密在事务外，VT 不持 DB 连接算 BCrypt ──
public String preRegister(String password) {
    return BCrypt.hashpw(password, BCrypt.gensalt(10));
}

// ── 只有 DB 操作在事务内 ──
@Transactional
public void register(RegisterRequest request, String hashedPwd) {
    String username = request.getUsername().trim();
    if (userRepository.existsByUsername(username))
        throw new BizException(1012, "用户名已被注册");
    User user = new User();
    user.setUsername(username);
    user.setPassword(hashedPwd);
    user.setPhone(request.getPhone());
    user.setStatus(1);
    try {
        userRepository.save(user);
    } catch (DataIntegrityViolationException e) {
        throw new BizException(1012, "用户名已被注册");
    }
}
```

## 边界处理

| 场景 | 行为 |
|------|------|
| 用户名带空格 | trim 后存储 |
| 大小写不同 | 视为不同用户（原样入库） |
| 并发注册同名 | `existsByUsername` 先拦，`DataIntegrityViolationException` → 1012 兜底 |
| 网络重传重复注册 | `X-Idempotency-Key` Redis SETNX 5min 去重 |
| 注册成功不自动登录 | 客户端跳转登录页 |

🤔 **面试扩展**：BCrypt 慢？注册是低频操作 <100 QPS，10ms 加密可接受。为什么 BCrypt 提前到事务外？VT 下 @Transactional 持有 DB 连接，BCrypt 是纯计算不含 DB 操作，不应占用连接。用户名唯一性通过 `existsByUsername` + `UNIQUE INDEX` + `DataIntegrityViolationException catch` 三重保险——查、拦、兜，覆盖并发窗口。
