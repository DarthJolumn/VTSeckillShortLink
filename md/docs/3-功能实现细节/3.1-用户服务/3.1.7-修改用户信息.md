## 输入输出

**请求** `PUT /user/profile`（需 JWT）

| 字段 | 类型 | 必填 | 校验 |
|------|------|------|------|
| nickname | String | ❌ | 1~50 字符 |
| avatar | String | ❌ | URL 格式 |
| phone | String | ❌ | 11 位手机号，不可与其他用户冲突 |

**请求** `PUT /user/password`（需 JWT）

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| oldPassword | String | ✅ | 旧密码 BCrypt 验证 |
| newPassword | String | ✅ | ≥8 字符 |

**响应**

| 场景 | code (§2.1) | message |
|------|-------------|---------|
| 成功 | 200 | — |
| 旧密码错误 | 1010 | "旧密码错误" |
| 手机号已被使用 | 1014 | "手机号已被绑定" |
| 参数校验失败 | 400 | 具体字段 |
| 用户不存在 | 404 | "用户不存在" |

## 核心流程

```
PUT /user/profile
  → [Gateway] JWT → userId
  → 只更新非 null 字段
  → phone 唯一性排除自己后检查 → 冲突 → 1014
  → UPDATE t_user SET nickname=?, avatar=?, phone=? WHERE id=?

PUT /user/password
  → [Gateway] JWT → userId
  → 查 t_user → 不存在 → 404
  → BCrypt.checkpw(oldPassword) → 不匹配 → 1010
  → BCrypt.hashpw(newPassword) → SET password=?
```

## 关键代码

> VT + `@Transactional` 纪律：明确涉及 DB 写入（UPDATE）的操作加 `@Transactional`，纯查询不加。

### 修改资料

```java
@Transactional
public void updateProfile(Long userId, UpdateProfileRequest req) {
    User user = userRepository.findById(userId)
            .orElseThrow(() -> new BizException(404, "用户不存在"));

    // 手机号唯一性检查
    if (req.getPhone() != null && !req.getPhone().equals(user.getPhone())) {
        if (userRepository.existsByPhoneAndIdNot(req.getPhone(), userId)) {
            throw new BizException(1014, "手机号已被绑定");
        }
        user.setPhone(req.getPhone());
    }
    if (req.getNickname() != null) user.setNickname(req.getNickname());
    if (req.getAvatar() != null) user.setAvatar(req.getAvatar());

    userRepository.save(user);
}
```

### 修改密码

```java
// ✅ BCrypt.checkpw 在事务外，只有 DB 写在事务内
public void changePassword(Long userId, String oldPwd, String newPwd) {
    User user = userRepository.findById(userId)
            .orElseThrow(() -> new BizException(404, "用户不存在"));

    if (!BCrypt.checkpw(oldPwd, user.getPassword())) {
        throw new BizException(1010, "旧密码错误");
    }
    String hashedPwd = BCrypt.hashpw(newPwd, BCrypt.gensalt(10));
    updatePassword(userId, hashedPwd);
}

@Transactional
private void updatePassword(Long userId, String hashedPwd) {
    User user = userRepository.findById(userId).get();
    user.setPassword(hashedPwd);
    userRepository.save(user);
}
```

## 边界处理

| 场景 | 行为 |
|------|------|
| 只传 nickname | 仅更新该字段 |
| 什么都不传 | 幂等——字段全 null 只查不更新 |
| 手机号已存在（他人）| 1014 |
| 手机号已存在（自身）| 幂等，通过 |
| 新旧密码相同 | 允许（BCrypt 加密后密文不同）|
| 旧密码错 | 1010（不改 password 字段）|
| VT + @Transactional | changePassword：BCrypt 在事务外，只有 DB UPDATE 在事务内 |
| VT + @Transactional | idempotent—phone 是自己的、什么都不改，直接返回 |

🤔 **面试扩展**：修改信息不刷新 JWT（用户信息如 nickname/phone 不编码在 JWT 中，JWT 只存 userId + role）。修改密码后是否踢其他设备？本版本不踢，可作为安全优化点。为什么 changePassword 的 BCrypt 在事务外？BCrypt.checkpw ~10ms CPU 计算 + BCrypt.hashpw ~10ms CPU 计算，加一起 20ms。VT 下 @Transactional 持有 DB 连接，纯计算不应占用连接——遵循 1.4 的 @Transactional 纪律。
