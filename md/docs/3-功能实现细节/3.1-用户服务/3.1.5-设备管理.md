> 本项目所有业务服务运行在 VT 上（`spring.threads.virtual.enabled=true`）。以下代码跑在 VT 上，不涉及 DB 写入，不加 `@Transactional`。

## 输入输出

**请求** `GET /user/devices`（需 JWT）

**响应**

| 场景 | code | 说明 |
|------|------|------|
| 成功 | 200 | `DeviceInfo[]` 设备列表 |
| 未登录 | 401 | JWT 无效 |

```json
[{ "deviceId": "a1b2c3d4", "loginTime": 1719465600, "current": true }]
```

## 核心流程

```
GET /user/devices
  → [Gateway] JWT → userId（ScopedValue）
  → SMEMBERS device_sessions:{userId} → 所有 deviceId
  → 标记当前设备（对比 X-Device-Id Header）
  → 返回列表
```

> ⚠️ `device_sessions:{userId}` Set 中存储的 deviceId 在 3.1.2 登录时通过 `SADD + EXPIRE 7d` 写入，与 refreshToken 同生命周期。超过 7 天未登录的设备自动过期清理。

## 关键代码

```java
// 运行在 VT 上。纯 Redis 读操作，不加 @Transactional。
public List<DeviceInfo> getDevices(Long userId, String currentDeviceId) {
    Set<String> deviceIds = redisTemplate.opsForSet()
            .members("device_sessions:" + userId);
    if (deviceIds == null || deviceIds.isEmpty()) return List.of();
    return deviceIds.stream()
            .map(did -> DeviceInfo.builder()
                    .deviceId(did)
                    .current(did.equals(currentDeviceId))
                    .build())
            .collect(Collectors.toList());
}
```

## 边界处理

| 场景 | 行为 |
|------|------|
| 无设备 | 空列表 `[]` |
| 多设备登录 | 各设备独立条目 |
| device_sessions key 过期（7天未回访） | 返回空列表，用户不感知 |

🤔 **面试扩展**：
- **追问：VT 下 SMEMBERS 的 Blocking 行为？** → `redisTemplate.opsForSet().members()` 是同步阻塞调用，在 VT 上执行时底层会 park VT，释放平台线程去跑其他 VT。SMEMBERS 命令本身 O(N) 但正常用户 ≤ 10 台设备，毫秒级返回
- **追问：怎么拿到登录时间？** → 当前 refresh token value 存 `userId:role:deviceId`。要拿时间要么扩展 value 格式（不推荐——影响所有 parse 代码），要么维护 `device_session_info:{userId}:{deviceId}` hash 存 loginTime + ip + userAgent。本项目演示级，当前只返回设备列表
- **追问：设备信息和 refreshToken 生命周期不一致怎么办？** → 目前 device_sessions key 的 EXPIRE 和 refreshToken 7天一致。但如果用户刷了 refreshToken（3.1.3 Rotation 换新 key），旧 key DEL 但 device_sessions set 不变。这意味着 deviceId 仍在线但实际 refreshToken 已换。解决方案：加 `device_token_rev:{userId}:{deviceId}` 版本号或扫描 refresh:* 验证
