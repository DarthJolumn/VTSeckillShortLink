## 核心配置

```yaml
spring:
  cloud:
    gateway:
      routes:
        - id: user-service
          uri: lb://livemall-user
          predicates: [Path=/auth/**, /user/**]
        - id: seckill-service
          uri: lb://livemall-seckill
          predicates: [Path=/seckill/**]
        - id: leaderboard-service
          uri: lb://livemall-leaderboard
          predicates: [Path=/leaderboard/**]
        - id: websocket-service
          uri: lb:ws://livemall-websocket
          predicates: [Path=/ws/**]
```

## 核心流程

```
客户端请求 → Nginx → Gateway(8080)
  → 路由匹配（Path 前缀）
  → Nacos 服务发现 → lb:// 负载均衡
  → Filter 链执行
  → 转发到目标服务
```

## 边界处理

| 场景 | 行为 |
|------|------|
| 服务不可用 | Gateway 返回 503 Service Unavailable |
| 路由不匹配 | 404 Not Found |
| WebSocket 升级 | lb:ws:// 协议支持 WS upgrade |

🤔 **面试扩展**：为什么用 `lb://` 而不是硬编码地址？Nacos 服务发现自动负载均衡。Gateway 是唯一 WebFlux 服务——WebFlux 的异步非阻塞 IO 适合网关的 IO 密集型场景（大量连接转发）。
