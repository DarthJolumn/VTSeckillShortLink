## 核心流程

```
请求进入 Gateway
  → JwtAuthGlobalFilter (Order=-5)
  → 白名单判断（/auth/login, /auth/register, /actuator/health → 跳过）
  → 提取 Authorization: Bearer <token>
  → JwtUtil.verify(token) 验签
     ├── 失败 → 401 Unauthorized
  → 提取 Claims（userId, role）
  → 存入 exchange.getAttributes()
  → 请求转发前写入 Header
     downstream-service 收到 Header → 拦截器 → 赋值到 ScopedValue
```

## 关键代码

```java
@Component
public class JwtAuthGlobalFilter implements GlobalFilter, Ordered {
    private static final List<String> WHITE_LIST = List.of(
            "/auth/login", "/auth/register", "/actuator/health");

    @Override
    public Mono<Void> filter(ServerWebExchange exchange, GatewayFilterChain chain) {
        String path = exchange.getRequest().getURI().getPath();
        if (isWhiteListed(path)) return chain.filter(exchange);

        String token = extractToken(exchange.getRequest());
        if (token == null) return unauthorized(exchange, "Missing token");

        try {
            Claims claims = JwtUtil.verify(token);
            exchange.getAttributes().put("userId", claims.get("userId"));
            exchange.getAttributes().put("role", claims.get("role"));
            return chain.filter(exchange);
        } catch (Exception e) {
            return unauthorized(exchange, "Invalid token");
        }
    }

    @Override
    public int getOrder() { return -5; }
}
```

## ScopedValue 传递

```
Gateway exchange.attributes
  → 转发前 GlobalFilter 写入 Header: X-User-Id, X-User-Role
  → 下游 MVC 服务 @RequestHeader 或 HandlerInterceptor 提取
  → ScopedValue.where(UserContext.USER_ID, userId).run(() -> { ... })
```

## 边界处理

| 场景 | 行为 |
|------|------|
| Token 过期 | 401 |
| Token 签名错误 | 401 |
| 白名单接口带 JWT | 不校验，透传 |
| 无 Token | 401 |
| Header 注入失败 | 下游服务无 userId → 业务异常 |

🤔 **面试扩展**：为什么不在 Gateway 直接用 ScopedValue？WebFlux 响应式链路可能切换线程（Reactor EventLoop），ScopedValue 绑定在当前线程，切换后丢失。MVC + VT 同步模型不存在此问题。HMAC-SHA256 1 核验 5w+ TPS。
