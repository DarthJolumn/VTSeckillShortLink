## 配置

```java
@Configuration
public class SentinelConfig {
    @PostConstruct
    public void initGatewayRules() {
        Set<GatewayFlowRule> rules = new HashSet<>();

        // 秒杀：每用户每活动 100 QPS
        rules.add(new GatewayFlowRule("seckill:create")
                .setResourceMode(RESOURCE_MODE_ROUTE_ID)
                .setParamItem(new GatewayParamFlowItem()
                        .setParseStrategy(PARAM_PARSE_STRATEGY_URL_PARAM)
                        .setFieldName("activityId"))
                .setCount(100)
                .setIntervalSec(1));

        // 登录：每 IP 10 QPS
        rules.add(new GatewayFlowRule("auth:login")
                .setCount(10).setIntervalSec(1));

        GatewayRuleManager.loadRules(rules);
    }
}
```

## 核心流程

```
请求进入 → Sentinel 热点参数限流
  → 秒杀接口: 按 activityId + userId 分组，限 100 QPS
  → 登录接口: 按 IP 限 10 QPS
  → 超出 → 返回 429 Too Many Requests
```

## 嵌入模式多节点

> ⚠️ Sentinel 嵌入模式下各节点独立计数。3 个 Gateway 节点 count=100 → 实际总限流 = 300。生产环境用 Sentinel Dashboard 推全局规则。本项目单节点部署，不受影响。

## 边界处理

| 场景 | 行为 |
|------|------|
| 正常请求 | 放行 |
| 超过阈值 | 429 |
| Sentinel 挂了 | 降级为不做限流，Nginx 层兜底 |

🤔 **面试扩展**：Sentinel 滑动窗口精度（LeapArray 2 个 500ms 窗口），比固定窗口更平滑。热点参数限流的原理：为每个参数组合维护独立的计数器。
