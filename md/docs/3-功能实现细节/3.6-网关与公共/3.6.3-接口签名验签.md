## 核心流程

```
SignVerifyGlobalFilter (Order=-10，在 JWT 之前执行)
  → 判断是否需要签名（非白名单且带签名 Header）
  → 提取 X-Timestamp, X-Nonce, X-Sign
  → 时间窗口校验：|now - timestamp| > 5min → 401
  → Nonce 防重放：SETNX nonce:{nonce} TTL 60s → 已存在 → 401
  → 根据 X-AppKey 查 Secret
  → 重算 HMAC-SHA256(timestamp + nonce + secret) == sign？
     ├── 不等 → 401
  → 放行（签名即身份凭证，跳过 JWT）
```

## 关键代码

> ⚠️ **P0-1 fixed**：Gateway 是 WebFlux EventLoop，`SignVerifyGlobalFilter` 中 Nonce 检查必须用 `ReactiveRedisTemplate` 做非阻塞调用。原同步 `RedisTemplate.setIfAbsent()` 会阻塞 EventLoop 线程，高并发下导致网关排队。

```java
@Component
public class SignVerifyGlobalFilter implements GlobalFilter, Ordered {
    private static final long TIME_WINDOW = 5 * 60 * 1000L; // ±5min

    @Override
    public Mono<Void> filter(ServerWebExchange exchange, GatewayFilterChain chain) {
        HttpHeaders headers = exchange.getRequest().getHeaders();
        String timestamp = headers.getFirst("X-Timestamp");
        String nonce = headers.getFirst("X-Nonce");
        String sign = headers.getFirst("X-Sign");

        if (timestamp == null || nonce == null || sign == null)
            return unauthorized(exchange, "Missing signature headers");

        // 时间窗口（纯 CPU，不阻塞）
        if (Math.abs(System.currentTimeMillis() - Long.parseLong(timestamp)) > TIME_WINDOW)
            return unauthorized(exchange, "Timestamp expired");

        // Nonce 防重放——ReactiveRedisTemplate 非阻塞
        return reactiveRedisTemplate.opsForValue()
            .setIfAbsent("nonce:" + nonce, "1", Duration.ofSeconds(60))
            .flatMap(success -> {
                if (Boolean.FALSE.equals(success))
                    return unauthorized(exchange, "Nonce reused");

                // 签名校验
                String secret = getSecretByAppKey(headers.getFirst("X-AppKey"));
                String expectedSign = HmacUtil.sha256(timestamp + nonce + secret);
                if (!expectedSign.equals(sign))
                    return unauthorized(exchange, "Invalid signature");

                return chain.filter(exchange);
            });
    }

    @Override
    public int getOrder() { return -10; }
}
```

## 边界处理

| 场景 | 行为 |
|------|------|
| 时间戳超过 ±5min | 401 |
| Nonce 重复使用 | 401（SETNX 60s 内防重放）|
| 签名错误 | 401 |
| Secret 不匹配 | 401 |

🤔 **面试扩展**：timestamp + nonce 组合保证一次一签，防重放攻击。为什么 5min 窗口？容忍客户端时钟偏差。SETNX 60s 过期 Nonce——60s 后允许相同 nonce 理论上可重放，但实际已超过 5min 时间窗口，两重限制双保险。
