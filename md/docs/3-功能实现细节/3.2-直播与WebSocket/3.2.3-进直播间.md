## 输入输出

**连接** `ws://host:8083/ws/live/{roomId}?token=<AccessToken>`

| 场景 | WS 关闭码 | 说明 |
|------|-----------|------|
| 连接成功 | — | 正常建立连接 |
| Token 无效 | 4001 | @OnOpen 中校验失败 |
| 房间已关播/不存在 | 4004 | 活动校验失败 |

## VT 配置

```java
@Bean
public ServletServerContainerFactoryBean websocketContainer() {
    ServletServerContainerFactoryBean container = new ServletServerContainerFactoryBean();
    container.setExecutor(Executors.newVirtualThreadPerTaskExecutor());
    return container;
}
```

缺此配置则 @ServerEndpoint 跑在 Tomcat 线程池上，不是 VT。

## 核心流程

```
@OnOpen(roomId, token)
  → 运行在 VT 上（由 container.setExecutor 保证）
  → JwtUtil.verify(token) → userId
     ├── 失败 → session.close(4001)
  → 查房间存在/开播中
     ├── 房间不存在或已关播 → session.close(4004)
  → [踢旧连接] 查 Redis ws:route:{userId}
     ├── 有旧 session → 异步 VT 发 KICK → 3s 后 close
     ├── 新 session 立即注册，不阻塞 onOpen
  → Redis SADD "room:members:{roomId}" userId
  → Redis SET "ws:route:{userId}" "{nodeId}:{sessionId}" EX 30min
  → RoomManager 本地缓存 sessionId
  → 通知房间用户 online_count 更新
```

## 广播并发安全

`@OnMessage` 和广播都在 VT 上运行，多个 VT 可能同时往同一个 session 发消息。`getBasicRemote().sendText()` 不是线程安全的：

```java
// ✅ 必须用 AsyncRemote，无锁且 VT 不 pin
session.getAsyncRemote().sendText(message);
```

> ⚠️ VT 下**禁止** `synchronized (session) { session.getBasicRemote().sendText(msg); }` — `synchronized` 会导致 VT pinning（carrier 线程无法释放），在 IO 操作中持有锁时尤其致命。

## 边界处理

| 场景 | 行为 |
|------|------|
| Token 过期 | @OnOpen 校验返回 4001 |
| 重复进同一房间 | 异步踢旧连接，新连接立即可用 |
| 房间 ID 为负数/null | session.close(4004) |
| 并发进同一用户 | 先后到达，后者踢前者 |

🤔 **面试扩展**：
- **追问：container.setExecutor 不设会怎样？** → Tomcat 默认用 `ForkJoinPool.commonPool()` 或自身线程池处理 WebSocket 消息。设了 VT Executor 后每个 @OnOpen/@OnMessage/@OnClose 都跑在独立 VT 上，百万连接 = 百万 VT
- **追问：VT 下为什么不能用 `synchronized(session)` ？** → `synchronized` 是 JVM 内置锁，持有锁的 VT 无法 unmount（pinning），carrier 平台线程被占住。如果 `sendText()` 网络 IO 慢（200ms），200ms 内该平台线程无法调度任何其他 VT。`AsyncRemote` 内部用 CAS/队列，无锁 + 异步发送，VT 友好
- **追问：getBasicRemote 并发安全怎么测？** → 两个 VT 同时 sendText 可能交叠输出（部分帧 A + 部分帧 B 混合）。JSR 356 规范不保证 sendText 线程安全，必须外部同步或用 AsyncRemote
