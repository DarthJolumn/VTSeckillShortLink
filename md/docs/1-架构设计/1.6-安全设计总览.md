# 安全设计总览

> 集中梳理认证、加密、威胁防护、日志脱敏等安全措施。各实现细节分散在模块设计中，本文档提供全局视角和面试应答框架。

---

## 一、安全架构概览

```
客户端请求
  → Nginx（X-Forwarded-For 透传）
  → Gateway
      ├── 签名验签（HMAC-SHA256 + Timestamp + Nonce）
      ├── JWT 鉴权（Access Token 15min）
      └── Sentinel 限流（防刷/防 DDoS）
  → 业务服务
      ├── BCrypt 密码加密（work factor=10）
      ├── ScopedValue 用户上下文（防篡改）
      ├── DFA 敏感词过滤（弹幕内容，WebSocket onMessage 层）
      ├── Lua 原子扣库存（防超卖，Seckill 层）
      └── 乐观锁 CAS（防并发冲突，Seckill 层）
```

---

## 二、威胁模型（STRIDE 简化）

| 威胁类型 | 攻击场景 | 防护措施 | 实现位置 |
|---------|---------|---------|---------|
| **伪造（Spoofing）** | 伪造用户身份 | JWT 签名 + 接口签名 HMAC | Gateway Filter |
| **篡改（Tampering）** | 请求参数被中间人篡改 | HMAC-SHA256 签名校验 body+query | Gateway Filter |
| **重放（Replay）** | 截获请求后重复发送 | Nonce SETNX 60s + Timestamp ±5min | Gateway Filter |
| **信息泄露（Info Disclosure）** | 日志中泄露 Token/密码 | 日志脱敏不输出敏感字段 | 各服务 |
| **拒绝服务（DoS）** | 恶意刷接口 | Sentinel 热点参数限流 + IP 限流 | Gateway |
| **权限提升（Elevation）** | 普通用户调用管理接口 | @RequireRole 注解 + JWT role 校验 | Gateway + 业务服务 |

## 三、认证体系

### 3.1 外部认证：双 Token

```
登录 → Access JWT（15min，无状态）+ Refresh Token（7天，Redis 可撤销）
99% 请求 → Gateway 验 JWT 签名（零 IO）
1% 刷新 → Redis 查 Refresh Token → 签发新 Access
```

| 安全特性 | 机制 |
|---------|------|
| Token 泄露窗口 | Access 15min，泄露影响有限 |
| 主动撤销 | 删 Redis Refresh Token，Access 15min 后自然失效 |
| 泄露检测 | Rotation 模式——旧 Refresh 被刷新过，原持有者会发现失效 |
| 暴力破解防护 | Sentinel 登录接口每 IP 10 QPS |

### 3.2 内部认证：接口签名

服务间 HTTP 调用（非 Dubbo）用 HMAC-SHA256 签名：

```
sign = HMAC-SHA256(method + uri + timestamp + nonce + body, secretKey)
```

| 防护 | 机制 |
|------|------|
| 防伪造 | secretKey 服务端各持一份，攻击者无法重算签名 |
| 防重放 | Nonce SETNX 60s + Timestamp ±5min 窗口 |
| 降级 | Redis 挂了跳过 Nonce，仅验 timestamp + sign |

### 3.3 WebSocket 认证

连接 URL 带 Access Token 在 Query String：

```
ws://host:8083/ws/live/{roomId}?token=<AccessToken>
```

`@OnOpen` 中验签，失败关闭连接发 4001 状态码。WS 握手后是长连接，不走 Gateway Filter 链。

## 四、数据安全

### 4.1 密码存储

BCrypt（work factor=10），不可逆。注册 → BCrypt.hashpw → 存密文；登录 → BCrypt.checkpw → 比对。

### 4.2 敏感词过滤

弹幕/评论出发前服务端 DFA（Trie 树）过滤。客户端不可信——服务器过滤是安全底线。

### 4.3 SQL 注入防护

- ORM 框架（Spring Data JPA / MyBatis）参数化查询，天然防注入
- 唯一手写 SQL 在排行榜快照批量 INSERT，用 `PreparedStatement` 占位符
- 不在代码中拼接 SQL 字符串

### 4.4 日志脱敏

日志中不输出：
- 密码（明文/密文均不输出）
- Token（Access / Refresh 全值不输出，仅记录前 8 位）
- 手机号（中间 4 位用 `****` 代替）
- 身份证/银行卡号（本项目不涉及）

## 五、业务安全

### 5.1 秒杀防超卖

Redis Lua 原子扣库存，DECR 负数 → 返回库存不足。Lua 脚本单线程原子执行，天然防超卖。

### 5.2 秒杀防刷单

- 一人一单：`uk_activity_user` 唯一索引 + Lua 中的 `ordered:{activityId}:{userId}` 标记
- 限流：Sentinel 按 `activityId + userId` 热点参数限流 100 QPS

### 5.3 订单状态机防并发

乐观锁 `version` 字段 + `WHERE version = ? AND status = ?` 双重校验，防止：
- 超时取消和用户取消并发
- 重复退款

### 5.4 单端登录踢人

新连接建立 → Redis `ws:route:{userId}` 查旧 session → 发 KICK → 等 3s → 强制关闭。旧连接无法再发消息。

## 六、基础设施安全

| 层面 | 措施 | 说明 |
|------|------|------|
| 网络 | VM 内部网络，中间件不暴露宿主机端口 | MySQL/Redis 仅 VM 内可访问 |
| Docker | 非 root 运行（面试时说明） | 当前开发环境用 root，实际生产切非 root |
| Nginx | `X-Forwarded-For` 透传真实 IP | Sentinel IP 限流依赖 |
| CORS | `allowedOrigin` 限定 localhost:8080 | 不可与 `allowCredentials(true) + *` 同用 |
| 中间件密码 | 环境变量注入，不硬编码 | `MYSQL_ROOT_PASSWORD`、`--requirepass` |

## 七、面试应答框架

### 7.1 "你们系统怎么保证安全？"

> 分层防护：最外层 Nginx 透传真实 IP → Gateway 层做双鉴权（签名 + JWT）+ Sentinel 限流防刷 → 业务层 BCrypt 密码加密 + Lua 原子防超卖 + 乐观锁防并发 → 数据层参数化查询防注入 + 日志脱敏。每一层都有对应面试追问点。

### 7.2 未实现的可优化点

| 优化项 | 现状 | 面试时的改进方案 |
|--------|------|----------------|
| HTTPS | HTTP（本地开发） | Nginx 终止 TLS，内部 HTTP 不变 |
| 异地登录检测 | 未实现 | 对比登录 IP 与历史 IP 地理位置，异地发送通知 |
| 登录二次认证 | 未实现 | 短信/邮箱验证码（TOTP），本项目侧重秒杀链路可暂缓 |
| WAF | 未实现 | Nginx ModSecurity 拦截 SQL 注入/XSS |
| 数据库加密 | 未实现 | 手机号等敏感字段 AES 加密存储 |
| 审计日志 | 仅业务日志 | 独立审计日志表记录所有敏感操作 |
