## 一、线程模型约束

### 1.1 各模块线程模型

| 模块 | 框架 | 线程模型 | 端口 |
|------|------|---------|------|
| livemall-user | Spring MVC | VT | 8081 |
| livemall-seckill | Spring MVC | VT | 8082 |
| livemall-websocket | @ServerEndpoint | **VT（需显式配置 Executor）** | 8083 |
| livemall-leaderboard | Spring MVC | VT | 8084 |
| livemall-gateway | Spring Cloud Gateway | **WebFlux（EventLoop）** | 8080 |

**核心原则**：Gateway 是唯一响应式服务，其他全是同步 MVC + VT。

### 1.2 VT 开启方式

```yaml
# 所有业务服务 application.yml
spring:
  threads:
    virtual:
      enabled: true
```

```java
// livemall-websocket 额外配置（否则 @ServerEndpoint 跑在 Tomcat 线程池）
@Bean
public ServletServerContainerFactoryBean websocketContainer() {
    ServletServerContainerFactoryBean container = new ServletServerContainerFactoryBean();
    container.setExecutor(Executors.newVirtualThreadPerTaskExecutor());
    return container;
}
```

### 1.3 @Transactional 纪律

> `@Transactional` 持有 DB 连接直到方法返回。VT 下非 DB 操作不应占用 DB 连接。

```java
// ❌ 错误：BCrypt + Redis I/O 在事务内
@Transactional
public LoginResponse login(LoginRequest req) {
    User user = userRepository.findByUsername(req.getUsername()); // DB
    BCrypt.checkpw(req.getPassword(), user.getPassword());        // CPU 10ms，占连接
    String accessToken = JwtUtil.sign(user.getId(), user.getRole()); // CPU
    redisTemplate.opsForValue().set(refreshKey, refreshToken, 7, DAYS); // IO，占连接
    return new LoginResponse(accessToken, refreshToken);
}

// ✅ 正确：事务只包裹查 DB，BCrypt/JWT/Redis 在事务外
public LoginResponse login(LoginRequest req) {
    User user = userService.loadByUsername(req.getUsername()); // 独立事务
    if (!BCrypt.checkpw(req.getPassword(), user.getPassword()))
        throw new BizException(1011, "用户名或密码错误");
    String accessToken = JwtUtil.sign(user.getId(), user.getRole());
    String refreshToken = TokenUtil.generateRefreshToken();
    redisTemplate.opsForValue().set("refresh:" + user.getId(), refreshToken, 7, DAYS);
    return new LoginResponse(accessToken, refreshToken);
}

// ✅ 正确：注册等纯写入操作，事务只包裹 DB 写入
@Transactional
public void register(RegisterRequest req) {
    if (userRepository.existsByUsername(req.getUsername()))
        throw new BizException(1012, "用户名已被注册");
    userRepository.save(user);
}
```

### 1.4 用户上下文

**禁止 `ThreadLocal`**。VT 池化后 ThreadLocal 残留 → 内存泄漏。必须用 `ScopedValue`：

```java
// common 模块 UserContext.java
public class UserContext {
    private static final ScopedValue<Long> USER_ID = ScopedValue.newInstance();
    public static Long getUserId() { return USER_ID.get(); }
}

// 使用处
ScopedValue.where(UserContext.USER_ID, userId).run(() -> { ... });
```

Gateway 例外：WebFlux 中不可用 ScopedValue（Reactor EventLoop 切换线程丢失）。
方案：`exchange.getAttributes()` → 转发前写 Header → 下游 MVC 服务提取后赋给 ScopedValue。

### 1.5 @Scheduled 纪律

`@Scheduled` 在**平台线程**上运行。如需 VT 行为（如 session.close 触发 @OnClose），必须手动：

```java
@Scheduled(fixedRate = 10000)
public void checkHeartbeat() {
    for (Session s : staleSessions) {
        Thread.startVirtualThread(() -> s.close()); // 异步 VT
    }
}
```

### 1.6 VT 下的异步处理

`Thread.sleep()` / 长轮询 / 等待 → **禁止同步阻塞**，用异步 VT：

```java
// ❌ 错误：同步 sleep 阻塞 Controller
@OnOpen
public void onOpen(...) {
    oldSession.sendText(KICK);
    Thread.sleep(3000); // @OnOpen 卡 3s
}

// ✅ 正确：异步 VT，接口立即返回
Thread.startVirtualThread(() -> {
    oldSession.sendText(KICK);
    Thread.sleep(3000);
    if (oldSession.isOpen()) oldSession.close();
});
```

### 1.7 VT 下的锁纪律 — synchronized → ReentrantLock

> VT 持有 `synchronized` 锁时 **无法 unmount**（pinning），carrier 平台线程被占住。IO 操作 + synchronized = 致命组合。

| 场景 | ❌ 禁止 | ✅ 替代 |
|------|--------|--------|
| WebSocket session 同步 | `synchronized (session) { sendText(msg); }` | `session.getAsyncRemote().sendText(msg)`（内部线程安全） |
| Snowflake ID 生成 | `public synchronized long nextId()` | `ReentrantLock`，sleep 前 unlock |
| 任意含 IO 的临界区 | `synchronized` + 网络/磁盘 IO | `ReentrantLock`（VT 可 unmount） |

```java
// ❌ 致命：synchronized 内 IO，VT pin 到 carrier 直到 sendText 返回
synchronized (session) {
    session.getBasicRemote().sendText(msg); // 可能 200ms+
}

// ✅ ReentrantLock：VT park 时可 unmount
private final Lock lock = new ReentrantLock();
lock.lock();
try {
    session.getAsyncRemote().sendText(msg);
} finally {
    lock.unlock();
}
```

> **面试必答**：`synchronized` 是 JVM 内置锁，持有者 pin 到 carrier。`ReentrantLock` (java.util.concurrent) 持有者可正常 unmount/park。这是 VT 面试的核心考点之一。

## 二、中间件约束

### 2.1 RPC：Dubbo

- **唯一** RPC 框架。禁用 Feign / gRPC / RestTemplate 服务间调用。
- Dubbo API 接口定义在 `livemall-common` 模块的 `api/` 包下。
- 线程模型：Netty IO 线程 + VT Biz 线程。

### 2.2 消息队列：Kafka

- **唯一** MQ。禁用 RocketMQ / RabbitMQ。
- 3.x KRaft 模式（不依赖 ZK）。
- 消费者手动 commit + VT 逐条消费。
- 分区 key 用 `userId` 保证同一用户消息有序。

### 2.3 缓存层次

```
读：Client → [Caffeine] → [Redis] → [MySQL]
写：MySQL → MQ 更新缓存（最终一致）
```

| 缓存 | TTL | 使用场景 |
|------|-----|---------|
| Caffeine | 1s | 秒杀活动状态、TopN 排行 |
| Caffeine | 5min | 用户基本信息 |
| Redis | 7天 | Refresh Token |
| Redis | 活动时长 | 库存分片 key |

### 2.4 Redis 约束

- **库存分片路由**：`userId % shardCount`，禁止遍历。
- **Lua 脚本**：原子扣库存，代替 `MULTI/EXEC`。
- **Value 格式**：`String.split(":", limit)` **必须带 limit**。

```java
// ✅ 正确：带 limit
String[] parts = value.split(":", 3);

// ❌ 错误：不带 limit
String[] parts = value.split(":");
```

### 2.5 Sentinel 约束

- 嵌入模式，各节点独立计数。
- 多节点总限流 = 单节点阈值 × 节点数（在文档显式标注此 ⚠️）。
- 双实例部署时，`count` 按节点数均分或使用 Sentinel Dashboard 推全局规则。

### 2.6 注册中心与配置中心

- Nacos 单套部署，既是注册中心也是配置中心。
- 所有服务通过 `lb://` 服务名发现。
