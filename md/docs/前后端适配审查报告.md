## 三、Mock 假数据来源分析

> 你在 Chrome 里看到的自动冒出来的弹幕、礼物、人数跳动、库存变化——以下是完整溯源。

### 3.1 Mock 总开关

`stores/live.js:12`：
```js
const USE_MOCK = import.meta.env.VITE_USE_WS_MOCK === '1' || !tokensExists()
function tokensExists() {
  try { return !!localStorage.getItem('lm_refresh') } catch { return false }
}
```

**触发条件（满足任一即启用 mock）：**
1. 环境变量 `VITE_USE_WS_MOCK=1`
2. localStorage 中没有 `lm_refresh` 键

### 3.2 Mock 数据生成清单

| 来源 | 数据 | 频率 | 代码位置 |
|---|---|---|---|
| `ws-mock.js` | 随机弹幕（从 40 条候选池中选） | 每 2.5 秒 | `ws-mock.js:54-63` |
| `ws-mock.js` | 随机送礼（4 种礼物，随机 1~3 个） | 每 7 秒 | `ws-mock.js:66-81` |
| `ws-mock.js` | 在线人数抖动（±18~28） | 每 4 秒 | `ws-mock.js:84-87` |
| `ws-mock.js` | 库存缓慢消耗（-1~3） | 每 5.5 秒 | `ws-mock.js:90-93` |
| `ws-mock.js` | 秒杀结果（60% 命中率，800~1400ms 模拟延迟） | 用户点击秒杀时 | `ws-mock.js:125-151` |
| `LiveRoom.vue:247-264` | 活动名/价格/库存/倒计时/钱包余额硬编码 | 进入直播间即用 | `activity`, `walletBalance` |
| `order.js:22-26` | 订单号 `LM${timestamp36}${random6}` | `orderStore.create()` | 客户端生成 |
| `Login.vue:130-142` | `demo-access` / `demo-refresh` 假 Token + `id:0` 假用户 | 点击"演示登录"按钮 | 写入 localStorage |
| `ActivityManage.vue:352-359` | 4 条硬编码活动数据 | 后端请求失败时 | `catch {}` 降级 |
| `Dashboard.vue` | 全站 KPI/QPS/排行榜/战况/健康度 | 页面挂载后每 5s | 全部 `Math.random()` |
| `UserManage.vue:272-286` | 8 条假用户 | 后端请求失败时 | `catch {}` 降级 |
| `Devices.vue:171` | 3 台假设备 | 后端请求失败时 | `catch {}` 降级 |
| `StreamConsole.vue:331-348` | 主播端实时统计（在线/打赏/弹幕数） | 开播后每 5s | 全部 `Math.random()` |

### 3.3 关键矛盾

**演示登录**（`Login.vue:130`）写入 `lm_refresh = 'demo-refresh'` → `tokensExists()` 返回 `true` → `USE_MOCK = false`，**但** Token 是假的，WebSocket 连接会带假 Token 去连后端 → 后端验签失败，降级为匿名连接 → 匿名连接只能收不能发 → 弹幕/送礼/秒杀全失败。

**实际上 mock 驱动接管了一切**——因为 `USE_MOCK` 的判断逻辑是：
- 有 `lm_refresh` → 不走 mock → 连真实 WS
- 没有 `lm_refresh` → 走 mock → 所有数据都是假的

但演示登录场景下：有假 `lm_refresh` → 连真实 WS（失败/匿名）→ 没有任何广播回来 → 页面一片空白。前端没有处理这种降级。

## 五、汇总

| 类别 | 问题数 | 关键项 |
|---|---|---|
| REST 接口不匹配 | **3 缺失端点 + 1 字段不匹配** | UserController 缺 3 个端点；SeckillActivity 前后端字段名全不一致 |
| WS 消息协议不匹配 | **5 处** | `nickname`↔`username`、`success`↔`ok`、缺 ONLINE_COUNT/STOCK_UPDATE/BAN/ROOM_CLOSED 广播 |
| Mock 假数据源头 | **10 处** | `ws-mock.js` + `Login.vue` 演示登录 + 5 个页面的 catch 降级 |
| 安全缺项 | **12 项** | P0×3 / P1×3 / P2×6 |

**修复建议优先级：**

1. **B1/B2** — WS 协议字段对齐（`nickname`→`username`、`success`→`ok`）——不改的话真后端连上也不显示数据
2. **A2** — SeckillActivity 前端→后端字段名统一（方案：前端做 DTO 转换层，不动后端 JPA 实体）
3. **A1** — UserController 补充 `PUT /user/profile`、`PUT /user/password`、`PUT /user/ban/{userId}`
4. **D1/D2/D3** — throttle + 幂等键 + WS 去重（安全底座）
5. **C** — 统一 mock 开关：加 `VITE_MOCK_MODE` 环境变量，去掉 `tokensExists()` 的隐式判断
