> 审查日期：2026-07-19
> 方法：对每个故障场景逐一追踪请求路径，检查是否有降级或兜底

| 故障 | 对系统的影响 | 当前有降级？ | 严重度 |

## 一、Redis 挂了

### 影响范围

| 功能 | 影响 | 当前代码处理 |
|---|---|---|
| 秒杀 Lua 扣库存 | `deduct()` 抛 RedisConnectionFailureException | ❌ 未 catch，异常直接抛到 Controller |
| 认证 refresh/login | `opsForValue().get()` 抛异常 | ✅ UserService catch 后抛 BizException(500) |
| 幂等检查 | `SETNX` 失败 | ❌ IdempotencyService 直接抛 |
| 网关 Nonce | `setIfAbsent` 失败 | ❌ SignVerifyGlobalFilter 无降级，Reactive 超时可能导致连接挂起 |
| 排行榜 ZSet | 全部 ZSet 操作失败 | ❌ LeaderboardServiceImpl 直接抛 |

### 当前缺失的降级

```java
// StockService.deduct() — 无降级
// 建议：catch RedisException → 读 MySQL 库存兜底 → 返回降级结果
// 面试话术："Redis 不可用时走 DB 扣库存，能力降到 1/100，但不完全不可用"

// SignVerifyGlobalFilter — Nonce SETNX 失败无降级
// 建议：Redis 超时时跳过 Nonce，只验 timestamp + sign（设计文档已提"
// 此方案，但代码未实现）
```

### 当前有几处是好的

- **登录 Redis 写入失败**：UserService.login() catch Exception → BizException(500)，用户可重试 ✅
- **Refresh Redis 失败**：finally 中 delete lock key，防止死锁 ✅

## 二、MySQL 挂了

### 影响范围

| 功能 | 影响 | 降级 |
|---|---|---|
| 注册/登录 | 无法查用户 | ❌ |
| 查询个人信息 | `findById` 抛 DataAccessException | ❌ |
| 开播/关播 | `LiveRoomRepository` 操作失败 | ❌ |
| 秒杀订单写入 | Consumer 中 `createOrder` 抛异常 | ⚠️ catch 后 ack.acknowledge()，消息丢失 |
| 超时取消扫描 | `findByStatusAndCreatedAtBefore` 抛异常 | ⚠️ 下次扫描重试 |
| 排行榜快照 | `snapshotRepo.save()` 抛异常 | ✅ catch 后 log.warn，其他 key 继续 |

### 最严重问题：Kafka Consumer 中 INSERT 失败

```java
// SeckillOrderConsumer.java L73-76
catch (Exception e) {
    log.error("订单消费异常", e);
    ack.acknowledge();  // ⚠️ MySQL 挂了也 ack，消息丢失！
}
```

**修复：** MySQL 异常不 ack，让 Kafka 重试。区分可重试异常（DB 连接失败）和不可重试异常（唯一索引冲突）。

## 四、Dubbo RPC 调用失败

### 逐个调用分析

| 调用方 | 被调方 | 失败处理 |
|---|---|---|
| UserService.kickDevice | WsPushService.kickDevice | ❌ 无 catch，异常直接抛 |
| LiveWebSocket.handleGift | LeaderboardService.addScore | ✅ VT 异步 + catch，不影响主流程 |
| LiveRoomController.start | UserDubboApi.getById | ❌ 无 catch，开播失败 |
| SeckillPushGrpcService | (gRPC,不是 Dubbo) | ✅ Consumer catch，不影响订单创建 |

### 需要修复

**UserService.kickDevice：** WsPushService 不可用时抛异常，踢设备接口 500。应该 catch 后返回部分成功：
```java
// 当前：Dubbo 调不通直接炸
wsPushService.kickDevice(userId, deviceId);
// 建议：catch + log.warn，Redis 已删设备，WS 推送降级
```

**LiveRoomController.start：** `userServiceClient.getNickname(userId)` 失败时开播报错。应降级：
```java
// 当前：Dubbo 调不通 → 开播失败
String anchorName = userServiceClient.getNickname(userId);
// 已有 fallback：UserServiceClient 中 catch 后返回 "user_" + userId ✅
```
UserServiceClient 已有降级——返回默认昵称。✅

## 六、WebSocket 连接断开

### 场景

| 场景 | 当前处理 | 缺失 |
|---|---|---|
| 客户端网络断开 | onClose 触发 → remove session | ⚠️ 如果 TCP 半开，onClose 不触发 |
| 服务端主动 kick | KICK 消息 → 3s 后 close | ✅ |
| 关播时用户该被踢 | 未广播 ROOM_CLOSED | ❌ 缺失功能 |
| 秒杀结果推送时用户离线 | gRPC 返回 delivered=false | ✅ |

### 幽灵连接问题

心跳扫描未实现（之前的 HeartbeatScanner 被用户回退了）。TCP 半开连接会导致 session 永远不释放。

```
          ┌──────────┐

          └────┬─────┘
               │ HTTP

    ▼          ▼          ▼

└───────────────┘  (送礼加分)
```

| 通信 | 方向 | 失败降级 |
|---|---|---|
| Gateway → * | HTTP | Gateway 本身无状态，下游挂了返回 502 |
| User → WS (Dubbo) | 踢人 | ❌ 未降级 |
| WS → Leaderboard (Dubbo) | 加分 | ✅ async catch |
| Seckill → WS (gRPC) | 推送 | ✅ catch |
| WS → User (Dubbo) | 查昵称 | ✅ fallback "user_xxx" |
