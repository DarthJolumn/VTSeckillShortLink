# 数据一致性设计（v0.2 新增）

## 分层一致性模型

```
Redis Lua ──── 强一致 ──── 单线程原子执行, 超卖不可接受
    │
    ▼ (成功)
Kafka ──────── 最终一致 ──── 异步削峰, 订单 50ms 延迟可接受
    │
    ▼
Consumer ───── 最终一致 ──── INSERT + gRPC 推送
    │
    ▼
DB 唯一索引 ── 强一致 ──── uk_activity_user 物理防重
```

## Redis Lua 原子性

- Redis 单线程执行 Lua 脚本，整个脚本不被中断
- DECR 返回 ≥0 → 扣成功；<0 → 库存不足
- 同一脚本内 SETEX ordered key（24h TTL），防重复

## Kafka 异步削峰

- Lua 扣成功 → Controller 发 Kafka → 返回 "ok"
- Consumer 收到消息 → VT 执行 INSERT + gRPC 推送
- 优点：不阻塞主流程，削峰
- 风险：Kafka 挂了 → 降级为同步下单（待实现）

## 乐观锁并发控制

- `t_seckill_order.version` 字段 + JPA `@Version`
- 超时取消：`SET status=2 WHERE status=0 AND version=?`
- 用户取消：同上
- 两者并发 → 只有一个 CAS 成功 → 只有一个执行回补库存

## MySQL 隔离级别

使用默认 **RR（可重复读）+ ROW 行格式**。

不升级 Serializable 的理由：
- 秒杀的并发安全不靠隔离级别
- Redis 原子性解决超卖
- DB 唯一索引解决重复
- 乐观锁 version 解决并发取消
- RR 够用，Serializable 会大幅降低并发度
