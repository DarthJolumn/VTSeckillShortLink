# gRPC + Dubbo 双通道设计（v0.2 新增）

> v0.1 决策清单 §4 写了"不选 gRPC"。v0.2 利用 Boot 4.1 内置 gRPC 自动配置，
> 不替换 Dubbo，而是互补——Dubbo 做主通道，gRPC 做秒杀推送专用通道。

## 通道分工

| 调用 | 协议 | 原因 |
|---|---|---|
| UserDubboApi.getById (查昵称) | Dubbo | 简单查询, 服务治理 |
| WsPushService.kickUser (踢人) | Dubbo | 管理操作 |
| LeaderboardService.addScore (加分) | Dubbo | 低频事件 |
| **SeckillPush.PushResult (秒杀推送)** | **gRPC** | 低延迟 + Boot 4.1 新能力展示 |

## Proto 定义

```protobuf
// seckill-push.proto
service SeckillPush {
  rpc PushResult (SeckillPushRequest) returns (SeckillPushResponse);
}
message SeckillPushRequest { int64 user_id = 1; string order_no = 2; bool success = 3; string message = 4; int64 timestamp = 5; }
message SeckillPushResponse { bool delivered = 1; string reason = 2; }
```

## 实现位置

| 端 | 文件 | 技术 |
|---|---|---|
| Server | `websocket/grpc/SeckillPushGrpcService.java` | `@GrpcService` + `StreamObserver` |
| Client | `seckill/config/GrpcClientConfig.java` | `ManagedChannelBuilder` → BlockingStub |
| 端口 | websocket:9090 | `spring.grpc.server.port` |

## 降级

gRPC 调用失败时 Consumer 不崩溃，记录 warn 日志。后续可加 Dubbo WsPushService.push 作为 fallback。
