# 运维部署

> 环境搭建、Docker Compose、端口规划、多节点 HA。

---

## 一、环境要求

| 组件 | 版本 | 说明 |
|------|------|------|
| OS | CentOS 10 | VM：8GB RAM / 4 vCPU / 100GB SSD |
| JDK | Java 21 | 所有业务服务运行环境 |
| Docker | 24+ | 容器运行时 |
| Docker Compose | 2.x | 容器编排 |
| IDE | IntelliJ IDEA | 仅用于开发调试（Windows 宿主机） |

### VM 资源分配

```
宿主机（Windows 10/11）
  └── VMware Workstation
        └── CentOS 10 VM（8GB / 4vCPU / 100GB）
              ├── MySQL（Docker）          :3306
              ├── Redis（Docker）           :6379
              ├── Nacos（Docker）           :8848 :9848
              ├── Kafka（Docker, KRaft）    :9092
              ├── Zipkin（Docker）          :9411（按需启动）
              │
Windows 宿主机运行：
              ├── Gateway-1                :8080
              ├── Gateway-2                :8085
              ├── User-1                   :8081
              ├── Seckill-1                :8082
              ├── WebSocket-1              :8083
              ├── Leaderboard-1            :8084
```

所有中间件跑在 VM 上，业务服务跑在 Windows 宿主机上，通过 VM 的 IP 访问中间件。

## 二、端口规划

### 中间件端口

| 组件 | 端口 | 暴露方式 |
|------|------|---------|
| MySQL | 3306 | VM:3306 → Container:3306 |
| Redis | 6379 | VM:6379 → Container:6379 |
| Nacos | 8848 / 9848 | VM 端口直接映射 |
| Kafka | 9092 | VM:9092 → Container:9092 |
| Zipkin | 9411 | VM:9411（按需启动，默认关闭）|

### 业务服务端口

| 服务 | 实例 1 | 实例 2（HA） | 说明 |
|------|--------|-------------|------|
| Gateway | 8080 | 8085 | WebFlux，双实例 |
| User | 8081 | 8086 | MVC + VT |
| Seckill | 8082 | 8087 | MVC + VT |
| WebSocket | 8083 | 8088 | @ServerEndpoint + VT |
| Leaderboard | 8084 | 8089 | MVC + VT |
| Nacos 客户端 | 9848 | — | Dubbo 注册 + 配置 |

### Nginx 反向代理端口

| 端口 | 上游 | 说明 |
|------|------|------|
| 80 → 8080/8085 | Gateway 集群 | HTTP 入口 |
| 443 → 8080/8085 | Gateway 集群 | HTTPS（可选）|

## 三、Docker Compose

> 中间件全部运行在 VM 上。

```yaml
version: '3.8'
services:
  mysql:
    image: mysql:8.0
    container_name: livemall-mysql
    environment:
      MYSQL_ROOT_PASSWORD: root123
      MYSQL_DATABASE: livemall
    ports:
      - "3306:3306"
    volumes:
      - mysql-data:/var/lib/mysql
      - ../sql/init.sql:/docker-entrypoint-initdb.d/init.sql
    networks:
      - livemall-net

  redis:
    image: redis:7
    container_name: livemall-redis
    ports:
      - "6379:6379"
    volumes:
      - redis-data:/data
    command: redis-server --requirepass redis123
    networks:
      - livemall-net

  nacos:
    image: nacos/nacos-server:v2.3.0
    container_name: livemall-nacos
    environment:
      MODE: standalone
      PREFER_HOST_MODE: hostname
    ports:
      - "8848:8848"
      - "9848:9848"
    networks:
      - livemall-net

  kafka:
    image: bitnami/kafka:3.6
    container_name: livemall-kafka
    environment:
      KAFKA_ENABLE_KRAFT: "yes"
      KAFKA_CFG_PROCESS_ROLES: broker,controller
      KAFKA_CFG_CONTROLLER_LISTENER_NAMES: CONTROLLER
      KAFKA_CFG_NODE_ID: 1
      KAFKA_CFG_CONTROLLER_QUORUM_VOTERS: 1@localhost:9093
      KAFKA_CFG_LISTENERS: PLAINTEXT://:9092,CONTROLLER://:9093
      KAFKA_CFG_ADVERTISED_LISTENERS: PLAINTEXT://192.168.x.x:9092
      KAFKA_CFG_LISTENER_SECURITY_PROTOCOL_MAP: CONTROLLER:PLAINTEXT,PLAINTEXT:PLAINTEXT
      KAFKA_CFG_INTER_BROKER_LISTENER_NAME: PLAINTEXT
    ports:
      - "9092:9092"
    networks:
      - livemall-net

  zipkin:
    image: openzipkin/zipkin:latest
    container_name: livemall-zipkin
    ports:
      - "9411:9411"
    profiles:
      - monitor
    networks:
      - livemall-net

volumes:
  mysql-data:
  redis-data:

networks:
  livemall-net:
    driver: bridge
```

> `KAFKA_CFG_ADVERTISED_LISTENERS` 中的 IP 替换为 VM 的实际 IP。
> **注意**：Windows 宿主机访问 VM 内 Kafka 需确保 `ADVERTISED_LISTENERS` 使用 VM 的桥接 IP（而非 localhost 或 127.0.0.1），否则宿主机 Java 应用连接 Kafka 时 broker 返回的地址不可达导致超时。
> Zipkin 通过 `--profile monitor` 按需启动，平时关闭节省资源。

## 四、Nginx HA 配置

```nginx
upstream gateway_cluster {
    server 192.168.x.x:8080 max_fails=3 fail_timeout=10s;
    server 192.168.x.x:8085 max_fails=3 fail_timeout=10s;
}

server {
    listen 80;
    server_name livemall.local;

    location / {
        proxy_pass http://gateway_cluster;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }

    location /ws/ {
        proxy_pass http://gateway_cluster;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
    }
}
```

> Nginx 安装在 VM 上，192.168.x.x 替换为 VM IP。如果业务服务也在 VM 上跑，对应替换。

## 五、启动顺序

```
Step 1: VM 上启动中间件
  docker compose up -d mysql redis nacos kafka

Step 2: 确认中间件就绪
  docker compose ps
  docker logs <container_name>  # 确认没有启动异常

Step 3: Nacos 配置（首次）
  打开 http://192.168.x.x:8848/nacos
  创建 namespace: livemall
  → 后续服务启动后自动注册

Step 4: Windows 宿主机启动业务服务
  # 先启动 common 模块（父 pom install）
  mvn clean install -pl livemall-common -DskipTests

  # 再启动各服务（IDEA 或 mvn）
  mvn spring-boot:run -pl livemall-gateway
  mvn spring-boot:run -pl livemall-user
  mvn spring-boot:run -pl livemall-seckill
  mvn spring-boot:run -pl livemall-websocket
  mvn spring-boot:run -pl livemall-leaderboard

Step 5: 健康检查
  curl http://localhost:8080/actuator/health
  curl http://localhost:8081/actuator/health
  ...

Step 6: 启动 Nginx
  nginx -s reload
```

### 多实例启动

每个服务启动第二个实例时，通过 `--server.port` 覆盖端口：

```bash
# Gateway 实例 2
mvn spring-boot:run -pl livemall-gateway -Dspring-boot.run.arguments="--server.port=8085"

# User 实例 2
mvn spring-boot:run -pl livemall-user -Dspring-boot.run.arguments="--server.port=8086"
```

## 六、健康检查

所有服务暴露 Actuator 端点：

```yaml
management:
  endpoints:
    web:
      exposure:
        include: health,metrics,prometheus
  endpoint:
    health:
      show-details: always
```

| 端点 | 用途 |
|------|------|
| `/actuator/health` | Nginx / Docker 健康检查 |
| `/actuator/metrics` | JVM / QPS / 延迟指标 |
| `/actuator/prometheus` | Prometheus 抓取（可选）|

## 七、应用配置模板

> 关键配置项，每个服务的 application.yml 需要根据环境修改。

### 通用配置

```yaml
spring:
  application:
    name: livemall-{service}
  threads:
    virtual:
      enabled: true  # 启用虚拟线程

dubbo:
  application:
    name: livemall-{service}
  registry:
    address: nacos://192.168.x.x:8848
  protocol:
    name: dubbo
    port: -1  # 随机端口
  provider:
    executor: virtual  # 虚拟线程执行
```

### 数据源配置

```yaml
spring:
  datasource:
    url: jdbc:mysql://192.168.x.x:3306/livemall?useUnicode=true&characterEncoding=utf-8
    username: root
    password: root123
    hikari:
      maximum-pool-size: 20
      # VT 下每个请求一个线程，但 DB 连接是稀缺资源。
      # 20 个连接足以覆盖实际并发 DB 操作（Kafka 削峰后 TPS ~500）。
      # 面试必答：VT 数 >> 连接池数，但实际阻塞在 DB IO 的 VT 不超过连接池上限。
      minimum-idle: 5
      connection-timeout: 3000
```

### Redis 配置

```yaml
spring:
  data:
    redis:
      host: 192.168.x.x
      port: 6379
      password: redis123
      database: 0
      lettuce:
        pool:
          max-active: 16
```

### Kafka 配置

```yaml
spring:
  kafka:
    bootstrap-servers: 192.168.x.x:9092
    producer:
      key-serializer: org.apache.kafka.common.serialization.StringSerializer
      value-serializer: org.springframework.kafka.support.serializer.JsonSerializer
    consumer:
      key-deserializer: org.apache.kafka.common.serialization.StringDeserializer
      value-deserializer: org.springframework.kafka.support.serializer.JsonDeserializer
      auto-offset-reset: latest
```

## 八、构建与部署脚本

```dockerfile
# 多阶段构建
FROM maven:3-eclipse-temurin-21 AS builder
WORKDIR /app
COPY pom.xml .
RUN mvn dependency:go-offline -B
COPY src ./src
RUN mvn package -DskipTests

FROM eclipse-temurin:21-jre
WORKDIR /app
COPY --from=builder /app/target/*.jar app.jar
EXPOSE 8080
ENTRYPOINT ["java", "-jar", "app.jar"]
```

```bash
# 全量构建脚本
#!/bin/bash
set -e

echo "=== Building LiveMall ==="

# 1. 构建 common 模块
mvn clean install -pl livemall-common -DskipTests

# 2. 构建各服务
for service in livemall-gateway livemall-user livemall-seckill livemall-websocket livemall-leaderboard; do
    echo "Building $service..."
    mvn package -pl $service -DskipTests
done

echo "=== Build Complete ==="
```
