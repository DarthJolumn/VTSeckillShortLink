# 匿名观看 + 按需登录设计 v1

> 从"全站需登录"改为"B站式匿名观看 + 按需登录"，重构整个鉴权体系。第一版：核心流程落地。第二版：扩展方向与优化。

---

## 一、设计目标

| 目标 | 现状 | 改后 |
|------|------|------|
| 首页 | 未登录 → 重定向 /login | 直接展示直播间广场 |
| 直播间 | 未登录 → 重定向 /login | 匿名 WS 连接，看弹幕/礼物/排行榜 |
| 发弹幕 | 仅登录用户 | 点击 → 弹出登录弹窗 → 成功后继续发送 |
| 送礼物 | 仅登录用户 | 同上 |
| 秒杀下单 | 仅登录用户 | 同上 |
| 开播/关播 | 仅主播/管理员 | 不受影响（本来就要登录） |
| 用户中心 | 仅登录用户 | 同上 |

核心思想：**读操作公开，写操作按需认证**。

## 二、三级鉴权模型

### 2.1 权限层级

```
            ┌──────────────────────────────────────────┐
            │              PUBLIC（匿名）               │
            │  无需 Token，任何人可访问                   │
            │  GET /live/room/*  GET /leaderboard/*     │
            │  ws://.../ws/live/{roomId}（不收不发）      │
            └────────────────┬─────────────────────────┘
                             │ 携带有效 JWT
            ┌────────────────▼─────────────────────────┐
            │              AUTH（已登录）                │
            │  需有效 JWT，不限角色                      │
            │  POST /live/barrage  POST /live/gift     │
            │  POST /seckill/order  GET /user/profile  │
            └────────────────┬─────────────────────────┘
                             │ role ∈ {ANCHOR, ADMIN}
            ┌────────────────▼─────────────────────────┐
            │           ROLE（主播/管理员）               │
            │  需特定角色                                │
            │  PUT /live/room/{id}/start               │
            │  PUT /live/room/{id}/stop                │
            │  POST /seckill/activity（创建活动）         │
            └────────────────┬─────────────────────────┘
                             │ role == ADMIN
            ┌────────────────▼─────────────────────────┐
            │           ADMIN（管理员）                   │
            │  PUT /user/ban/{userId}                  │
            │  DELETE /seckill/activity/{id}            │
            └──────────────────────────────────────────┘
```

### 2.2 层级标识

```java
// livemall-common/constant/ApiPermission.java
public enum ApiPermission {
    PUBLIC,   // 不需要 Token
    AUTH,     // 需要有效 JWT（任意角色）
    ANCHOR,   // role ∈ {2, 3}
    ADMIN     // role == 3
}
```

### 2.3 对应注解

```java
@Target(ElementType.METHOD)
@Retention(RetentionPolicy.RUNTIME)
public @interface PublicApi {}

@Target(ElementType.METHOD)
@Retention(RetentionPolicy.RUNTIME)
public @interface RequireAuth {}

@Target(ElementType.METHOD)
@Retention(RetentionPolicy.RUNTIME)
public @interface RequireRole {
    RoleEnum[] value();
}
```

**设计模式**：策略模式——`AuthInterceptor` 根据方法上的注解类型选择不同校验策略（跳过 / 验 JWT / 验 JWT+角色）。

## 三、角色与用户上下文

### 3.1 RoleEnum（唯一角色定义点）

```java
// livemall-common/constant/RoleEnum.java
public enum RoleEnum {
    AUDIENCE(1, "观众"),
    ANCHOR(2, "主播"),
    ADMIN(3, "管理员");

    private final int code;
    private final String label;

    public static RoleEnum fromCode(int code) {
        for (RoleEnum r : values()) {
            if (r.code == code) return r;
        }
        throw new BizException(400, "无效角色码: " + code);
    }

    public boolean isAnchorOrAbove() {
        return this == ANCHOR || this == ADMIN;
    }

    public boolean isAdmin() {
        return this == ADMIN;
    }
}
```

### 3.2 UserContext（ScopedValue，替代 ThreadLocal）

```java
// livemall-common/context/UserContext.java
public final class UserContext {
    public static final ScopedValue<Long> USER_ID = ScopedValue.newInstance();
    public static final ScopedValue<Integer> ROLE = ScopedValue.newInstance();
    public static final ScopedValue<String> DEVICE_ID = ScopedValue.newInstance();

    // 便捷方法：在 ScopedValue 作用域内获取当前用户
    public static Long currentUserId() {
        return USER_ID.isBound() ? USER_ID.get() : null;
    }

    public static Integer currentRole() {
        return ROLE.isBound() ? ROLE.get() : null;
    }

    public static boolean isAnonymous() {
        return !USER_ID.isBound();
    }
}
```

**设计模式**：ScopedValue 是 Java 21 为 Virtual Threads 提供的 ThreadLocal 替代方案。在 VT 模型下，ThreadLocal 会导致 VT pinning（承载线程被绑定），ScopedValue 通过 `where().run()` 的不可变快照模型避免此问题。

### 3.3 上下文传递链路

```
Gateway (WebFlux)
  → JwtAuthGlobalFilter 解 JWT
  → 写入 exchange.attributes: userId, role
  → 转发前写入 Header: X-User-Id, X-User-Role

下游 MVC 服务
  → UserContextInterceptor (HandlerInterceptor)
  → preHandle() 从 @RequestHeader 提取
  → ScopedValue.where(USER_ID, userId)
              .where(ROLE, role)
              .run(() -> chain.proceed())
  → Controller / Service 中通过 UserContext.currentUserId() 获取
```

**为什么不在 Gateway 直接用 ScopedValue**：WebFlux 响应式链路中 EventLoop 线程会切换，ScopedValue 绑定在当前线程，切换后丢失。因此 Gateway 用 `exchange.getAttributes()` 存储，转成 Header 传给下游 MVC 服务后，在同步 VT 模型中用 ScopedValue。

## 四、Gateway 鉴权重构

### 4.1 当前问题

```java
// 当前 JwtAuthGlobalFilter — 白名单极小，其余全部拦
WHITE_LIST = ["/auth/login", "/auth/register", "/auth/refresh",
              "/auth/test-token", "/actuator/health"]
// 后果：/ws/**、/live/room/* 全部被 401，匿名观看无法实现
```

### 4.2 新白名单设计

```yaml
# application.yml
gateway:
  auth:
    # 完全公开：不验 JWT，不注入 X-User-Id
    public-paths:
      - /auth/login
      - /auth/register
      - /auth/refresh
      - /actuator/health
      - /ws/**                          # WS 握手，token 在 query param

    # 仅 GET 公开：GET 放行，其他 method 需 JWT
    public-get-paths:
      - /live/room/*                    # GET 查直播间信息，PUT 需认证
      - /leaderboard/**                 # GET 查排行榜，POST 需认证（未来）

    # 其余路径：需 JWT，无 Token → 401
```

### 4.3 JwtAuthGlobalFilter 新逻辑

```
请求进入 (Order=-5)

1. 路径在 public-paths 中？
   → 放行（Header 中无 X-User-Id，下游服务 UserContext 为 null）
   → 结束

2. 路径在 public-get-paths 中 且 method == GET ？
   → 放行（同上）
   → 结束

3. 提取 Authorization: Bearer <token>
   → 无 Token？→ 401
   → 有 Token？
       → JwtUtil.parse() 验签
       → 失败 → 401
       → 成功 → 注入 X-User-Id, X-User-Role → 放行

4. SignVerifyGlobalFilter (Order=-10) 先执行
   → 签名通过 → signPassed=true → JwtAuthGlobalFilter 跳过
```

### 4.4 伪代码

```java
@Component
public class JwtAuthGlobalFilter implements GlobalFilter, Ordered {

    private final List<String> publicPaths;       // 从配置读取
    private final List<String> publicGetPaths;    // 从配置读取

    @Override
    public Mono<Void> filter(ServerWebExchange exchange, GatewayFilterChain chain) {
        String path = exchange.getRequest().getURI().getPath();

        // 1. 完全公开路径 → 放行
        if (matchAny(publicPaths, path)) {
            return chain.filter(exchange);
        }

        // 2. GET 公开路径 → 放行
        HttpMethod method = exchange.getRequest().getMethod();
        if (method == HttpMethod.GET && matchAny(publicGetPaths, path)) {
            return chain.filter(exchange);
        }

        // 3. 签名已通过 → 放行
        if (Boolean.TRUE.equals(exchange.getAttribute("signPassed"))) {
            return chain.filter(exchange);
        }

        // 4. 其余路径需 JWT
        String token = extractToken(exchange.getRequest());
        if (token == null) {
            return unauthorized(exchange, "请先登录");
        }

        try {
            Claims claims = jwtUtil.parse(token);
            Long userId = Long.parseLong(claims.getSubject());
            Integer role = claims.get("role", Integer.class);

            ServerHttpRequest mutated = exchange.getRequest().mutate()
                .header("X-User-Id", userId.toString())
                .header("X-User-Role", role.toString())
                .build();

            exchange.getAttributes().put("userId", userId);
            exchange.getAttributes().put("role", role);

            return chain.filter(exchange.mutate().request(mutated).build());
        } catch (Exception e) {
            return unauthorized(exchange, "Token 无效或已过期");
        }
    }

    @Override
    public int getOrder() { return -5; }
}
```

### 4.5 路径匹配支持 Ant 风格

```java
private boolean matchAny(List<String> patterns, String path) {
    return patterns.stream().anyMatch(p ->
        new AntPathMatcher().match(p, path));
}
```

## 五、WebSocket 混合鉴权

### 5.1 连接模型变化

```
当前设计：
  ws://host:8083/ws/live/{roomId}?token=<AccessToken>
  @OnOpen 中验 JWT → 失败 → 断连（匿名用户直接被拒）

改后设计：
  ws://host:8083/ws/live/{roomId}[?token=<AccessToken>]
  token 可选：
    - 无 token → 匿名连接（只收不发）
    - 有 token → @OnOpen 验 JWT → 认证连接（收发）
    - 匿名连接可在运行时通过 AUTH 消息升级
```

### 5.2 WsSession 模型

```java
public class WsSession {
    private Session session;
    private Long roomId;
    private Long userId;       // null = 匿名
    private Integer role;      // null = 匿名
    private String sessionId;
    private LocalDateTime connectedAt;

    public boolean isAnonymous() { return userId == null; }
    public boolean canSend() { return !isAnonymous(); }
    public boolean canManage() {
        return role != null && (role == 2 || role == 3);
    }
}
```

### 5.3 @OnOpen 新逻辑

```
1. 从 query string 提取 token（可选）
   → 无 token → 创建匿名 WsSession（userId=null, role=null）
   → 有 token → JwtUtil.parse() → 提取 userId, role

2. 鉴权结果：
   → 匿名：加入房间（可接收广播消息）
   → 已登录 + role 有效：完整权限
   → Token 无效：返回 AUTH_FAILED 消息（不断连，降级为匿名）

3. 短时间窗口内允许升级
   → 连接后 30s 内发送 { type: "AUTH", data: { token: "..." } }
   → 服务端验 JWT → 升级 WsSession.userId / role
   → 回复 { type: "AUTH_OK", data: { userId, role } }
   → 超过 30s 仍有登录需求 → 发 AUTH 消息依然有效（无窗口限制，设计简化）
```

### 5.4 上行消息过滤

```java
@OnMessage
public void onMessage(Session session, String message) {
    WsSession ws = sessionManager.get(session);
    WsMessage msg = parseMessage(message);

    // 匿名用户只能发 PING 和 AUTH
    if (ws.isAnonymous()) {
        if ("PING".equals(msg.getType())) {
            sendPong(session);
            return;
        }
        if ("AUTH".equals(msg.getType())) {
            handleAuth(ws, msg);  // 尝试升级
            return;
        }
        // 其余消息：忽略（或回复 NEED_AUTH）
        sendError(session, "请先登录");
        return;
    }

    // 已认证用户：正常处理
    dispatch(ws, msg);
}
```

### 5.5 Gateway `/ws/**` 路由调整

Gateway 路由 `/ws/**` 加入 `public-paths`，不验 JWT（token 在 WS 握手 query param 中，由 `@OnOpen` 自己验）。前端 dev server 的 WebSocket 代理也要确保不拦截。

## 六、业务服务层鉴权

### 6.1 AuthInterceptor

所有非 Gateway 的 MVC 服务注册此拦截器：

```java
@Component
public class AuthInterceptor implements HandlerInterceptor {

    @Override
    public boolean preHandle(HttpServletRequest request,
                             HttpServletResponse response,
                             Object handler) {
        if (!(handler instanceof HandlerMethod hm)) return true;

        // 1. 提取 Header
        String userIdStr = request.getHeader("X-User-Id");
        String roleStr = request.getHeader("X-User-Role");

        Long userId = userIdStr != null ? Long.parseLong(userIdStr) : null;
        Integer role = roleStr != null ? Integer.parseInt(roleStr) : null;

        // 2. 获取方法上的注解
        PublicApi publicApi = hm.getMethodAnnotation(PublicApi.class);
        RequireAuth requireAuth = hm.getMethodAnnotation(RequireAuth.class);
        RequireRole requireRole = hm.getMethodAnnotation(RequireRole.class);

        // 3. 按注解选择策略
        if (publicApi != null) {
            // 公开接口：不校验，UserContext 可为 null
            ScopedValue.where(UserContext.USER_ID, userId)
                       .where(UserContext.ROLE, role)
                       .run(() -> true);  // 有 Header 就传，没有就 null
            return true;
        }

        if (requireAuth != null) {
            // 需登录
            if (userId == null) {
                sendUnauthorized(response, "请先登录");
                return false;
            }
        }

        if (requireRole != null) {
            // 需特定角色
            if (userId == null) {
                sendUnauthorized(response, "请先登录");
                return false;
            }
            RoleEnum userRole = RoleEnum.fromCode(role);
            if (!Arrays.asList(requireRole.value()).contains(userRole)) {
                sendForbidden(response, "权限不足");
                return false;
            }
        }

        // 4. 设置 ScopedValue 上下文
        ScopedValue.where(UserContext.USER_ID, userId)
                   .where(UserContext.ROLE, role)
                   .run(() -> true);  // 实际在 postHandle 中用
        return true;
    }
}
```

**设计模式**：注解 + 拦截器 = 策略模式。`@PublicApi` → 跳过策略，`@RequireAuth` → 验 JWT 策略，`@RequireRole` → 验 JWT+角色策略。新增权限层级只需加注解，不改拦截器。

## 七、前端改造

### 7.1 路由守卫重写

```js
// router/guards.js — 新逻辑

const AUTH_REQUIRED_PATHS = ['/profile', '/orders', '/devices', '/anchor', '/admin']
const ANCHOR_PATHS = ['/anchor']
const ADMIN_PATHS = ['/admin']

export function installGuards(router) {
  router.beforeEach((to, from, next) => {
    const userStore = useUserStore()
    document.title = to.meta.title ? `${to.meta.title} · LiveMall` : 'LiveMall · 直播秒杀'

    // 1. 公共页直接放行
    if (to.meta.public) {
      if (userStore.isLogin && (to.name === 'login' || to.name === 'register')) {
        return next({ path: HOME_BY_ROLE[userStore.role] || '/' })
      }
      return next()
    }

    // 2. 直播相关页面 — 匿名可看
    if (to.name === 'home' || to.name === 'live-room') {
      return next()
    }

    // 3. 需登录页面 — 未登录弹出登录弹窗，不跳转
    const needsAuth = AUTH_REQUIRED_PATHS.some(p => to.path.startsWith(p))
    if (needsAuth && !userStore.isLogin) {
      // 弹出登录弹窗（全局事件），保留目标路由，登录成功后继续导航
      showLoginModal({ onSuccess: () => next() })
      return
    }

    // 4. 角色校验
    if (ANCHOR_PATHS.some(p => to.path.startsWith(p))
        && !userStore.isAnchor && !userStore.isAdmin) {
      return next('/403')
    }
    if (ADMIN_PATHS.some(p => to.path.startsWith(p)) && !userStore.isAdmin) {
      return next('/403')
    }

    next()
  })
}
```

  function showLoginModal({ onSuccess } = {}) {

## 十、面试亮点

1. **三级鉴权模型**：PUBLIC / AUTH / ROLE 三层分离，Gateway 做粗粒度，业务层注解做细粒度，展示架构分层思想
2. **WebSocket 匿名连接 + 运行时升级**：先匿名进直播间（零摩擦），登录后同一条 WS 连接升级权限——不常见，好讲
3. **ScopedValue 上下文传递**：Gateway（WebFlux）→ Header → 业务层（MVC+VT）→ ScopedValue，展示对 Java 21 的理解
4. **注解驱动的策略模式**：新权限层级只需加注解 + 枚举值，不改拦截器代码，展示 OCP（开闭原则）
5. **前端登录弹窗 + 操作重试链**：未登录点秒杀 → 弹窗 → 登录 → 自动重发秒杀，对标真实产品体验
