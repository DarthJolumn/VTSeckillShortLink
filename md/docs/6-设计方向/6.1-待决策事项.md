## 一、RPC 三协议对比压测

### 问题

当前选了 Dubbo，但面试官必定会问"Feign、Dubbo、gRPC 你到底比过没有？差多少？"没有数据支撑的回答都是理论。

### 方案

| 协议 | 序列化 | 传输 | 实现方式 |
|------|--------|------|----------|
| Feign | JSON | HTTP/1.1 | Spring Cloud OpenFeign |
| Dubbo | Hessian2 | TCP（Dubbo 协议） | dubbo-spring-boot-starter |
| gRPC | Protobuf | HTTP/2 | LogNet grpc-spring-boot-starter |

### 测试设计

```
被测接口：UserService.getById(id)
数据源：真实 Redis + MySQL
并发级别：100 / 1,000 / 5,000 / 10,000 QPS
采集指标：吞吐量、P50/P99/P999 延迟、CPU/内存、错误率
工具：JMeter（初步）→ 后续对比 Gatling / k6
```

### 需要探索的

- gRPC Spring Boot starter 选型（LogNet vs 手动集成）
- benchmark 模块结构（独立模块 vs 调试端点）
- 同一接口暴露三种协议如何统一 Dubbo API

**状态：** `pending`

**关联文档：** `3.1-技术决策清单.md` §4 RPC

## 二、数据库高可用

### 问题

当前 MySQL 单实例。面试官必定追问：单实例挂了怎么办？量大了怎么办？

### 决策树

```
MySQL 单实例
  ├── 加主从（MGR / 半同步复制）
  │     ├── 只做读扩展（读写分离）
  │     └── 做高可用（MHA / Orchestrator 故障切换）
  └── 加分库分表（ShardingSphere）
        ├── 按 user_id 分片
        ├── 按 order_id 分片
        └── 一致性哈希 vs 取模
```

### 需要探索的

- MySQL 8.x vs PostgreSQL 16 对比（面试官也可能问"为什么不用 PG"）
- 主从复制延迟怎么解决（半同步 vs 异步，GTID vs binlog position）
- 分库分表后跨分片查询怎么办（订单列表跨分片怎么查）
- ShardingSphere proxy 模式 vs jdbc 模式优劣

**状态：** `pending`

**关联文档：** `3.1-技术决策清单.md` §6 数据库

## 三、缓存一致性方案 ✅ 已决定

**决策：** 最终一致性（写 DB → Kafka → 消费后刷缓存）

秒杀场景接受秒级不一致——库存扣减走 Redis Lua（实时精确），订单状态变更走最终一致。用户已通过 WebSocket 实时推送知道秒杀结果，缓存中的订单列表差一秒不影响体验。详细对比见 `1.2-技术选型分析.md` §5 缓存。

**状态：** `decided`

## 四、服务注册中心 ✅ 已决定

**决策：** Nacos（单实例，注册中心 + 配置中心合并）

| 维度 | Nacos | Zookeeper |
|------|-------|-----------|
| CAP | CP + AP 可切换 | CP 强一致 |
| 健康检查 | 客户端心跳 + 服务端探测 | Session 超时 |
| 配置中心 | ✅ 原生支持 | ❌ 需额外搭建 |
| 运维复杂度 | 中 | 中 |

选 Nacos 的核心原因：一个进程同时解决注册 + 配置，Dubbo 原生支持，少一个部署单元。面试扩展：CAP 模式——注册用 AP（优先可用性），配置用 CP（优先一致性）。

**状态：** `decided`

**关联文档：** `3.1-技术决策清单.md` §七 服务治理 / `5.1-运维部署.md` §三 Docker Compose

## 五、配置中心 ✅ 已决定

**决策：** Nacos Config（和注册中心共用同一实例）

默认用本地 yml（简单，无需额外依赖），通过 Nacos Config 支持热更新（Sentinel 规则、排行榜权重配置）。面试时可说"生产环境全部走 Nacos Config"。

**状态：** `decided`

## 七、认证 Redis 是否独立实例

### 问题

认证（Refresh Token）和业务缓存共用 Redis，是否应该独立？

| 方案 | 优点 | 缺点 |
|------|------|------|
| 合并（当前） | 少一个容器，运维简单 | 认证 IO 和秒杀 Lua 抢同一事件循环 |
| 独立 | 流量隔离，互不影响 | 多一个容器，多一套密码/监控 |

**当前选择：** 合并，`select 1` 隔离。面试时可提出"独立实例优化方案"。

**状态：** `decided`（已定合并，独立作为可优化点）
