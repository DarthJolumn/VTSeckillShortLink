## 模块 1: common（公共模块）

### F1. JwtUtil — JWT HS256 生成/解析
- [ ] 🔲 `jwtUtil.generate(userId, role, 900)` 返回三段式 token，中间段 base64 可解码
- [ ] 🔲 `jwtUtil.parse(token)` 正确提取 userId 和 role
- [ ] 🔲 过期 token parse 抛异常
- [ ] 🔲 密钥不匹配 token parse 抛异常

### F2. IdempotencyService — Redis SETNX 幂等
- [ ] 🔲 首次 `tryAcquire("key")` 返回 true，Redis 存 key 5min
- [ ] 🔲 重复 `tryAcquire("key")` 返回 false
- [ ] 🔲 `set()` 写入 JSON 对象，`get()` 返回反序列化对象，读取不到返回 null

### F3. SnowflakeIdGenerator — 分布式 ID
- [ ] 🔲 单线程连续生成 100 个 ID 不重复
- [ ] 🔲 10 线程并发各生成 1000 个 ID，无重复
- [ ] 🔲 时钟回拨 ≤30ms 自旋恢复，不抛异常
- [ ] 🔲 workerId > 1023 抛异常

### F4. SensitiveFilter — DFA 敏感词过滤
- [ ] 🔲 "正常弹幕" 不变
- [ ] 🔲 "傻逼" → "**"
- [ ] 🔲 "操你妈" → "***"
- [ ] 🔲 null / 空字符串 返回原值不崩溃
- [ ] 🔲 `reload()` 热更新词库后立即生效

### F5. GlobalExceptionHandler — 全局异常处理
- [ ] 🔲 `BizException(400, "msg")` → `{"code":400,"message":"msg"}`
- [ ] 🔲 `MissingRequestHeaderException` → `{"code":400}`

### F6. ScopedValue UserContext — 用户上下文
- [ ] 🔲 `USER_ID.isBound()` 在 `ScopedValue.where()` 内为 true
- [ ] 🔲 `currentUserId()` 未绑定时返回 null

## 模块 2: user（用户服务）

### F7. 注册
```bash
curl -X POST http://localhost:8080/auth/register \
  -H "Content-Type: application/json" \
  -d '{"username":"test01","password":"Test1234"}'
```
- [ ] 🔲 正常注册 → `{"code":200}`
- [ ] 🔲 重复注册同一 username → `{"code":1012,"message":"用户名已被注册"}`
- [ ] 🔲 username 长度 < 4 → 400
- [ ] 🔲 password 长度 < 8 → 400
- [ ] 🔲 带 X-Idempotency-Key 重复请求 → 幂等返回 200，DB 只一条数据

### F8. 登录
```bash
curl -X POST http://localhost:8080/auth/login \
  -H "Content-Type: application/json" \
  -H "X-Device-Id: device-001" \
  -d '{"username":"test01","password":"Test1234"}'
```
- [ ] 🔲 正确密码 → `{"accessToken":"...","refreshToken":"rft_...","expiresIn":900}`
- [ ] 🔲 accessToken 可 JWT 解码含 userId + role + exp
- [ ] 🔲 错误密码 → `{"code":1011,"message":"用户名或密码错误"}`
- [ ] 🔲 缺少 X-Device-Id → 400
- [ ] 🔲 封禁用户登录 → `{"code":1006}`

### F9. Refresh Token
```bash
curl -X POST http://localhost:8080/auth/refresh \
  -H "Content-Type: application/json" \
  -d '{"refreshToken":"rft_..."}'
```
- [ ] 🔲 合法 refreshToken → 返回新 accessToken + 新 refreshToken
- [ ] 🔲 旧 refreshToken 已删除（Rotation）
- [ ] 🔲 旧 refreshToken 再次 refresh → `{"code":1013,"message":"登录已过期"}`
- [ ] 🔲 并发 5 个线程同时 refresh → 只签发一次新 token（合并请求）

### F10. 退出登录
```bash
curl -X POST http://localhost:8080/auth/logout \
  -H "Content-Type: application/json" \
  -d '{"refreshToken":"rft_..."}'
```
- [ ] 🔲 退出后 Redis 中 refresh key 已删除
- [ ] 🔲 退出后用旧 refreshToken 刷新 → 1013
- [ ] 🔲 空 refreshToken → 400

### F11. 设备管理
```bash
curl http://localhost:8080/user/devices \
  -H "Authorization: Bearer {token}"
```
- [ ] 🔲 返回已登录设备列表
- [ ] 🔲 踢设备 → Redis SREM 对应 deviceId + Dubbo 通知 WS

## 模块 3: websocket（直播长连接）

### F12. 连接 + 认证
```
wscat -c "ws://localhost:8083/ws/live/1?token={accessToken}"
```
- [ ] 🔲 带合法 token → 收到 `{"type":"CONNECTED","data":{"anonymous":false,"displayName":"user_1","online":N}}`
- [ ] 🔲 不带 token → 收到 `{"type":"CONNECTED","data":{"anonymous":true}}`，发 BARRAGE → `{"type":"NEED_AUTH"}`
- [ ] 🔲 错误 token → 收到 `{"type":"AUTH_FAILED"}`
- [ ] 🔲 AUTH 消息升级 → 收到 `{"type":"AUTH_OK"}`
- [ ] 🔲 连接超上限（maxSessions）→ 关闭连接

### F13. 弹幕（VT 并行广播）
```
发送: {"type":"BARRAGE","data":{"content":"冲冲冲"}}
```
- [ ] 🔲 房间内所有连接的客户端收到 BARRAGE 广播
- [ ] 🔲 广播消息含 userId + nickname + content + timestamp
- [ ] 🔲 1000 人房间广播延迟（最后一个收到的时间 - 发送时间）< 100ms

### F14. 送礼 + 排行榜联动
```
发送: {"type":"GIFT","data":{"giftId":3,"quantity":2}}
```
- [ ] 🔲 房间内所有客户端收到 GIFT 广播
- [ ] 🔲 排行榜 `GET /leaderboard/top?activityId=1&n=10` 中该用户分数增加
- [ ] 🔲 送礼后 ZINCRBY 值正确（GIFT = 5.0 基础分）

### F15. 心跳
```
发送: {"type":"PING"}
```
- [ ] 🔲 回复 `{"type":"PONG"}`
- [ ] 🔲 60s 无心跳 → 连接关闭

### F16. 踢人
- [ ] 🔲 管理员踢用户 → WS 收到 `{"type":"KICK","data":{"reason":"违规操作"}}`
- [ ] 🔲 收到 KICK 后 3s 连接关闭

### F17. 直播房间管理
```bash
curl -X POST http://localhost:8080/live/room/start \
  -H "Authorization: Bearer {token}" \
  -H "X-User-Id: 1" -H "X-User-Role: 2" \
  -H "Content-Type: application/json" \
  -d '{"title":"测试直播","category":"digital","coverColor":"linear-gradient(...)"}'
```
- [ ] 🔲 开播 → 返回房间信息，status=1
- [ ] 🔲 同主播再开播 → 幂等返回已有房间
- [ ] 🔲 关播 → status=0，在线人数定格
- [ ] 🔲 GET /live/rooms → 返回直播中房间列表 + 在线人数
- [ ] 🔲 GET /live/room/{roomId} → 返回单个房间信息

### F18. gRPC SeckillPush
- [ ] 🔲 秒杀下单成功后，WebSocket 收到 `{"type":"SEC_KILL_RESULT","data":{...}}`
- [ ] 🔲 用户离线时 gRPC 返回 delivered=false

## 模块 4: seckill（秒杀）

### F19. Redis Lua 库存扣减
- [ ] 🔲 首次扣减 → 200
- [ ] 🔲 同一用户再次扣减 → -1（重复下单）
- [ ] 🔲 库存扣完后再扣 → -2（库存不足）
- [ ] 🔲 分片路由正确：userId % shardCount 计算的分片被 DECR
- [ ] 🔲 回补库存：refund 后库存 +1，ordered 标记删除

### F20. 活动管理
```bash
# 创建
curl -X POST http://localhost:8080/seckill/activity \
  -H "Content-Type: application/json" \
  -d '{"title":"测试活动","productId":1,"seckillPrice":99.00,"originalPrice":199.00,"totalStock":100,"startTime":"2026-07-19T10:00:00","endTime":"2026-07-19T22:00:00"}'

# 上架
curl -X PUT http://localhost:8080/seckill/activity/1/status \
  -H "Content-Type: application/json" \
  -d '{"status":1}'
```
- [ ] 🔲 创建成功 → 返回活动对象，status=0
- [ ] 🔲 上架 → status=1
- [ ] 🔲 开始时间 > 结束时间 → 400
- [ ] 🔲 库存 ≤ 0 → 400
- [ ] 🔲 GET /seckill/activity/{id} → 返回活动详情
- [ ] 🔲 GET /seckill/activity/list → 返回进行中的活动列表

### F21. 抢购下单
```bash
curl -X POST http://localhost:8080/seckill/order \
  -H "Authorization: Bearer {token}" \
  -H "Content-Type: application/json" \
  -H "X-User-Id: 1" \
  -d '{"activityId":1}'
```
- [ ] 🔲 活动进行中 + 有库存 → `{"data":"ok"}`
- [ ] 🔲 活动待开始 → `{"code":400,"message":"活动未在进行中"}`
- [ ] 🔲 活动已结束 → 同上
- [ ] 🔲 活动不存在 → 404
- [ ] 🔲 重复下单 → `{"code":1010,"message":"已参与过该活动"}`
- [ ] 🔲 库存不足 → `{"code":1009,"message":"库存不足"}`

### F22. Kafka 异步订单 + gRPC 推送
- [ ] 🔲 Lua 扣减成功后 Kafka 消息发送到 `seckill-order` topic
- [ ] 🔲 Consumer 消费后 INSERT t_seckill_order
- [ ] 🔲 gRPC 推送后 WS 客户端收到 SEC_KILL_RESULT
- [ ] 🔲 gRPC 不通时 Consumer 不崩溃，日志有 warn

### F23. 超时取消
- [ ] 🔲 15 分钟未支付 → @Scheduled 扫描 → status 改为 2
- [ ] 🔲 超时取消后库存回补 +1
- [ ] 🔲 超时取消和用户取消并发 → 乐观锁不出现重复回补

### F26. JWT 鉴权 + 签名 + 限流

- [ ] 🔲 带过期 token → 401
