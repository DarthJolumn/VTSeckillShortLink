# 数据库设计

> 7 张表，覆盖用户、直播、秒杀、排行全链路。不属于同一数据库，按业务域逻辑组织。

---

## 一、用户域

### 1.1 t_user — 用户表

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT PK AUTO | 用户 ID |
| username | VARCHAR(50) UNIQUE NOT NULL | 用户名 |
| password | VARCHAR(255) NOT NULL | BCrypt 加密 |
| nickname | VARCHAR(50) | 昵称（可选）|
| phone | VARCHAR(20) | 手机号（可选）|
| avatar | VARCHAR(255) | 头像 URL |
| role | TINYINT DEFAULT 1 | 1:观众 2:主播 3:管理员 |
| status | TINYINT DEFAULT 1 | 0:封禁 1:正常 |
| created_at | DATETIME | |
| updated_at | DATETIME | ON UPDATE CURRENT_TIMESTAMP |

```sql
CREATE TABLE t_user (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    username VARCHAR(50) NOT NULL UNIQUE,
    password VARCHAR(255) NOT NULL,
    nickname VARCHAR(50),
    phone VARCHAR(20),
    avatar VARCHAR(255),
    role TINYINT DEFAULT 1,
    status TINYINT DEFAULT 1,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    INDEX idx_phone (phone)
);
```

**索引说明：**

| 索引 | 目的 |
|------|------|
| PRIMARY KEY (id) | 主键，聚簇索引 |
| UNIQUE (username) | 登录查询，唯一约束 |
| idx_phone | 手机号登录查询 |

## 二、直播域

### 2.1 t_live_room — 直播间表

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT PK AUTO | 房间 ID |
| anchor_id | BIGINT NOT NULL | 主播用户 ID |
| title | VARCHAR(200) | 直播间标题 |
| status | TINYINT DEFAULT 0 | 0:离线 1:直播中 |
| start_time | DATETIME | 开播时间 |
| end_time | DATETIME | 关播时间 |
| max_viewers | INT DEFAULT 10000 | 最大观众数 |
| created_at | DATETIME | |
| updated_at | DATETIME | |

```sql
CREATE TABLE t_live_room (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    anchor_id BIGINT NOT NULL,
    title VARCHAR(200),
    status TINYINT DEFAULT 0,
    start_time DATETIME,
    end_time DATETIME,
    max_viewers INT DEFAULT 10000,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    INDEX idx_anchor_status (anchor_id, status),
    INDEX idx_status_start (status, start_time)
);
```

**索引说明：**

| 索引 | 目的 |
|------|------|
| idx_anchor_status | 主播查询自己的直播间 |
| idx_status_start | 首页展示直播中房间，按开播时间排序 |

### 2.2 t_barrage — 弹幕记录表

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT PK AUTO | |
| room_id | BIGINT NOT NULL | 直播间 ID |
| user_id | BIGINT NOT NULL | 发送者 |
| content | VARCHAR(500) NOT NULL | 弹幕内容（已过滤） |
| created_at | DATETIME | |

```sql
CREATE TABLE t_barrage (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    room_id BIGINT NOT NULL,
    user_id BIGINT NOT NULL,
    content VARCHAR(500) NOT NULL,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    INDEX idx_room_created (room_id, created_at)
);
```

**索引说明：**

| 索引 | 目的 |
|------|------|
| idx_room_created | 按房间查弹幕历史（回放）|

弹幕实时推送不走 DB，存 MySQL 仅用于历史回放和审核。

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT PK AUTO | |
| room_id | BIGINT NOT NULL | |
| user_id | BIGINT NOT NULL | 送礼者 |
| gift_id | INT NOT NULL | 礼物 ID |
| gift_name | VARCHAR(50) | |
| gift_price | DECIMAL(10,2) | 单价 |
| quantity | INT DEFAULT 1 | 数量 |
| created_at | DATETIME | |

```sql
CREATE TABLE t_gift_log (

    room_id BIGINT NOT NULL,
    user_id BIGINT NOT NULL,
    gift_id INT NOT NULL,
    gift_name VARCHAR(50),
    gift_price DECIMAL(10,2) NOT NULL,
    quantity INT DEFAULT 1,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,

```

**索引说明：**

| 索引 | 目的 |
|------|------|
| idx_room_created | 主播收入统计、礼物榜历史 |

送礼 → Redis ZSet 实时加分 + 异步落库 t_gift_log。

## 三、秒杀域

### 3.1 t_seckill_activity — 秒杀活动表

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT PK AUTO | 活动 ID |
| title | VARCHAR(200) NOT NULL | 活动标题 |
| product_id | BIGINT NOT NULL | 商品 ID |
| seckill_price | DECIMAL(10,2) NOT NULL | 秒杀价 |
| original_price | DECIMAL(10,2) NOT NULL | 原价 |
| total_stock | INT NOT NULL | 总库存 |
| start_time | DATETIME NOT NULL | 开始时间 |
| end_time | DATETIME NOT NULL | 结束时间 |
| status | TINYINT DEFAULT 0 | 0:待开始 1:进行中 2:已结束 3:已取消 |
| created_at | DATETIME | |
| updated_at | DATETIME | |

```sql
CREATE TABLE t_seckill_activity (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    title VARCHAR(200) NOT NULL,
    product_id BIGINT NOT NULL,
    seckill_price DECIMAL(10,2) NOT NULL,
    original_price DECIMAL(10,2) NOT NULL,
    total_stock INT NOT NULL,
    start_time DATETIME NOT NULL,
    end_time DATETIME NOT NULL,
    status TINYINT DEFAULT 0,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    UNIQUE INDEX uk_title_product (title, product_id),
    INDEX idx_status_time (status, start_time)
);
```

**索引说明：**

| 索引 | 目的 |
|------|------|
| uk_title_product | 防止重复创建同一活动的幂等兜底 |
| idx_status_time | 查询进行中的活动、活动列表按时间排序 |

---

### 3.2 t_seckill_order — 秒杀订单表

> **设计说明**：`id`（自增）为物理主键，用于聚簇索引顺序插入；`order_no`（Snowflake）为业务主键，对外暴露。Snowflake 的同一毫秒内 workerId 不同的 ID 会交叉，直接用作 PK 仍可能导致页分裂。用自增 ID 确保聚簇索引严格顺序写入，order_no 通过二级唯一索引保证业务唯一性。

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT PK AUTO | |
| order_no | VARCHAR(50) UNIQUE NOT NULL | 订单号（Snowflake）|
| activity_id | BIGINT NOT NULL | 活动 ID |
| user_id | BIGINT NOT NULL | 用户 ID |
| product_id | BIGINT NOT NULL | 商品 ID |
| seckill_price | DECIMAL(10,2) NOT NULL | 成交价 |
| status | TINYINT DEFAULT 0 | 0:待支付 1:已支付 2:已取消 3:已退款 |
| created_at | DATETIME | |
| paid_at | DATETIME | |
| cancelled_at | DATETIME | |
| version | INT DEFAULT 0 | 乐观锁 |

```sql
CREATE TABLE t_seckill_order (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    order_no VARCHAR(50) NOT NULL UNIQUE,
    activity_id BIGINT NOT NULL,
    user_id BIGINT NOT NULL,
    product_id BIGINT NOT NULL,
    seckill_price DECIMAL(10,2) NOT NULL,
    status TINYINT NOT NULL DEFAULT 0,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    paid_at DATETIME,
    cancelled_at DATETIME,
    version INT DEFAULT 0,
    UNIQUE INDEX uk_activity_user (activity_id, user_id),
    INDEX idx_status_created (status, created_at)
);
```

**索引说明：**

| 索引 | 目的 |
|------|------|
| uk_activity_user | 一人一单（唯一约束 + 查询）|
| idx_status_created | 超时取消扫描（status=0 + created_at < 15min）|
| UNIQUE (order_no) | 订单号唯一 |

## 四、排行域

### 4.1 t_leaderboard_snapshot — 排行快照表

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT PK AUTO | |
| activity_id | BIGINT NOT NULL | 活动 ID |
| user_id | BIGINT NOT NULL | 用户 ID |
| score | DECIMAL(15,2) NOT NULL | 累计分数 |
| rank | INT NOT NULL | 排名 |
| snapshot_time | DATETIME NOT NULL | 快照时间 |
| created_at | DATETIME | |

```sql
CREATE TABLE t_leaderboard_snapshot (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    activity_id BIGINT NOT NULL,
    user_id BIGINT NOT NULL,
    score DECIMAL(15,2) NOT NULL,
    rank INT NOT NULL,
    snapshot_time DATETIME NOT NULL,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    INDEX idx_activity_time (activity_id, snapshot_time),
    INDEX idx_user_activity (user_id, activity_id)
);
```

**索引说明：**

| 索引 | 目的 |
|------|------|
| idx_activity_time | 查某活动某时间点的快照（历史排行）|
| idx_user_activity | 查某用户在活动中的排行变化趋势 |

## 五、表关系总览

```
t_user
  ├── 1:N → t_live_room (anchor_id)
  ├── 1:N → t_barrage (user_id)
  ├── 1:N → t_gift_log (user_id)
  ├── 1:N → t_seckill_order (user_id)
  └── 1:N → t_leaderboard_snapshot (user_id)

t_seckill_activity
  ├── 1:N → t_seckill_order (activity_id)
  └── 1:N → t_leaderboard_snapshot (activity_id)

t_live_room
  ├── 1:N → t_barrage (room_id)
  └── 1:N → t_gift_log (room_id)
```

> 所有外键不加 CONSTRAINT（影响插入性能），仅在业务层保证一致性。

## 六、存储估算

| 表 | 单行大小 | 预估行数 | 预估空间 |
|------|---------|---------|---------|
| t_user | ~500B | 100 万 | 500MB |
| t_live_room | ~300B | 5 万 | 15MB |
| t_barrage | ~600B | 1 亿 | 60GB |
| t_gift_log | ~300B | 5000 万 | 15GB |
| t_seckill_activity | ~300B | 1 万 | 3MB |
| t_seckill_order | ~300B | 5000 万 | 15GB |
| t_leaderboard_snapshot | ~300B | 5000 万 | 15GB |

弹幕表最大（1 亿条约 60GB），可考虑按月分表或归档冷数据，面试时可提出此优化点。
