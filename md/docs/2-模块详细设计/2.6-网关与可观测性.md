# 网关与可观测性（livemall-gateway）

## 架构

Gateway 是唯——个响应式（WebFlux）服务，其余业务服务均用 MVC + VT。Gateway 不碰业务逻辑，只做：

1. 路由转发
2. JWT 鉴权
3. 签名验签
4. 限流
5. 跨域

## Filter 链与执行顺序

```java
@Configuration
public class GatewayConfig {
    
    @Bean
    public SignVerifyGlobalFilter signVerifyGlobalFilter() {
        return new SignVerifyGlobalFilter();
    }
    
    @Bean
    public JwtAuthGlobalFilter jwtAuthGlobalFilter() {
        return new JwtAuthGlobalFilter();
    }
}
```

执行顺序（通过 `@Order` 或 `getOrder()` 控制）：

| Order | Filter | 职责 |
|-------|--------|------|
| -10 | SignVerifyGlobalFilter | 验签 → 通过则放行（跳过 JWT）|
| -5 | JwtAuthGlobalFilter | JWT 鉴权 → 提取 userId/role → ScopedValue 注入 |
| — | Sentinel 限流 | 热点参数限流 |
| — | 路由转发 | 转发到目标服务 |

`/auth/login`、`/auth/register` 需签名验签但不需要 JWT——这两个接口在 JwtAuthGlobalFilter 中走白名单跳过。

## JWT 鉴权

```java
@Component
public class JwtAuthGlobalFilter implements GlobalFilter, Ordered {

    private static final List<String> WHITE_LIST = List.of(
        "/auth/login", "/auth/register", "/actuator/health"
    );

    @Override
    public Mono<Void> filter(ServerWebExchange exchange, GatewayFilterChain chain) {
        String path = exchange.getRequest().getURI().getPath();
        if (isWhiteListed(path)) {
            return chain.filter(exchange);
        }

        String token = extractToken(exchange.getRequest());
        if (token == null) {
            return unauthorized(exchange, "Missing token");
        }

        try {
            Claims claims = JwtUtil.verify(token);
            Long userId = claims.get("userId", Long.class);
            Integer role = claims.get("role", Integer.class);

            // 存入 exchange attributes（不在 WebFlux 中用 ScopedValue）
            exchange.getAttributes().put("userId", userId);
            exchange.getAttributes().put("role", role);
            return chain.filter(exchange);
        } catch (Exception e) {
            return unauthorized(exchange, "Invalid token");
        }
    }

    @Override
    public int getOrder() { return -5; }
}
```

### ScopedValue 传递策略

> ⚠️ **不在 Gateway Filter 中直接用 ScopedValue**。WebFlux 的响应式链路中线程可能切换（Reactor 的 EventLoop 在执行 `chain.filter()` 返回的 `Mono` 时可能换线程），ScopedValue 绑定在当前 Thread 上，切换后丢失。

**本项目做法**：

```
Gateway Filter → exchange.getAttributes() 存 userId/role
             → 转发前 GlobalFilter 将 attributes 写入请求 Header
             → 下游 MVC 服务 @RequestHeader 或拦截器提取
             → 赋值到 ScopedValue（MVC + VT 同步模型，不会跨线程）
```

下游 MVC 服务从 Header 中提取后赋给 ScopedValue——MVC + VT 的同步模型保证一个请求绑定一个虚拟线程，ScopedValue 生命周期与请求一致，不会跨线程丢失。

代码实现详见 `2.1-公共模块.md` §ScopedValue。

## 签名验签

内部签名接口（供移动端/第三方调用，非浏览器）：

> ⚠️ **P0-1 fixed**：Gateway 运行在 WebFlux EventLoop 上，Nonce 的 Redis 调用必须是非阻塞的。原代码使用同步 `RedisTemplate` 会阻塞 EventLoop 线程——当 10w QPS 下 EventLoop 线程被阻塞时请求排队，网关成为瓶颈。改用 `ReactiveRedisTemplate` + `Mono` 链式调用。

```java
@Component
public class SignVerifyGlobalFilter implements GlobalFilter, Ordered {

    private static final long TIME_WINDOW = 5 * 60 * 1000; // ±5min

    @Override
    public Mono<Void> filter(ServerWebExchange exchange, GatewayFilterChain chain) {
        HttpHeaders headers = exchange.getRequest().getHeaders();
        String timestamp = headers.getFirst("X-Timestamp");
        String nonce = headers.getFirst("X-Nonce");
        String sign = headers.getFirst("X-Sign");

        if (timestamp == null || nonce == null || sign == null) {
            return unauthorized(exchange, "Missing signature headers");
        }

        // 1. 时间窗口校验（纯 CPU，EventLoop 无阻塞）
        if (Math.abs(System.currentTimeMillis() - Long.parseLong(timestamp)) > TIME_WINDOW) {
            return unauthorized(exchange, "Timestamp expired");
        }

        // 2. Nonce 防重放——ReactiveRedisTemplate，非阻塞
        String nonceKey = "nonce:" + nonce;
        return reactiveRedisTemplate.opsForValue()
            .setIfAbsent(nonceKey, "1", Duration.ofSeconds(60))
            .flatMap(success -> {
                if (Boolean.FALSE.equals(success)) {
                    return unauthorized(exchange, "Nonce reused");
                }
                // 3. 重算签名（HMAC-SHA256）
                String secret = getSecretByAppKey(headers.getFirst("X-AppKey"));
                String expectedSign = HmacUtil.sha256(timestamp + nonce + secret);
                if (!expectedSign.equals(sign)) {
                    return unauthorized(exchange, "Invalid signature");
                }
                return chain.filter(exchange);
            });
    }

    @Override
    public int getOrder() { return -10; }
}
```

签名验签跳过 JWT——签名请求不需要额外鉴权，签名本身即身份凭证。

## 限流

Sentinel 嵌入模式，通过 `GatewayRuleManager` 加载规则：

```java
@Configuration
public class SentinelConfig {

    @PostConstruct
    public void initGatewayRules() {
        Set<GatewayFlowRule> rules = new HashSet<>();
        
        // 秒杀接口限流：每用户每活动 100 QPS
        rules.add(new GatewayFlowRule("seckill:create")
            .setResourceMode(SentinelGatewayConstants.RESOURCE_MODE_ROUTE_ID)
            .setParamItem(new GatewayParamFlowItem()
                .setParseStrategy(SentinelGatewayConstants.PARAM_PARSE_STRATEGY_URL_PARAM)
                .setFieldName("activityId"))
            .setCount(100)
            .setIntervalSec(1));
        
        // 登录接口限流：每 IP 10 QPS
        rules.add(new GatewayFlowRule("auth:login")
            .setCount(10)
            .setIntervalSec(1));
        
        GatewayRuleManager.loadRules(rules);
    }
}
```

### 嵌入模式多节点注意事项

> ⚠️ Sentinel 嵌入模式各节点独立计数。部署 2 个 Gateway 节点、`count=100` → 实际总限流 = 200 QPS/用户/活动。本项目虽启动双实例做 HA，但开发阶段单实例运行即可避免此问题。生产环境用 Sentinel Dashboard 推全局规则，或 `count` 按节点数均分（`count = 全局阈值 / 节点数`）。

规则也可以从 Nacos 动态拉取，支持运行时修改。本项目先用代码加载，面试时提 Nacos 动态配置。

## 跨域配置

```java
@Bean
public CorsWebFilter corsWebFilter() {
    CorsConfiguration config = new CorsConfiguration();
    config.setAllowCredentials(true);
    // 注意：credentials=true 时不能用 allowedOriginPattern("*")，浏览器会拒绝
    // 本项目 Knife4j 调试走 localhost，生产应改为具体域名
    config.addAllowedOrigin("http://localhost:8080");
    config.addAllowedHeader("*");
    config.addAllowedMethod("*");

    UrlBasedCorsConfigurationSource source = new UrlBasedCorsConfigurationSource();
    source.registerCorsConfiguration("/**", config);
    return new CorsWebFilter(source);
}
```

## 全局异常处理

Gateway 层统一异常：

```java
@Order(-1)
@Component
public class GlobalErrorWebExceptionHandler implements ErrorWebExceptionHandler {

    @Override
    public Mono<Void> handle(ServerWebExchange exchange, Throwable ex) {
        // 统一返回 Result<T> 格式
        Result<?> result = Result.error(500, ex.getMessage());
        exchange.getResponse().setStatusCode(HttpStatus.INTERNAL_SERVER_ERROR);
        return writeResponse(exchange, result);
    }
}
```

## 链路追踪

依赖：

```xml
<dependency>
    <groupId>io.micrometer</groupId>
    <artifactId>micrometer-tracing-bridge-brave</artifactId>
</dependency>
<dependency>
    <groupId>io.zipkin.reporter2</groupId>
    <artifactId>zipkin-reporter-brave</artifactId>
</dependency>
```

配置：

```yaml
management:
  tracing:
    sampling:
      probability: 0.1  # 10% 采样，高并发降低开销
  zipkin:
    tracing:
      endpoint: http://localhost:9411/api/v2/spans
```

采样率 10%：10w QPS → 1w 条 trace，既能看到全貌又不会把 Zipkin 打爆。

Dubbo、Kafka、MySQL 的 span 自动上报，无需额外配置。Zipkin UI 展示：

```
Gateway (5ms) → Dubbo UserService (2ms) → MySQL query (18ms)
```

面试必答：traceId 全链路唯一，spanId 每跳不同，parentId 串联成树。

## 面试追问要点

- 为什么 Gateway 不用 VT？（WebFlux 是响应式，VT 是同步模型，两者哲学冲突）
- JWT 验签性能（HMAC-SHA256 纯 CPU 运算，1 核可验 5w+ TPS）
- 为什么签名也要 Nonce？（防止重放攻击，timestamp + nonce 组合确保一次一签）
- Sentinel 滑动窗口精度（LeapArray 2 个 500ms 窗口，比固定窗口更平滑）
- Gateway 多实例时限流数据共享吗？（嵌入模式各实例独立，总量 = 单机阈值 × 节点数，需要 Dashboard 推全局规则）
