# 秒杀服务（livemall-seckill）

> 内容来源：原设计文档第五章

## 核心流程

### 秒杀下单

```
客户端 → Gateway（验签+鉴权+限流）→ SeckillController
  → checkActivityValid（Caffeine + Redis）
  → checkUserLimit（Redis 预判 + DB 唯一索引）
  → StockService.deduct（Redis Lua 原子扣库存）
  → 成功 → 发 Kafka 消息
  → SeckillOrderConsumer（VT 消费）→ INSERT 订单
  → WebSocket 推送结果给用户
```

### 创建秒杀活动

```
POST /seckill/activity (管理员)
  → X-Idempotency-Key 幂等检查（Redis SETNX，5min TTL）
  → 参数校验（时间合法性、库存 > 0）
  → INSERT t_seckill_activity
  → 返回 ActivityVO
```

> 幂等保证：Redis SETNX 防重复提交，DB `uk_title_product (title, product_id)` 兜底。详见 `3.4.1-创建秒杀活动.md`。

## Redis Lua 库存脚本

```lua
-- KEYS[1] = totalKey (stock:total:{activityId})
-- KEYS[2] = orderedKey (ordered:{activityId}:{userId})
-- ARGV[1] = userId
-- ARGV[2] = shardCount

local ordered = redis.call("GET", KEYS[2])
if ordered then return {code = -1, msg = "重复下单"} end

local shard = tonumber(ARGV[1]) % tonumber(ARGV[2])
local stockKey = "stock:shard:" .. KEYS[1] .. ":" .. shard

local stock = redis.call("DECR", stockKey)
if stock >= 0 then
    redis.call("SETEX", KEYS[2], 86400, "1")
    return {code = 200, msg = "扣减成功"}
end
return {code = -2, msg = "库存不足"}
```

**为什么用 Lua：** 天然原子，支持条件判断，比 MULTI/EXEC 和 SETNX 都好。

**库存分片：** `userId % shardCount` 哈希路由，单 key DECR，无遍历。

分片数计算：Redis 单实例单 key DECR 的 QPS 上限约 8~10w（官方 benchmark），预留 30% 安全余量，公式：

```
shardCount = 预计峰值 QPS / (10w × 0.7)
10w 峰值 → 10w / 7w ≈ 2 片
50w 峰值 → 50w / 7w ≈ 8 片
```

本项目目标 10w QPS（全站，非单活动秒杀），取 **4 片** 为起点，足够覆盖单活动秒杀峰值。过度分片的代价：库存碎片化——某分片卖完时总分片可能还有库存，需回收碎片库存（复杂度与分片数成正比）。4 片是经验值与计算的交叉验证结果。

## 订单状态机

```
PENDING → PAID：支付
PENDING → CANCELLED：超时/用户取消
PAID → REFUNDED：退款
```

超时取消：@Scheduled 每 15s 扫描 + 乐观锁 CAS 回补库存。

## 数据库

```sql
CREATE TABLE t_seckill_activity (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    title VARCHAR(200) NOT NULL,
    product_id BIGINT NOT NULL,
    seckill_price DECIMAL(10,2) NOT NULL,
    original_price DECIMAL(10,2) NOT NULL,
    total_stock INT NOT NULL,
    start_time DATETIME NOT NULL,
    end_time DATETIME NOT NULL,
    status TINYINT DEFAULT 0,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    UNIQUE INDEX uk_title_product (title, product_id),
    INDEX idx_status_time (status, start_time)
);

CREATE TABLE t_seckill_order (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    order_no VARCHAR(50) NOT NULL UNIQUE,
    activity_id BIGINT NOT NULL,
    user_id BIGINT NOT NULL,
    product_id BIGINT NOT NULL,
    seckill_price DECIMAL(10,2) NOT NULL,
    status TINYINT NOT NULL DEFAULT 0,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    paid_at DATETIME,
    cancelled_at DATETIME,
    version INT DEFAULT 0,
    UNIQUE INDEX uk_activity_user (activity_id, user_id),
    INDEX idx_status_created (status, created_at)
);
```

## 降级方案

| 故障场景 | 降级动作 | 用户感知 |
|---------|---------|---------|
| Redis 挂了 | 跳过 Redis，直接查 MySQL + 拒绝写 | 秒杀不可用，活动浏览正常 |
| Kafka 挂了 | 切为同步下单（Redis Lua 扣减后直接 INSERT DB） | 下单变慢但可用 |
| MySQL 挂了 | 读走 Redis 缓存，写操作暂存 Redis 草稿 | 查数据正常，下单稍后再试 |
| 本地缓存过期 | 重新从 Redis 加载 | 无感知 |
| Sentinel 挂了 | 降级为不做限流，Nginx 层兜底 | 无感知（限流暂时失效） |
