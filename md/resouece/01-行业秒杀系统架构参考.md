# 行业秒杀系统架构参考

> 来源：阿里云开发者社区、腾讯云开发者社区、CSDN、博客园等多篇高并发秒杀架构文章总结

---

## 一、主流架构模式对比

### 阿里云社区方案（Redis + Lua + 异步）

```
核心链路：
  客户端 → Nginx/LB → Gateway → Seckill Service
                                      ↓
                               Redis Lua 预扣库存
                                      ↓
                                Kafka/RocketMQ 异步下单
                                      ↓
                               MySQL 持久化订单
```

**QPS 数据：**
- 传统 DB 扣减：120 QPS
- Redis + Lua：5,600 QPS
- Redis 分段 + Lua：8,200 QPS

**关键结论：** Redis + Lua 方案比传统方案吞吐提升 46 倍，响应时间从 450ms 降至 18ms

### 腾讯云社区方案（三级缓存 + 流量漏斗）

```
接入层：CDN + Nginx（过滤 80% 无效请求）
   ↓
应用层：Spring Boot + Sentinel（限流 + 熔断）
   ↓
数据层：Caffeine（L1）→ Redis（L2）→ MySQL（L3）
```

**核心原则：** 能缓存不数据库，能异步不同步，能降级不崩溃

### 博客园 10w QPS 方案

```
技术栈：
  前端：Vue3 + CDN
  网关：Nginx + OpenResty
  应用：Spring Boot + Dubbo
  缓存：Redis Cluster
  MQ：RocketMQ
  数据库：MySQL 8.0 分库分表
  限流：Sentinel
  监控：Prometheus + Grafana

库存扣减黄金法则：
  Redis 预扣 → MQ 异步 → DB 最终一致性
```

## 二、库存扣减方案对比

| 方案 | QPS | P99延迟 | 超卖率 | 复杂度 |
|------|-----|---------|--------|--------|
| DB 乐观锁 UPDATE stock>0 | 500 | 200ms | 0% | 低 |
| Redis DECR 预扣 | 3,000 | 50ms | 需补偿 | 中 |
| Redis + Lua 原子脚本 | 5,600 | 18ms | 0% | 中 |
| Redis 分段库存 + Lua | 8,200 | 12ms | 0% | 高 |
| Redis + MQ 异步 | 10,000+ | 5ms | 最终一致 | 高 |

## 三、防作弊体系参考

```
第一层：前端
  按钮置灰 + 验证码 + 请求频率限制

第二层：网关
  单 IP 限流（每 IP 每秒 3 次）
  设备指纹识别
  User-Agent 合法性校验

第三层：应用
  用户行为分析（从进入页面到点击抢购 < 1s 标记为疑似脚本）
  黑名单机制（历史作弊用户 ID/IP/设备指纹）
  同一用户 1 分钟内点击抢购 > 10 次触发滑块验证

第四层：数据
  唯一索引防重复下单
  库存扣减幂等
```

## 四、业内推荐的面试回答结构

```
1. 先说业务特点：瞬时高并发、库存有限、一致性要求高
2. 说架构分层：接入层 → 应用层 → 数据层
3. 说核心难点：
   - 怎么防超卖（Redis Lua）
   - 怎么扛高并发（多级缓存 + 异步 + 限流）
   - 怎么防作弊（限流 + 验证码 + 黑名单）
   - 怎么保一致（最终一致性 + 定时补偿）
4. 说量化结果：压测 QPS、延迟、超卖率
5. 说优化空间：知道更好的方案但当前没做
```
