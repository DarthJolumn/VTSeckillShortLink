## 一、慕课网秒杀课程的技术演进路径

```
单体 MVC 版本：
  SpringBoot + MyBatis + MySQL + Redis
  实现基本秒杀逻辑
  QPS: 约 500

加入 MQ 异步版本：
  + RabbitMQ 削峰
  客户端轮询查询秒杀结果
  QPS: 约 1,000

加入 WebSocket 版本：
  + WebSocket 主动推送秒杀结果
  去掉客户端轮询
  QPS: 稳定在 1,000+

加入多级缓存 + 限流版本：
  + Caffeine 本地缓存
  + Redis 缓存预热
  + 限流防刷
  QPS: 约 2,000
```

**课程定价：** ¥366（18 小时）
**项目特点：** 从单体 → 逐步优化 → 高并发，非常适合面试时讲"演进过程"

## 二、黑马商城微服务项目的架构

```
hmall (黑马商城)
├── hm-gateway          # Spring Cloud Gateway 网关
├── hm-user             # 用户服务
├── hm-item             # 商品服务
├── hm-cart             # 购物车服务
├── hm-trade            # 交易/订单服务
├── hm-pay              # 支付服务
├── hm-api              # Feign 接口定义
└── hm-common           # 公共模块

技术栈：
  Spring Boot + Spring Cloud + MyBatis-Plus
  Nacos（注册中心 + 配置中心）
  OpenFeign（远程调用）
  Sentinel（限流熔断）
  RabbitMQ（消息队列）
  Redis（缓存）
  Elasticsearch（搜索）
  Docker（部署）
```

**课程特点：** 从单体到微服务的完整演进，每个中间件都是因为"单体架构遇到了什么问题"才引入的。

## 三、牛客网汇总的秒杀面试高频问题

面试官最常问的 10 个问题：

| # | 问题 | 期望回答要点 |
|---|------|------------|
| 1 | 如何处理超卖 | Redis Lua 原子扣减 + 唯一索引兜底 |
| 2 | 如何解决重复下单 | `(activity_id, user_id)` 唯一索引 |
| 3 | 缓存击穿怎么解决 | 永不过期 + 互斥锁重建 |
| 4 | 缓存和 DB 一致性怎么保证 | 先更新 DB → 后删缓存（Cache Aside） |
| 5 | 限流怎么做 | Sentinel 热点限流 + 本地令牌桶兜底 |
| 6 | 消息队列挂了怎么办 | 降级到同步下单 / 拒绝服务 |
| 7 | 库存扣减 Redis 挂了怎么办 | 本地缓存兜底 + 拒绝写请求 |
| 8 | 性能数据（QPS/延迟） | 必须有自己的压测数据 |
| 9 | 有没有考虑分库分表 | 当前量级不够，但了解 ShardingSphere |
| 10 | 项目有什么优化空间 | 说出 2~3 个可优化点 + 为什么没做 |

## 四、一个优秀的秒杀项目简历描述模板

> **项目名称：** LiveMall 直播电商秒杀系统
>
> **技术栈：** Spring Boot 3.x + JDK 21 虚拟线程 + Redis + Kafka + Sentinel + WebSocket
>
> **项目描述：**
> - 设计并实现了一套基于微服务架构的直播秒杀系统，核心服务包括 Gateway 网关、秒杀服务、WebSocket 长连接服务、排行榜服务
> - 基于 Redis Lua 原子脚本实现库存扣减与库存分片热点打散，单节点支撑 5,000+ QPS，0 超卖
> - 使用 JDK 21 虚拟线程重构 Kafka 消费与 WebSocket 连接处理，连接数提升至 5 万+
> - 实现 WebSocket 长连接网关与会话路由，支持心跳检测、断线重连、跨节点消息推送
> - 基于 Redis ZSet 实现实时排行榜，多维度加权计算，5 分钟定时快照到 MySQL
> - 集成 Sentinel 热点限流 + Caffeine 多级缓存，解决缓存穿透、击穿、雪崩问题
> - 采用 Micrometer Tracing + Zipkin 实现全链路追踪，Prometheus + Grafana 监控
>
> **个人职责：** 系统架构设计、核心代码实现、全链路压测
