# 全模块安全与漏洞审计报告

## P0 - 严重

### 1. CORS 配置：`allowCredentials + allowOriginPattern(*)` 冲突

**位置**：`CorsConfig.java:16`

```java
config.setAllowCredentials(true);
config.addAllowedOriginPattern("*"); // 开发环境允许任意 origin
```

`allowCredentials(true)` 与 `allowedOriginPattern("*")` 同时存在会导致浏览器拒绝请求（Chrome/Firefox 强制同源策略）。生产环境若部署到任意域名，会被任意网站通过携带 Cookie 的方式调用所有接口。

**修复**：明确列出允许的源，或在生产配置中限制。

---

### 2. HMAC 签名比较非恒定时间（Timing Attack）

**位置**：`SignVerifyGlobalFilter.java:95`、`HmacUtil.java`

```java
String expectedSign = HmacUtil.sha256(timestamp + nonce, secret);
if (!expectedSign.equals(sign)) {  // 非恒定时间比较
```

`String.equals()` 比较到不同字符就立即返回，攻击者可通过响应时间逐字节推断签名。HMAC-SHA256 的安全前提是恒定时间比较。

**修复**：使用 `MessageDigest.isEqual()` 进行恒定时间字节比较。

---

### 3. `IdempotencyService.tryAcquire()` 存在 TOCTOU 竞争条件

**位置**：`IdempotencyService.java:28-30`

```java
return Boolean.TRUE.equals(
    redisTemplate.opsForValue()
        .setIfAbsent(PREFIX + key, "1", 5, TimeUnit.MINUTES));
```

`setIfAbsent` 是原子操作，这其实是安全的。但如果后续 `get/set` 操作用作分布式锁语义时，需要注意：`setIfAbsent` 返回 true 时持有锁，但崩溃后 5min TTL 内锁不会释放。对于幂等检查当前是可接受的。

**结论**：当前用法安全，但命名 `tryAcquire` 容易误解为锁机制，建议重命名。

---

### 4. GlobalExceptionHandler 不适用于 WebFlux 网关

**位置**：`GlobalExceptionHandler.java:16`

```java
@ConditionalOnWebApplication(type = ConditionalOnWebApplication.Type.SERVLET)
```

网关是 WebFlux 应用，这个条件不会匹配。所有 `@ExceptionHandler` 方法在网关中**不会生效**，网关的异常会返回默认的 Whitelabel Error Page 或空响应，而不是统一的 JSON 错误格式。

**修复**：网关需要独立的 `@ControllerAdvice` 或继承 `AbstractErrorWebExceptionHandler`。

---

### 5. `decrementStockIfAvailable` 不使用乐观锁

**位置**：`SeckillActivityRepository.java:24-27`

```sql
UPDATE t_seckill_activity SET total_stock = total_stock - 1 
WHERE id = :activityId AND total_stock > 0
```

方法名包含 "Version" 但 SQL 没有更新或检查 `version` 列。`@Version` 注解只对 JPA `save()` 生效，对原生 SQL 无效。

如果并发扣减，两个事务都可能通过 `total_stock > 0` 检查同时成功，导致超卖。

---

### 6. DBQueueStrategy 发送到 `seckill-order-queue` 无消费者

**位置**：`DBQueueStrategy.java:44`

订单发往 `seckill-order-queue` topic，但 `SeckillOrderConsumer` 只监听 `seckill-order`。DBQueue 模式的订单**永远不会被持久化**。

---

### 7. WebSocket 无消息大小限制

**位置**：`LiveWebSocket.java`

`@ServerEndpoint` 默认最大消息大小 64KB（取决于容器实现）。超大消息可能导致内存溢出或 DoS。没有应用层消息大小校验。

---

### 8. SeckillMode 枚举注释错误

**位置**：`SeckillMode.java:5`

```java
REDIS_SYNC,   // Redis Lua + Kafka.get() 同步等待
```

`RedisSyncStrategy` 实际是直接 `orderRepo.save()` 同步落库，**没有 Kafka 参与**。注释与实际代码不符。

---

## P1 - 高危

### 9. Gateway 缺少 Sentinel Dashboard 连接配置

**位置**：`vtsl-gateway` 的 `application.yml`

Gateway 的 yaml 没有 `spring.cloud.sentinel.transport.dashboard` 配置，无法向 Sentinel Dashboard 注册。结果：网关层限流规则无法管理。

**修复**：`application.yml` 添加 sentinel config。

---

### 10. 签名验签模块 AppSecret 硬编码在内存且无轮换

**位置**：`SignVerifyGlobalFilter.java:35`

```java
private final Map<String, String> appSecrets = new ConcurrentHashMap<>();
// 从配置解析：appKey1:secret1,appKey2:secret2
```

密钥存在内存 Map 中，无自动轮换机制，无加密存储。重启后凭配置加载。

---

### 11. 前端生成 `orderNo` - 可预测订单号

**位置**：`SeckillController.java` 的 `placeOrder` 接收前端传来的 `orderNo`

如果前端生成的订单号可预测（如基于时间戳），攻击者可枚举订单号进行重放攻击。

---

### 12. `HmacUtil` 异常时泄露堆栈信息

**位置**：`HmacUtil.java:20-22`

```java
} catch (NoSuchAlgorithmException | InvalidKeyException e) {
    throw new RuntimeException("HMAC-SHA256 签名失败", e);
}
```

运行时异常带堆栈信息暴露给调用方，在生产环境是信息泄露风险。

---

### 13. WebSocket 连接参数通过 URL 传递 token

**位置**：`LiveWebSocket.java:34`

```java
String token = extractParamFromQuery(query, "token");
```

URL 查询参数会被：
- 浏览器历史记录保存
- 代理服务器/负载均衡器日志记录
- Referer 头泄露到第三方站点

JWT token 通过 URL 传递存在泄露风险。应该使用 WebSocket 子协议或 header。

---

### 14. `DBQueueStrategy.deductStock()` 的 `@Transactional` 与方法命名

**位置**：`DBQueueStrategy.java:30-33`

```java
@Transactional
@Override
public int deductStock(Long activityId, Long userId) {
```

方法名是 `deductStock`，`@Transactional` 会开启事务。但 DBQueue 模式的设计意图是"乐观锁扣减 + Kafka 异步落库"，这里的事务在 `deductStock` 调用时开启，方法结束时立即提交。Kafka 发送在 `createOrder` 中，不在同一个事务里。这意味着 `deductStock` 成功但 Kafka 失败时，库存已经扣减但订单未落库，需要对账补偿。

---

## P2 - 中危

### 15. 短链接返回 `originalUrl` 可能泄露内部链接

**位置**：`ShortLinkController.java:70`

```java
return Result.ok(Map.of("shortCode", shortCode, "originalUrl", originalUrl));
```

任何人都能创建短链并解析获取原始 URL。如果短链包含内部系统链接或支付链接，会造成信息泄露。

---

### 16. WebSocket 通过 URL 传递 token 的问题（可记录到代理日志）

见 P1 #13。

---

### 17. `SeckillOrderConsumer.retryCounts` 内存 Map 丢失

**位置**：`SeckillOrderConsumer.java:29`

```java
private final ConcurrentHashMap<String, AtomicInteger> retryCounts = new ConcurrentHashMap<>();
```

重启后重试计数归零。如果 Kafka  broker 短暂不可用，消费者重启后可能重试次数不准确。

### 18. ActivityBloomFilter 死代码

**位置**：`SeckillService.java:27`

`bloomFilter` 字段已注入但 `placeOrder()` 中 BF 逻辑在 P2-6 修复中注释掉。死代码会增加维护负担。

---

### 19. Gateway Gateway `public-get-paths` 的 Ant `*` 不匹配多级路径

**位置**：`application.yml:111`

```yaml
public-get-paths: '${GATEWAY_PUBLIC_GET_PATHS:/live/rooms,/live/room/*,/leaderboard/**,/s/*}'
```

`/live/room/*` 是单级匹配，不会匹配 `/live/rooms`。如果需要公开多级路径，应使用 `**`。

---

### 20. `SeckillActivity.id` 使用 `IDENTITY` 自增

**位置**：`SeckillActivity.java:13`

```java
@Id
@GeneratedValue(strategy = GenerationType.IDENTITY)
private Long id;
```

自增 ID 对外暴露可被枚举。创建活动时分配的 ID 可被预测，对于需要隐蔽性的运营活动存在风险。

## P3 - 低危

### 21. `Result.error()` 默认 code=500 涵盖所有异常

**位置**：`Result.java`

```java
public static <T> Result<T> error(String message) {
    return new Result<>(ERROR_CODE, message, null);
}
```

所有未分类异常统一返回 HTTP 500 + code=500，前端无法区分业务错误和系统错误。

---

### 22. 缺失 `@Max`/`@Min` 注解校验

`SeckillActivity.totalStock`、`seckillPrice` 等字段仅靠 `@Column(nullable = false)` 数据库约束，缺少 `@Min(0)` 等 JSR-380 注解。前端可绕过限制发送负数。

---

### 23. `ObjectMapper` 在 `handleGift` 中未限制反序列化类型

**位置**：`LiveWebSocket.java:87`

```java
msg = mapper.readValue(message, Map.class);
```

虽然 `Map.class` 相对安全，但 WebSocket 端点使用的全局 `ObjectMapper` 如果没有配置 `@JsonTypeInfo` 限制，可能在某些版本中存在反序列化攻击面。

---

### 24. `User` 实体密码字段无标注

**位置**：`User.java:17`

```java
private String password;
```

虽然 MyBatis-Plus 不会自动忽略，但 DTO 层没有密码字段，理论上不会泄露。但实体上缺少 `@JsonIgnore` 注解作为额外保护。

---

### 25. `ShortLinkController` CORS 不安全

见 `CorsConfig.java`，但短链接服务本身也是公开 API，返回 `originalUrl` 存在泄露风险。

## Nacos 连接问题

Gateway 启动失败是因为 `NACOS_ADDR` 环境变量可能指向 `192.168.147.132:8858`（Sentinel 端口），而非正确的 `192.168.147.132:8848`（Nacos 端口）。检查并修正。

```powershell
# 虚拟机中检查
echo $NACOS_ADDR

# 应该输出 192.168.147.132:8848，不是 192.168.147.132:8858
```
