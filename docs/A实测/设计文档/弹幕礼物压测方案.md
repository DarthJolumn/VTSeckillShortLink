# 弹幕 & 礼物压测方案

## 一、接口分析

### 弹幕（Barrage）
- **协议**：WebSocket
- **连接**：`ws://localhost:8080/ws/live/{roomId}?deviceId=xxx&token=xxx`
- **消息格式**：`{"type": "BARRAGE", "data": {"content": "你好"}}`
- **后端处理**：`LiveWebSocket.handleBarrage()` → 广播给同房间所有用户

### 礼物（Gift）
- **协议**：WebSocket
- **消息格式**：`{"type": "GIFT", "data": {"giftId": 1, "quantity": 1}}`
- **后端处理**：
  1. `LiveWebSocket.handleGift()` → 广播给同房间
  2. Dubbo 调用 `leaderboardService.addScore(roomId, userId, "GIFT")` → Redis ZSet 加分
- **礼物目录**：

| giftId | 名称 | 价格 | 权重 |
|---|---|---|---|
| 1 | 玫瑰 | 1 | 0.3 |
| 2 | 啤酒 | 5 | 0.5 |
| 3 | 火箭 | 100 | 1.0 |
| 4 | 皇冠 | 520 | 2.0 |

### 点赞（Like）
- **协议**：WebSocket（或 REST）
- **消息格式**：`{"type": "LIKE", "data": {}}`（如果有的话）
- **或者**：直接调用 `leaderboardService.addScore(roomId, userId, "LIKE")`

## 二、JMeter WebSocket 测试方案

### 方案 A：JMeter WebSocket 插件（推荐）

#### 安装插件
1. 下载 [JMeter WebSocket Samplers](https://github.com/johannesthyssen/jmeter-websocket-samplers)
2. 放入 `apache-jmeter-5.6.3/lib/ext/`
3. 重启 JMeter

## 三、数据准备

### 1. ws-users.csv（WebSocket 用户）

```csv
userId,token,deviceId,roomId
1001,eyJhbGciOiJIUzI1NiJ9...,device-1001,1
1002,eyJhbGciOiJIUzI1NiJ9...,device-1002,1
...
```

**生成方式**：
```bash
# 用 curl 批量登录，输出到 CSV
for i in {1..1000}; do
  username="jmuser$i"
  password="password123"
  deviceId="device-$i"
  
  token=$(curl -s -X POST http://localhost:8080/auth/login \
    -H "Content-Type: application/json" \
    -H "X-Device-Id: $deviceId" \
    -d "{\"username\":\"$username\",\"password\":\"$password\"}" \
    | jq -r '.data.accessToken')
  
  echo "$i,$token,$deviceId,1" >> ws-users.csv
done
```

### 2. barrage-contents.csv（弹幕内容）

```csv
barrage_content
666
主播牛逼
冲冲冲
来了来了
哈哈哈
好厉害
求关注
双击 666
```

**建议**：准备 50-100 条不同的弹幕内容，避免重复

### 3. gift-ids.csv（礼物 ID）

```csv

1
1
1
2

```

**权重分配**：玫瑰(1) 占 50%，啤酒(2) 占 25%，火箭(3) 占 15%，皇冠(4) 占 10%

## 五、JMeter 配置要点

### 1. WebSocket Open Connection 配置

```
Server Name: localhost
Port: 8080
Protocol: ws
Path: /ws/live/${roomId}?deviceId=${deviceId}&token=${token}
Connection Timeout: 5000
```

### 2. WebSocket Single Write Sampler 配置

**弹幕**：
```
Message: {"type":"BARRAGE","data":{"content":"${barrage_content}"}}
```

**礼物**：
```
Message: {"type":"GIFT","data":{"giftId":${gift_id},"quantity":1}}
```

### 3. Timer 配置

```
Constant Timer: 1000ms (每秒 1 次)
```

或者用 **Uniform Random Timer** 模拟真实用户：
```
Minimum Delay: 500ms
Maximum Delay: 1500ms
```

### 4. 监听器

- **Aggregate Report**：查看 QPS、p99、错误率
- **View Results Tree**：调试时查看 WS 消息

## 六、监控指标

### WebSocket 服务（PID 19632）

```bash
jstat -gcutil 19632 2000
```

重点关注：
- **YGC 次数/时长**：WebSocket 连接多，对象分配频繁
- **Old%**：WsSession 对象是否及时回收
- **Metaspace%**：类加载是否过多

### 排行榜服务（PID 22124）

```bash
jstat -gcutil 22124 2000
```

重点关注：
- **Redis 连接池**：礼物加分会频繁调用 Redis ZSet

### 任务管理器

- **CPU**：WebSocket 广播是 CPU 密集
- **内存**：每个 WS 连接占用 ~10KB，3000 连接 ≈ 30MB

## 七、执行顺序

```
1. 造数据：
   - 生成 ws-users.csv（批量登录获取 token）
   - 生成 barrage-contents.csv（50 条弹幕内容）
   - 生成 gift-ids.csv（按权重分配礼物 ID）

2. 单接口测试：
   - 纯弹幕：100 → 500 → 2000 用户
   - 纯礼物：50 → 200 → 1000 用户
   - 记录每个阶段的 QPS 和 GC

3. 混合测试：
   - 3A → 3B → 3C → 3D 逐步加压
   - 观察 WebSocket 广播延迟
   - 观察排行榜 Redis 写入延迟

4. 调参：
   - 如果 YGC 频繁 → 加大 WebSocket 服务堆
   - 如果广播延迟高 → 调整 BROADCAST_SEM 信号量
   - 如果 Redis 慢 → 检查网络延迟
```

## 八、注意事项

1. **WebSocket 连接数限制**：`ws.max-sessions=200000`（已配置）
2. **JMeter WebSocket 插件**：需要额外安装，或者用 REST API 替代
3. **弹幕内容去重**：后端有 500ms 去重逻辑，避免重复内容
4. **礼物广播风暴**：1000 用户同时送礼，每个用户收到 999 条广播 = 999,000 条消息
5. **Redis 网络延迟**：Redis 在远程机器 (132)，每次礼物加分有 ~1-2ms 延迟
