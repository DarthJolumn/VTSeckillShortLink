# LiveMall 全链路压测方案 — 单机 16GB 最优性能

## 一、系统架构

| 服务 | 端口 | 特征 | 瓶颈类型 |
|---|---|---|---|
| Gateway | 8080 | WebFlux/Netty, JWT 解析, 路由转发 | CPU + 连接数 |
| User | 8081 | bcrypt (CPU 密集), JWT 签发 | CPU |
| Seckill | 8082 | Redis Lua 扣库存 + Caffeine L1 + DB | Redis + 网络 |
| Leaderboard | 8084 | Redis ZSet 操作 | Redis |
| WebSocket | 8083 | DB 查询 + WS 连接管理 | 连接数 + DB |

**公共依赖**：MySQL + Redis (192.168.147.132) + Nacos (192.168.147.132:8848)

## 二、流量模型（模拟真实线上场景）

### 场景说明

模拟一个直播间秒杀活动：
- **开抢前**：用户进入直播间，发弹幕、送礼物（低频）
- **开抢瞬间**：大量用户同时抢秒杀商品
- **开抢后**：部分用户继续互动，部分用户查看排行榜

### 流量比例

| 场景 | 占比 | 接口 | 说明 |
|---|---|---|---|
| **秒杀抢购** | **45%** | `POST /seckill/order` | 核心压测目标，Redis Lua + Caffeine |
| **排行榜查询** | **20%** | `GET /leaderboard/top?activityId={id}` | Redis ZREVRANGE，用户查看排名 |
| **直播间列表** | **15%** | `GET /live/rooms` | DB 查询，轻量读 |
| **登录** | **10%** | `POST /auth/login` | bcrypt，CPU 重 |
| **注册** | **5%** | `POST /auth/register` | bcrypt，最重 |
| **排行榜加分** | **3%** | `POST /leaderboard/score` | 模拟礼物/点赞/观看，Redis ZSet |
| **弹幕** | **2%** | WebSocket `BARRAGE` | 需要 JMeter WebSocket 插件 |

### 为什么调整比例

- **秒杀是核心**：真实场景中秒杀瞬间流量占比最大
- **礼物/弹幕降权**：避免 WebSocket 广播风暴（N 用户送礼 → N² 条广播）
- **排行榜查询提升**：用户抢完后会看排行榜

│   ├── DURATION = 120

│   ├── Uniform Random Timer: 500-2000ms (用户浏览榜单)
│   └── Response Assertion: code=200
│
├── Thread Group: 直播间列表 (15% 线程)
│   ├── HTTP Request: GET /live/rooms
│   ├── Uniform Random Timer: 1000-3000ms (用户浏览)
│   └── Response Assertion: code=200

├── Thread Group: 登录 (10% 线程)

│   ├── HTTP Request: POST /auth/login
│   │   └── Header: X-Device-Id: ${deviceId}
│   ├── JSON Extractor: 提取 token
│   ├── Uniform Random Timer: 2000-5000ms (登录频率低)
│   └── Response Assertion: code=200
│
├── Thread Group: 注册 (5% 线程)
│   ├── CSV Data Set Config: new-users.csv (username, password)
│   ├── HTTP Request: POST /auth/register
│   │   └── Body: {"username":"${username}","password":"${password}"}

│   └── Response Assertion: code=200 或 400(已存在)
│
├── Thread Group: 排行榜加分 (3% 线程，模拟礼物/点赞)

│   ├── WebSocket Single Write Sampler: {"type":"BARRAGE","data":{"content":"${content}"}}
│   ├── Uniform Random Timer: 500-2000ms (弹幕频率)
│   └── WebSocket Close Connection
│
└── Aggregate Report

## 四、setUp 线程组详细配置

### 步骤 1：登录获取 token

```
HTTP Request:
├── Method: POST
├── URL: http://localhost:8080/auth/login
├── Header: Content-Type: application/json
├── Header: X-Device-Id: admin-device
├── Body: {"username":"${username}","password":"${password}"}
└── JSON Extractor:
    ├── Variable: accessToken
    ├── JSON Path: $.data.accessToken
    └── Default: FAILED
```

### 步骤 2：创建秒杀活动

```
HTTP Request:
├── Method: POST
├── URL: http://localhost:8080/seckill/activity
├── Header: Authorization: Bearer ${accessToken}
├── Header: Content-Type: application/json
├── Body:
{
  "name": "压测秒杀商品-${__time(yyyyMMdd-HHmmss)}",
  "price": 9.9,
  "origPrice": 99.9,
   "stockTotal": 50,
  "startAt": ${__time(,startTime)},
  "endAt": ${__longSum(${startTime},3600000)},
  "productId": 1,
  "roomId": 1
}
└── JSON Extractor:
    ├── Variable: activityId
    ├── JSON Path: $.data.id
    └── Default: FAILED
```

### 步骤 3：上架活动（status=1）

```
HTTP Request:
├── Method: PUT
├── URL: http://localhost:8080/seckill/activity/${activityId}/status
├── Header: Authorization: Bearer ${accessToken}
├── Header: Content-Type: application/json
├── Body: {"status":1}
└── Response Assertion: code=200
```

### 步骤 4：存储 activityId 为全局变量

```
JSR223 Sampler (Groovy):
├── Language: groovy
└── Script:
props.put("ACTIVITY_ID", vars.get("activityId"));
log.info("活动 ID: " + vars.get("activityId"));
```

### 步骤 5：等待 5 秒

```
Constant Timer: 5000
```

### 步骤 6：验证配置

```
Debug Sampler:
├── Show JMeter Properties: True
└── Show JMeter Variables: True
```

## 七、JVM 参数调优

### 7.1 内存分配（16GB 总量）

| 服务 | G1 推荐堆 | ZGC 推荐堆 | 理由 |
|---|---|---|---|
| Gateway | `-Xms1g -Xmx1g` | `-Xms1g -Xmx1g` | 无状态转发 |
| User | `-Xms2g -Xmx2g` | `-Xms2g -Xmx2g` | bcrypt 对象分配大 |
| Seckill | `-Xms2g -Xmx2g` | `-Xms2g -Xmx2g` | Caffeine 缓存 + Redis |
| Leaderboard | `-Xms1g -Xmx1g` | `-Xms1g -Xmx1g` | 纯 Redis 操作 |
| WebSocket | `-Xms2g -Xmx2g` | `-Xms2g -Xmx2g` | WS 连接 + DB |
| **合计** | **8GB** | **8GB** | 留 8GB 给 OS + MySQL + Redis + JMeter |

### 7.2 G1 调参

```bash
-Xms{size} -Xmx{size}
-XX:+UseG1GC
-XX:MaxGCPauseMillis=200
-XX:G1HeapRegionSize=4m
-XX:InitiatingHeapOccupancyPercent=45
-XX:ConcGCThreads=2
-XX:ParallelGCThreads=4
-XX:+ParallelRefProcEnabled
-XX:MetaspaceSize=256m
-XX:+UseStringDeduplication
```

**调参思路**：
1. 先跑默认 G1，记录基线
2. YGC 频繁 → `-XX:G1NewSizePercent=30`
3. Mixed GC 不够快 → `-XX:G1MixedGCCountTarget=16`
4. FGC 出现 → 加堆或排查内存泄漏

### 7.3 ZGC（分代）调参

```bash
-Xms{size} -Xmx{size}
-XX:+UseZGC
-XX:+ZGenerational
-XX:SoftMaxHeapSize={size}
-XX:ConcGCThreads=2
-XX:ParallelGCThreads=4
-XX:MetaspaceSize=256m
```

**ZGC vs G1**：
- ZGC 暂停 <1ms，G1 目标 200ms
- ZGC 吞吐量略低（~5-10%）
- 重点对比 **p99 延迟** 和 **GC 暂停时间**

## 十一、注意事项

1. **setUp 线程组必须先成功**：否则所有业务线程组无法获取 activityId
2. **WebSocket 插件**：弹幕测试需要安装 `jmeter-websocket-samplers`
3. **礼物/弹幕降权**：避免 WebSocket 广播风暴（N 用户送礼 → N² 条广播）
4. **端口耗尽**：已配置 `netsh dynamicport start=10000 num=55535`
5. **连接复用**：`user.properties` 已配置 `httpclient.reset_state_on_thread_group_iteration=true`
6. **Gateway Netty**：已配置 `max-connections: 16384`
7. **Redis/MySQL 远程**：网络延迟 ~1-2ms，是天然瓶颈，本地调参无法消除
8. **压测时关闭非必要程序**：浏览器、其他 IDE 项目，释放 CPU 和内存

## 十三、故障排查

### 问题 1：setUp 线程组失败

**现象**：活动创建失败，activityId 为 FAILED

**排查**：
- 检查 admin 账号是否存在
- 检查 `/seckill/activity` 接口是否需要特殊权限
- 查看 Seckill 服务日志

### 问题 2：秒杀接口大量 1009 错误

**现象**：错误率 >50%

**原因**：库存已抢完

**解决**：
- 增加 `stockTotal`（如 50000）
- 或减少秒杀线程数

### 问题 3：Connection refused

**现象**：Gateway 拒绝连接

**排查**：
- 检查 Gateway `max-connections` 配置
- 检查 Windows 端口范围
- 检查 JMeter `user.properties`

### 问题 4：排行榜加分失败

**现象**：`POST /leaderboard/score` 返回 401

**原因**：需要 JWT 认证

**解决**：在请求头加 `Authorization: Bearer ${token}`
