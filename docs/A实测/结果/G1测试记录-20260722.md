# G1 GC 测试记录 - 2026-07-22

## 环境
- JDK 25.0.3
- User 服务 (PID 488)
- GC: G1 (`-XX:+UseG1GC`)
- 100用户/900用户登录压测

---

## 测试1：100用户注册 + 登录（轻量）

### 参数
- 线程数: 100
- Ramp-Up: 10s
- 循环: 1次

### jstat 关键数据
```
YGC: 268→271 (3次)
YGCT: 0.629→0.635 (单次 ~2ms)
FGC: 0
FGCT: 0
CGC: 234→236
CGCT: 0.812→0.820
Old: 83~86%
Metaspace: 99.32%
GCT: 1.441→1.455s
```

### 结论
压力太小，G1 没启动任何实际GC工作。

---

## 测试2：900用户注册 + 登录（中等压力）

### 参数
- 线程数: 900
- Ramp-Up: 先100s后改10s
- 循环: 1次 + 后续永远循环

### jstat 关键数据
```
YGC: 276→297 (21次)
YGCT: 0.644→0.693 (单次 ~2ms)
FGC: 0
FGCT: 0
CGC: 242→256
CGCT: 0.839→0.876
Old: 79~89%
Metaspace: 99.25~99.29%
GCT: 1.483→1.569s
```

### 结论
- ✅ Full GC = 0 次
- ✅ Young GC 单次仅 ~2ms
- ✅ 老年代稳定在 89%，G1 混合回收正常
- ⚠️ 注册操作因 bcrypt 哈希过重导致 CPU 瓶颈（非GC原因）
- ⚠️ 元空间 99.3% 接近上限需关注

## 测试4：1000用户瞬间压入（Ramp-Up 1s）

### 参数
- 线程数: 1000
- Ramp-Up: **1s**（瞬间全部启动）
- 循环: 无限 + 调度器

### jstat 关键数据
```
YGC: 309→318 (9次)
YGCT: 0.719→0.775 (单次 ~6ms，因瞬间峰值变大)
FGC: 0
FGCT: 0
CGC: 264→270
CGCT: 0.895→0.918
Old: 71~87%（从88%降至71%，G1做了混合回收）
Metaspace: 99.27~99.29%
GCT: 1.614→1.693s
```

### 与测试3对比（1000用户，10s vs 1s）

| 指标 | 10s Ramp-Up | 1s Ramp-Up |
|---|---|---|
| YGC次数 | 5 | 9 |
| 单次YGCT | ~2ms | ~6ms |
| 老年代 | 87~88% 平稳 | 88%→71% 下降 |
| CGC | 2次 | 6次 |

1s 瞬间峰值迫使 G1 做了更多混合回收，老年代明显下降。

## 全部测试汇总

| 测试 | 场景 | 线程 | Ramp-Up | YGC | YGCT/次 | FGC | 老年代 |
|---|---|---|---|---|---|---|---|
| 1 | 注册+登录 | 100 | 10s | 3 | ~2ms | 0 | 83~86% |
| 2 | 注册+登录 | 900 | 10s | 21 | ~2ms | 0 | 79~89% |
| 3 | 纯登录 | 1000 | 10s | 5~6 | ~2ms | 0 | 87~88% |
| 4 | 纯登录 | 1000 | **1s** | 9 | **~6ms** | 0 | **71~87%** |

### 结论
- ✅ G1 在所有测试中 Full GC = 0
- ⚠️ 瞬间并发（1s ramp-up）导致单次 YGCT 从 2ms 升到 6ms
- ⚠️ 元空间 99.3% 持续高位，建议加 `-XX:MetaspaceSize=256M`
- 下一步：切 ZGC 重复测试4（最有对比价值的场景）
