# LiveMall 前端设计文档

> 基于后端接口模块重新规划前端页面，分 C 端（观众/买家）和 B 端（主播/卖家）两套界面。

---

## 一、风格定位：沉浸式极夜黑

**设计核心词**: 专注 · 竞技感 · 数据可视化

### 色彩体系

| 角色 | 色值 | 用途 |
|------|------|------|
| **主背景** | `#0F0F14` | 沉浸黑，全屏直播画面，OLED 省电 |
| **功能背景** | `#1A1A24` | 极夜灰，聊天室/排行榜卡片层 |
| **秒杀红** | `#FF2C55` | 立即抢购/倒计时/价格 |
| **富豪金** | `#FFD666` | 排行榜/礼物特效/充值 |
| **状态绿** | `#34C759` | 在线 |
| **失效灰** | `#8E8E93` | 售罄/已结束 |

### 交互风格

- 数据驱动动画: BARRAGE/GIFT 走 `transition-group`，滑入/弹跳/全屏撒花
- 微交互: 秒杀按钮 Loading → 震动/粒子爆炸
- 字体: 价格/倒计时用 DIN 等宽，常规信息用 PingFang SC

## 三、C 端页面（观众/买家端）

### 1. 登录/注册页 — `/login` / `/register`

| 接口 | 用途 |
|------|------|
| `POST /auth/login` | 账号密码登录 |

**页面内容**: 简洁卡片表单 + 动态直播画面虚化背景。支持登录/切换注册。JWT 存 LocalStorage，自动刷新。

### 2. 直播大厅页 — `/`

| 接口 | 用途 |
|------|------|
| `GET /live/rooms` | 直播列表 |

**卡片元素**:

### 4. 秒杀下单抽屉 — `SeckillDrawer`

**形态**: 直播间内 Modal/Drawer（不跳转不脱离直播氛围）。

| 接口 | 用途 |
|------|------|
| `GET /seckill/activity/{id}` | 活动详情 |
| `POST /seckill/order` | 抢购 |

**组件**:
- 商品大图 + 标题 + 原价划线 + 秒杀价(红)
- 毫秒级倒计时 + 库存进度条(已抢 XX%)
- CTA 按钮三态:

| 状态 | 条件 | 按钮 |
|------|------|------|
| `PENDING` | `now < startTime` | 灰色"即将开始" |
| `PROCESSING` | 活动时间内有库存 | 红色"立即抢购" + 呼吸动画 |
| `FAILED` | 售罄/已结束 | 灰色"已抢光" |

**防抖**: 点击后按钮 loading，防止重复下单（后端也有 Redis Lua 防重）。

## 五、特殊场景

### 设备互踢提示

收到 WS `KICK` 消息时:
1. 断开 WebSocket
2. 全屏遮罩 + 提示 "您的账号在另一台设备登录，您已被迫下线"
3. "重新登录" 按钮 → 跳转 `/login`

### 秒杀有限状态机

```
PENDING      →  now < startTime          → 倒计时
READY        →  now 接近 startTime       → 排队中
PROCESSING   →  活动时间内 + stock > 0   → 按钮可点
SUCCESS      →  下单成功                 → 结果弹窗
FAILED       →  库存为0/报错            → 售罄
```

### WebSocket 心跳保活

```javascript
// 30s interval PING，收到 KICK 断开跳转登录
onMounted(() => {
  pingTimer = setInterval(() => ws.send('{"type":"PING"}'), 30000)
})
onUnmounted(() => clearInterval(pingTimer))
```

```typescript

const orderResult = ref<SecKillResultData | null>(null)
```

**逻辑闭环**:

```
watch(activityData.status) → 动态启动/停止倒计时定时器
     │

     │

     │       └─→ seckillStore.registerOrderCallback(orderNo)
     │
     └─→ WS SEC_KILL_RESULT 到达 → match orderNo
             ├─ ok=true  → buttonState = 'success' → 3s 关抽屉
             └─ ok=false → buttonState = 'sold_out' → Toast 原因
```

## 七、Mock / 开发环境方案

> 后端接口不全时，前端通过 MSW (Mock Service Worker) 在网络层拦截请求，独立开发。

### 7.1 技术选型：MSW

| 方案 | 选型理由 |
|------|---------|
| **MSW** ✅ | Service Worker 层拦截，不污染 Axios/Fetch，与真实请求逻辑一致 |
| Mock.js ❌ | 侵入式，运行时与实际 Axios 混合，切换成本高 |

### 7.2 安装与初始化

```bash
npm install msw --save-dev
npx msw init public/ --save
```

### 8.2 权限守卫

```typescript
// src/router/guard.ts
import { useAuthStore } from '@/stores/authStore'

router.beforeEach(async (to, from, next) => {
  const auth = useAuthStore()

  // A. 登录校验
  if (to.meta.requiresAuth && !auth.isLoggedIn) {
    return next({ path: '/login', query: { redirect: to.fullPath } })
  }

  // B. 角色权限
  if (to.meta.roles) {
    const roleMap: Record<number, string> = { 1: 'AUDIENCE', 2: 'ANCHOR', 3: 'ADMIN' }
    const userRole = roleMap[auth.role] || 'AUDIENCE'
    if (!to.meta.roles.includes(userRole)) {
      return next('/403')
    }
  }

  // C. 已登录用户禁止访问登录页
  if (to.meta.guestOnly && auth.isLoggedIn) {
    return next('/')
  }

  next()
})
```
