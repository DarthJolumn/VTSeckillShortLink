## 1. 认证接口 — `AuthController` (`/auth`)

### 1.1 注册 `POST /auth/register`

| 请求头 | 说明 |
|--------|------|
| `X-Idempotency-Key` | 可选，幂等 Key |

**请求体**:
```json
{
  "username": "string (4~50)",
  "password": "string (≥8)",
  "phone": "string (手机号正则)"
}
```

**逻辑**:
1. 幂等检查（`IdempotencyService.tryAcquire`）
2. BCrypt 哈希密码（cost=10）
3. MyBatis Plus INSERT → `DuplicateKeyException` 兜底并发冲突
4. 用户名唯一性通过 `SELECT COUNT` + 唯一索引双重保障

### 1.2 登录 `POST /auth/login`

| 请求头 | 必填 | 说明 |
|--------|------|------|
| `X-Device-Id` | 是 | 客户端设备唯一标识 |
| `X-Idempotency-Key` | 否 | 5min 幂等缓存 |

**请求体**:
```json
{
  "username": "string",
  "password": "string"
}
```

**响应**:
```json
{
  "accessToken": "JWT (15min)",
  "refreshToken": "rft_xxx (7天)",
  "expiresIn": 900,
  "tokenType": "Bearer"
}
```

**逻辑**:
1. 幂等缓存查询 → 已存在直接返回
2. 用户名查库 → 不存在 / 已封禁 / 密码不匹配 → 报错
3. 生成 Access Token（JWT, 15min）和 Refresh Token（Redis, 7天）
4. Redis 写入：
   - `refresh:<token>` → `userId:role:deviceId`
   - `device_sessions:<userId>` → Set 存 `deviceId`
   - `user_tokens:<userId>` → Set 存所有 `refresh:<token>` key（踢设备用）

### 1.3 Token 刷新 `POST /auth/refresh`

**请求体**:
```json
{
  "refreshToken": "rft_xxx"
}
```

**逻辑 — Rotation 模式**:
1. 请求合并：`pendingRefreshes`（ConcurrentHashMap）合并同一 token 的并发请求
2. 分布式锁：`SETNX refresh:lock:<token>`（3s 过期）防止跨节点并发
3. Rotation：DELETE 旧 Refresh Token → 签发新 Access + Refresh Token
4. 新 Token 写入 Redis，设备 ID 不变

### 1.4 退出登录 `POST /auth/logout`

**请求体**:
```json
{
  "refreshToken": "rft_xxx"
}
```

**逻辑**: 删除 `refresh:<token>` 并从 `device_sessions:<userId>` Set 中移除对应设备。

## 2. 用户管理接口 — `UserController` (`/user`)

所有接口需 JWT 鉴权（Gateway 注入 `X-User-Id` Header），部分标注 `@RequireAuth`。

### 2.1 个人资料查询 `GET /user/profile`

| Header | 来源 | 说明 |
|--------|------|------|
| `X-User-Id` | Gateway 注入 | 当前用户 ID |

**响应**: `UserProfileVO`（id / username / nickname / avatar / phone / role / status）

### 2.2 余额查询 `GET /user/balance`

返回用户余额 `BigDecimal`。

### 2.3 设备列表 `GET /user/devices`

| Header | 说明 |
|--------|------|
| `X-Device-Id` | 可选，标记当前设备 |

返回 `List<DeviceInfo>`（deviceId + isCurrent）。

### 2.4 踢设备下线 `DELETE /user/devices/{deviceId}`

**逻辑**:
1. Redis 移除 `device_sessions:<userId>` 中的设备
2. 遍历 `user_tokens:<userId>`，删除匹配该设备的所有 Refresh Token
3. **跨服务调用** → `WsPushService.kickDevice()` (Dubbo) 推送踢下线通知

### 2.5 修改个人资料 `PUT /user/profile`

| 字段 | 说明 |
|------|------|
| `nickname` | 可选 |
| `avatar` | 可选 |
| `phone` | 可选，校验唯一性 |

### 2.6 修改密码 `PUT /user/password`

校验旧密码 BCrypt → 新密码 BCrypt 重哈希。

### 2.7 封禁/解禁 `PUT /user/ban/{userId}`

```json
{"status": 0}  // 封禁
{"status": 1}  // 解禁
```

## 5. Redis Key 设计

| Key | 类型 | TTL | 说明 |
|-----|------|-----|------|
| `refresh:<token>` | String | 7天 | `userId:role:deviceId` |
| `device_sessions:<userId>` | Set | 7天 | 该用户所有设备 ID |
| `user_tokens:<userId>` | Set | 7天 | 该用户所有 Refresh Token key |
| `refresh:lock:<token>` | String | 3s | 刷新分布式锁 |
| `idempotency:<key>` | String | 5min | 登录幂等 |

---

## 6. 安全设计

- 密码 BCrypt 哈希（cost=10），永不存储明文
- JWT 双 Token 模式，Access Token 15min 短时效
- Refresh Token Rotation：每次刷新旧 token 立即作废
- 登录幂等（5min 缓存），注册幂等（`IdempotencyService`）
- 并发注册 `DuplicateKeyException` 兜底
- Token 刷新分布式锁 + 请求合并防并发
