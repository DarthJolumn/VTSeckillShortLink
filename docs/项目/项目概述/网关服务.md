# 网关服务 — livemall-gateway

**端口**: 8080 | **技术栈**: Spring Cloud Gateway 5.x (WebFlux) | **框架**: Spring Boot 4.1 + JDK 25

---

## 1. 路由转发

配置在 `application.yml`，通过 Nacos 服务发现 + Spring Cloud LoadBalancer (`lb://` / `lb:ws://`) 转发。

| 路由 ID | 目标服务 | 路径前缀 | 协议 |
|---------|---------|---------|------|
| `user-service` | livemall-user | `/auth/**`, `/user/**` | HTTP |
| `seckill-service` | livemall-seckill | `/seckill/**` | HTTP |
| `leaderboard-service` | livemall-leaderboard | `/leaderboard/**` | HTTP |
| `live-service` | livemall-websocket | `/live/**` | HTTP (直播间 REST) |
| `websocket-service` | livemall-websocket | `/ws/**` | WebSocket |

> **说明**: Gateway 5.0+ 路由配置路径为 `spring.cloud.gateway.server.webflux.routes`，非旧版 `spring.cloud.gateway.routes`。

## 2. JWT 鉴权 — `JwtAuthGlobalFilter`

**优先级**: `Ordered = -5`（在签名验签之后执行）

### 鉴权白名单

| 白名单 | 匹配行为 | 配置项 | 默认值 |
|--------|---------|--------|--------|
| `public-paths` | 完全放行，不验 JWT | `gateway.auth.public-paths` | `/auth/login,/auth/register,/auth/refresh,/ws/**,/actuator/health` |
| `public-get-paths` | 仅 GET 请求放行 | `gateway.auth.public-get-paths` | `/live/room/*,/leaderboard/**` |

### 鉴权流程

1. 完全公开路径 → 直接放行
2. GET 公开路径 → 直接放行
3. 签名验签已通过（`signPassed` attribute） → 跳过 JWT
4. 其余路径从 `Authorization: Bearer <token>` 提取 JWT
5. 解析成功 → 向下游注入请求头 `X-User-Id`、`X-User-Role`
6. 解析失败 → 返回 401

### 请求头注入

当 JWT 验证通过后，向转发请求注入：

| Header | 来源 | 示例值 |
|--------|------|--------|
| `X-User-Id` | JWT subject | `12345` |
| `X-User-Role` | JWT claim `role` | `1` |

### 已知问题

- **JJWT + Gson 类型转换**: Gson 将 JWT payload 中数字解析为 `Double`，需通过 `((Number) claims.get("role")).intValue()` 转换。

## 3. 接口签名验签 — `SignVerifyGlobalFilter`

**优先级**: `Ordered = -10`（最先执行）

### 支持的请求头

| Header | 必填 | 说明 |
|--------|------|------|
| `X-Timestamp` | 是 | 请求时间戳（ms），与服务器时间差 ≤ ±5min |
| `X-Nonce` | 是 | 随机字符串，60s 内不可重复（Redis SETNX） |
| `X-AppKey` | 是 | 应用标识，用于查找对应的 Secret |
| `X-Sign` | 是 | HMAC-SHA256 签名值 |

### 签名算法

```
sign = HMAC-SHA256(timestamp + nonce, secret)
```

- `timestamp` + `nonce` 字符串拼接后作为签名数据
- `secret` 通过 `X-AppKey` 从本地 `ConcurrentHashMap` 获取
- 默认配置: `gateway.sign.app-secrets=livemall:livemall2026`

### 验签流程

1. 缺少任意签名 header → 跳过，交由 JWT 鉴权
2. 时间窗口校验（`Math.abs(now - timestamp) > 5min`） → 401
3. Redis SETNX `nonce:<nonce>`（TTL=60s）→ 重复返回 401
4. 查找 AppKey → 不存在返回 401
5. HMAC 校验 → 不匹配返回 401
6. 通过 → attribute `signPassed=true`，跳过 JWT

## 5. 全局异常处理 — `GlobalErrorWebExceptionHandler`

- 实现 `ErrorWebExceptionHandler`（`@Order(-1)`）
- 统一返回 JSON 格式 `Result`
- 对 `ResponseStatusException` 提取 HTTP 状态码和原因
- 未知异常返回 500 + "系统繁忙，请稍后重试"

### 返回格式

```json
{
  "code": 401,
  "message": "请先登录",
  "data": null,
  "timestamp": 1712345678000
}
```

## 8. 全局过滤链执行顺序

1. `SignVerifyGlobalFilter`（order = -10）— 签名验签
2. `JwtAuthGlobalFilter`（order = -5）— JWT 鉴权
3. Gateway 内置路由过滤器 — 请求转发到下游服务
4. `GlobalErrorWebExceptionHandler`（order = -1）— 异常兜底
