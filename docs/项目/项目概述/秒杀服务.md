# 秒杀服务 — livemall-seckill

**端口**: 8082 | **Dubbo**: 20882 | **技术栈**: Spring MVC + VT + Redis Lua + Kafka + Caffeine

---

## 1. 秒杀活动管理

### 1.1 创建活动 `POST /seckill/activity`

```json
{"name":"双11秒杀","price":0.01,"origPrice":99,"stockTotal":100,"startAt":1712345678000,"endAt":1712355678000}
```

- 参数校验后 INSERT `t_seckill_activity`
- 状态初始值 `0`（待开始）

### 1.2 更新活动状态 `PUT /seckill/activity/{id}/status`

```json
{"status": 1}
```

| status | 含义 |
|--------|------|
| 0 | 待开始 |
| 1 | 进行中（上架） |
| 2 | 已结束 |
| 3 | 已取消 |

上架（→1）时初始化库存：
1. `StockService.initStock()` → Redis 分片 key `stock:shard:{activityId}:{0..N}`
2. `ActivityCacheService.markInStock()` 清除本地售罄标记
3. `ActivityCacheService.refresh()` 刷新 Caffeine 缓存

### 1.3 活动详情 `GET /seckill/activity/{id}`

### 1.4 活动列表 `GET /seckill/activity/list?roomId=`

可选 `roomId` 过滤，默认返回所有进行中活动。

## 2. 抢购核心链路 — `POST /seckill/order`

**核心路径**: Caffeine L1 → Redis Lua → Kafka → gRPC 推送

请求体: `{"activityId": 1}`

### 2.1 L1 Caffeine 快速售罄检查

`ActivityCacheService.isSoldOut()` — 本地 `ConcurrentHashMap` 标记，已售罄直接拒绝，减少 90% Redis 查询。

### 2.2 活动校验（Caffeine L2）

- `ActivityCacheService.getActivity()` — Caffeine 5s 缓存活动信息
- 校验 status=1、时间范围

### 2.3 Redis Lua 原子扣库存 — `StockService.deduct()`

**返回值**:

| 值 | 含义 |
|----|------|
| 200 | 扣减成功 |
| -1 | 重复下单（`ordered:{activityId}:{userId}` 已存在） |
| -2 | 库存不足（Lua DECR 返回负数） |

**Lua 脚本 (`deduct_stock.lua`)**:

1. `GET ordered:{activityId}:{userId}` → 已存在返回 -1
2. `userId % shardCount` 计算分片
3. `DECR stock:shard:{activityId}:{shard}` → 结果 ≥ 0 表示成功
4. 成功则 `SETEX ordered:{activityId}:{userId} 86400 "1"`
5. Lua 原子性保证不超卖

**库存分片配置**: `seckill.shard-count=4`，用以支撑 10w+ QPS。

### 2.4 Kafka 异步下单

扣减成功 → 发 Kafka topic `seckill-order`（消息格式: `userId:activityId:orderNo`）

Kafka 不可用时的降级策略：
```java
kafkaTemplate.send("seckill-order", msg).get(3, TimeUnit.SECONDS);
// 超时或异常 → 降级同步调用 createOrder()
```

### 2.5 Kafka 消费者 — `SeckillOrderConsumer`

- 消费 group: `livemall-seckill`，4 个并发线程，MANUAL ACK
- 消息处理（VT 异步）：
  1. 解析消息 → 查 `SeckillActivity`
  2. `createOrder()` → INSERT `t_seckill_order`（`@Transactional`）
  3. **gRPC 调用** `SeckillPushGrpc` 推送秒杀结果到 WebSocket 节点
  4. 手动 ACK

`DuplicateKeyException` → 幂等兜底，直接 ACK 跳过。

### 2.6 全链路

```
HTTP POST /seckill/order
  → Caffeine(isSoldOut?) → Caffeine(getActivity?) → Redis Lua(deduct)
  → Kafka send("seckill-order")
  → KafkaConsumer(parse → INSERT order → gRPC push to WS)
  → WebSocket 推送 SEC_KILL_RESULT 到用户
```

## 3. 订单管理

### 3.1 用户订单列表 `GET /seckill/order/list`

### 3.2 订单详情 `GET /seckill/order/{orderNo}`

### 3.3 取消订单 `PUT /seckill/order/{orderNo}/cancel`

1. 校验订单归属 + 状态可取消
2. `StockService.refund()` — Redis Lua 回补库存（`INCR stock:shard` + `DEL ordered`）
3. DB 更新 status=2 （`@Transactional`）

### 3.4 退款 `PUT /seckill/order/{orderNo}/refund`

设置 status=3（已退款）。

### 3.5 超时自动取消 — `TimeoutCancelScheduler`

- 每 15s 扫描超时（15min）未支付订单
- 乐观锁 CAS（`@Version`）防并发
- 成功取消后回补 Redis 库存

## 4. 库存分片架构

```
┌─────────────────────────────────┐
│          Redis Lua               │
│  deduct_stock.lua                │
│  ┌─────────────────────────┐     │
│  │ ordered:actId:userId     │     │
│  │ → 已存在? -1             │     │
│  │                          │     │
│  │ shard = userId % 4       │     │
│  │ DECR stock:shard:actId:0 │     │
│  │ DECR stock:shard:actId:1 │     │
│  │ DECR stock:shard:actId:2 │     │
│  │ DECR stock:shard:actId:3 │     │
│  │                          │     │
│  │ stock >= 0? → OK + SETEX │     │
│  │ stock < 0? → -2          │     │
│  └─────────────────────────┘     │
└─────────────────────────────────┘
```

**参数**: `seckill.shard-count=4`
**效果**: 4 个 Redis key 分摊热点，Lua 原子性保证不超卖。

## 5. 数据模型

### t_seckill_activity

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | BIGINT (Auto) | 主键 |
| `title` | VARCHAR(200) | 活动名称 |

### t_seckill_order

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | BIGINT (Auto) | 主键 |
| `order_no` | VARCHAR(50) | 订单号（Snowflake） |

| `user_id` | BIGINT | 用户 ID |

**唯一约束**: `(activity_id, user_id)` — 一人一单。

## 6. Redis Key 设计

| Key | 说明 | TTL |
|-----|------|-----|
| `stock:shard:{actId}:{i}` | 分片库存 | 持久 |
| `stock:total:{actId}` | 总库存标记（仅 Lua 参数） | — |
| `ordered:{actId}:{userId}` | 防重下单标记 | 24h |
| `soldOut:{actId}` | （预留）Redis 售罄标记 | — |

## 7. 降级与容错

| 场景 | 降级策略 |
|------|---------|
| Kafka 不可用 | 同步调用 `createOrder()` + 跳过 gRPC 推送 |
| gRPC 不可用 | 日志警告，订单正常创建 |
| DB 不可用 | Kafka 不 ACK，重试消费 |
| Redis 异常 | Lua 执行失败 → 抛异常回滚 |
| 重复订单 | `DuplicateKeyException` + `@Version` 乐观锁 |
